## Two rendering bugs found while editing (nobody flagged these)

`/context`'s glossary rows are JS array strings rendered as `{def}`, so HTML in them renders
**literally**. `ProjectCard`'s `description` is the same. JSX *attribute* strings get their
entities decoded; array strings do not. Consequences:

- A pre-existing `&amp;` in the `identity-continuity` row was rendering as the literal text
  `&amp;` on the live site. Fixed.
- My own first draft of the new rows used `<strong>`/`<em>` and would have shipped literal
  tags. Caught by grepping the **built HTML** (`.next/server/app/*.html`), not the source.
  Both classes now verified absent from the build output.

Verifying against built output rather than source is worth keeping as a habit here — the
source looked correct in both cases.
