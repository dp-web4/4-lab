## Tooling Defect Found and Fixed
`check-caveats.sh` reported `fleet-count-as-of-date` as a MISSING protected caveat after a legitimate
recount. Two bugs, both in the check rather than the page:
1. The pattern was pinned to the literal string `counted 2026-09-12`. The caveat protects *that a count
   carries an as-of date*, not that it carries one particular date — so refreshing the count correctly
   tripped it as a removed caveat. Generalised to match any date.
2. The generalised pattern I first wrote used `\d`, which `grep -E` does not support (that is PCRE).
   It silently matched nothing and looked like the same failure. Now `[0-9]`.

This is the second session in three where the enforcement tooling, not the content, produced the
finding. A check pinned to today's literal text will fire on tomorrow's correct edit, and a maintainer
in a hurry resolves that by restoring stale text. Worth a sweep of the other patterns for the same
shape — logged below.

## So What?
Two things this session establishes beyond the individual fixes.

**First: the site's verification method is sound and its refresh discipline is not.** Pass 3 re-ran the
counting basis from a clone and it reproduced to the digit — that is a rare property for a research
site and it survived audit. The same basis then produced two wrong cards, because a re-runnable rule
that nobody re-runs against the *current* instance list is just last week's answer with a citation. The
migration clause is the fix that matters; the card edits would otherwise recur at the next swap.

**Second: the page's own best idea did not bind its own claims.** /fleet argues at length that keying a
health test on commit subjects is unsound, then rested the Sprout conclusion on the absence of one
subject prefix, fifteen lines later. The methodology was right and local; the reasoning it should have
governed was upstream of it on the same page. That is the more general lesson than either card — a
stated standard that does not reach the claims beside it is a disclosure, not a control, which is the
same shape as the carry-forward rule's own known weakness.

Terminology enforcement, meanwhile, has now been clean for three sessions and ten visitor passes across
three independent methods. This track's stated highest priority is a solved problem, and its live
failure class is upstream freshness: descriptions of the fleet keeping up with the fleet. Worth raising
with the researcher whether the triage order in `maintainer/CLAUDE.md` should be rewritten to match —
it currently sends each session to look first at the thing that has not moved in ten passes.
