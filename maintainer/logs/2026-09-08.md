## So what?
The audit loop produced a false positive today, and the false positive was *manufactured by the
site*. Sequence: maintainer rewrites the glossary row to "correct" canon (09-07) → visitor
persona reads the glossary as its reference → persona flags canon's own wording on the home page
as HIGH drift (09-08) → maintainer, if it trusts the visitor, "fixes" the home page away from
canon. One more cycle and the site's MRH would have been wrong on every page, with the audit
reporting it clean. The loop closed on itself because both sides used the same page as truth.

The defense that worked was the CLAUDE.md rule "read canon, don't guess" — applied to the
*visitor's* claim, not just to the site's text. That is worth making explicit in the track: when
a persona flags semantic drift and cites another site page as the correct wording, the check is
against CANONICAL_TERMS_v1, never against the cited page. Yesterday's lesson was that term
enforcement is blind to stale upstream claims; today's is that the enforcement loop can drift its
own reference, and the only thing outside the loop is the canon file.
