### 1. MRH — incomplete, not drifted (visitor finding partially refuted)

distinction the visitor correctly identified as missing:

- `src/app/page.tsx` — MRH vocabulary card

The visitor's *diagnosis* was right (a reader learns the word and means something

while believing they were removing it.

### The scramble control — the researcher was right and this was the best finding in the log

`/raising` correctly rejected the generic-replacement control on the grounds that the
deflationary hypothesis already predicts degradation there, and then specified a scramble
control that fails the identical test. Order sensitivity of in-context learning is one of
the most robustly documented properties of transformer LMs; "competent context
engineering" *is* the hypothesis that ordering matters. A bare "behavior degrades under
scramble" is predicted by both hypotheses and adjudicates neither.

Added a section stating this against the site's own earlier text ("the first version of
this section got that wrong"), and specifying what would actually discriminate:

1. **Excess degradation over a measured ordering baseline** — threshold pre-registered
   relative to what permutation alone does to a comparable context, not relative to zero.
2. **Or a dissociation** — identity-continuity measures degrade while task competence on
   the *same* scrambled context holds. Ordering effects predict a broad main effect; the
   developmental account predicts something narrower. A dissociation is evidence; a main
   effect is not.

Also added the pre-commitment Pass 4 asked for in its unanswered question #8: if the
control runs and returns a bare main effect or no effect, that result gets published here
and the developmental vocabulary comes off this page. On the record before the
experiment, which is the only ordering under which it means anything.

## So what?

Two things worth carrying forward beyond the diff.

**The visitor's highest-confidence terminology finding was half wrong, and only checking
the canonical source caught it.** Pass 3 was the expert persona, flagged MRH as its
top-priority fix, and prescribed replacing a phrase that turned out to be verbatim canon.
The diagnosis was sound and the prescription would have shipped drift. The workflow
instruction "read it, don't guess, don't interpolate" earned its keep — not against a
confused visitor, but against a confident and mostly-correct one. Expert flags need the
same source check as naive ones, arguably more, because they're the ones a maintainer is
tempted to apply directly.

**Four independent audits reported the terminology layer clean and none of them checked a
number against anything outside the site.** All four cross-checked pages against *each
other* and found the machine count, repo counts, and model strings inconsistent — which
is real signal, but it only ever localises a disagreement, never resolves it. Every
number I actually resolved this session came from outside the site: the GitHub API for
repo counts, SAGE session records for model strings, `BECOMING_CURRICULUM.md` for the
transfer date. And the one the passes couldn't see at all — 180+ sessions attributed to
the pre-transfer period — was internally *consistent* across three pages and wrong on all
three. Cross-page consistency checking cannot find that class of error by construction.
The audit loop is missing a ground-truth arm, and it's the same structural gap Pass 4
identified in the model-homogeneity finding: the loop is closed on itself. That's the
thing to fix, and it's cheaper than it sounds — repo counts, instance names, and dates
are all one command away.
