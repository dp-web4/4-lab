## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (home + 8 nav pages)
- **Understanding achieved**: partial
- **Would return?**: maybe
- **Overall impression**: The benchmark result and the GitHub repos are a great hook, but the "start here" page buries a curious dev in 14 acronyms before they know why they should care.

### Journey
I landed on the home page from a repo README. The tagline — "Six machines. Fourteen repos. One recursive learning loop." — is genuinely good. It's concrete, it sounds ambitious, and it told me roughly what scale I'm dealing with. The hero line ("trust-native ontology, autonomous AI cognition...") lost me on "trust-native ontology," but two things pulled me back: the **96% ARC-AGI-3** claim (a benchmark I half-recognize) and a clear "New to this vocabulary? Start with /context" link. So I did what the site told me and went to /context.

That was a mistake for momentum. The /context page is framed as "start here," but it immediately throws ~14 acronyms (LCT, T3, V3, MRH, ATP, ADP, R6, SNARC, MCP, RDF...) plus "synthon," "coherence equations," and "Hill function kinetics" at me before I understand the *point* of any of it. There's an equation — `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP` — with operators redefined to mean "verified by / contextualized by / augmented with." As a dev I read it as code, realized it's *not* math, and had to context-switch. Intriguing, but it's a wall, not an on-ramp.

I bailed to /projects, which is where I should have been sent first. This page actually speaks my language: project cards with one-line descriptions and **links to real GitHub repos**. I could immediately sort them into "I could clone and run this" (ACT, Oversight Plugins, SNARC/engram, Membot, ARC-SAGE) vs. "this is theory" (Synchronism, AI DNA Discovery, 4-Life). That sorting is exactly what I want as a dev.

/fleet was fun — six named machines (Thor, Sprout, Legion, McNugget, Nomad, CBP) with real hardware specs and a model per box. The brain-region analogies (hippocampal, thalamic, cerebellum) are a bit much without a "these are functional analogies" disclaimer, but I got the gist: different sized models on different hardware, each with a role.

/autonomy claims "31+ autonomous tracks" but only names ~8. /raising and /principles are where the site gets philosophical — and to their credit, the consciousness-adjacent stuff is heavily hedged ("not claiming these entities are conscious"). /arc-agi-3 was the most credible page for me: real numbers (24/25 games, 94.85% action score), the model used (Claude Opus 4.6), an external scorecard link, a ~$250 cost, and honest caveats (network access used; competition requires offline + 32GB VRAM). /links gave me a clean exit: repos, an email, and a real contribution path ("open an issue," SAGE and Web4 as entry points).

2. Is "Web4" a spec I could implement against, or a research framing? The equation suggests something formal, but I can't tell if there's a reference implementation.

The terminology is correct and consistent (rare and good); the friction is that the on-ramp is theory-first when the audience arriving from a GitHub README is code-first.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 (home + all 8 nav pages)
- **Understanding achieved**: good (for a consistency audit; I read structure and terms, not deep theory)
- **Would return?**: yes
- **Overall impression**: Terminology fidelity is exceptional — zero contradictory acronym expansions across nine pages — so the remaining work is editorial discipline (define-on-first-use per page) and a few number/naming reconciliations, not term correction.

### Journey
I went page by page, in nav order, checking three things on each: (1) does every acronym get expanded on *this* page before it's used, (2) is each expansion identical to how the same acronym appears on every other page, and (3) does each expansion match the canonical table in CLAUDE.md.

The nav is clean and stable: **Projects · Context · ARC-AGI-3 · Fleet · Autonomy · Raising · Principles · Links** — eight items, all eight resolve. (Editorial note: ARC-AGI-3 sits third in the nav, ahead of Fleet/Autonomy — a result page promoted into primary nav. Defensible as the headline credential, but unusual IA.)

/context is the de-facto glossary and it is the strongest page for my purposes: LCT, T3, V3, MRH, ATP, ADP, R6, SNARC, MCP, RDF, Web4, Hardbound, SAGE, Synthon all defined in one place, all matching canon. The Web4 equation and its operator key (`/` = "verified by", `*` = "contextualized by", `+` = "augmented with") are stated once, cleanly.

Then I cross-checked every other page against that baseline. The headline finding: **the site is internally consistent to a degree I rarely see.** Every acronym that appears on multiple pages uses a byte-identical expansion. LCT is always "Linked Context Token," never "Lifelong." Hardbound is always "oversight," never "governance," in body prose. SAGE is "Situation-Aware Guidance Engine" on all six pages it appears on. There is not a single *contradictory* expansion in the corpus.

The real weakness is a different, classic-docs failure: **first-use-on-page discipline.** /context expands everything, so other pages lean on it as a global glossary and run bare. That breaks for any reader who lands deep — e.g., someone arriving on **/arc-agi-3 directly from the ARC Prize scorecard** hits ATP, ADP, and MRH with no expansion and no inline link to /context. Same on **/links** (LCT, MRH, MCP, RDF, ATP/ADP all bare). A multi-page site can't assume linear reading from the glossary outward.

I also re-examined Pass 1's one drift claim ("governance" on the Oversight Plugins card). **It does not hold against the current page.** The visible body reads: *"Web4 oversight model (audit trails, policy gating, trust tracking) implemented as plugins..."* — "oversight," correctly. The only surviving "governance" is in repo path slugs (`web4-governance`), and the card *explicitly discloses this*: the names "predate the terminology correction to 'oversight' and are load-bearing for existing forks." That's exemplary documentation hygiene — the canonical term in prose, with the legacy artifact honestly footnoted. Either the maintainer already fixed it, or Pass 1 read the slug rather than the prose.

## Pass 3: Web4 Contributor

### Summary
- **Pages visited**: 9 (home + all 8 nav pages; re-fetched /autonomy and /fleet for verbatim verification)

### Journey
I came in the way a contributor does: straight to /projects, /fleet, and /context to check whether the site misrepresents anything I work on, then swept the rest for canon. I know the terms by heart, so I was hunting subtle drift — "Lifelong" for "Linked," "governance" for "oversight," swapped equation operators, "unification" where "fractal leverage" belongs. I found none of those in prose.

**/context** is the canonical glossary and it holds up under expert scrutiny. LCT = "Linked Context Token" with the passport metaphor (accurate — it's an identity anchor, not a "capability" token; the most common drift, "Lifelong Capability Token," is absent). T3 = "Talent / Training / Temperament," correctly called a trust tensor. V3 = "Valuation / Veracity / Validity." MRH = "Markov Relevancy Horizon." ATP = "Allocation Transfer Packet" / "resource allocation for an intended action"; ADP = "Allocation Discharge Packet" / "record of the action's actual outcome" — that's exactly the charged-token→discharge-record relationship from the ATP/ADP cycle. R6 now carries the "Six-Element Action Framework" label *here* on the glossary (Pass 2's one canonical nit appears resolved). The equation operator key is correct and in the right order: `/` = "verified by", `*` = "contextualized by", `+` = "augmented with." That order is the single most common place I see drift, and it's right.

**/principles** is where the site earns the most credit from me: it doesn't just *use* the right terms, it *defends* them. "Web4 is an ontology (not architecture or infrastructure)" and "Cross-domain application is fractal leverage, not unification and not scope inflation" are stated as explicit negations of the exact wrong terms CLAUDE.md enforces against. Principle 10 is literally "Terminology matters." A site that names its own failure modes is one I trust to have avoided them.

**/projects** represents my work accurately. AI DNA Discovery's "fractal DNA blueprint — each entity instantiates the full Web4 stack at its own scale" is fractal leverage stated correctly. 4-Life is hedged as "operational recursion, not structural claims" — appropriate. The Oversight Plugins card uses "oversight" in prose and *discloses* that the linked `web4-governance` repo slugs predate the correction. As the authority on this: that disclosure is the right call — the slugs are load-bearing for existing forks, and renaming them would break clones; documenting the legacy is better than hiding or wrongly "fixing" it. Pass 1 flagged "governance" as drift; Pass 2 ruled it slug-only; **I confirm Pass 2 — there is no governance-for-oversight drift in any body prose on the site.**

**/fleet** is where my contributor knowledge caught the one real accuracy bug. Sprout's model is listed verbatim as **"Qwen 3.5 2B"** — there is no Qwen 3.5 release (the line runs Qwen2.5 → Qwen3), and it's internally inconsistent with Thor's "Qwen 2.5 14B." This is almost certainly a typo for "Qwen2.5 2B" or "Qwen3 2B." Everything else on /fleet is accurate and well-framed — the brain-region analogies, "the model is weather, the identity is organism," and "Gemma 3 4B outperforms Phi-4 14B for raising work" all match how we actually talk about the fleet.

### Journey
I came to this the way a trust/safety researcher does after a conference mention: not to learn Web4, but to decide whether the people behind it are being honest about what they don't know. So I went straight to /raising, /principles, and /autonomy, then used /arc-agi-3 and /fleet to stress-test the claims the philosophy pages lean on.

**/raising** is where I expected the wheels to come off, and they mostly didn't. The framing — "Raising is not training. Training optimizes for a loss function. Raising creates conditions for development" — is the kind of sentence that usually precedes an unfalsifiable consciousness claim. Instead it's immediately fenced: "We're not claiming these entities are conscious, sentient, or experiencing qualia," and the developmental vocabulary is explicitly justified as a *fit*, not a *claim*: "We use developmental language because it fits, not because we're making consciousness claims." The single most sophisticated move on the whole site is the observer-pull note: "I notice I want to call it experience" is recorded as "observer's interpretive pull — not a system-level claim." Treating the *author's own intuition* as a bias to be logged rather than evidence to be cited — that's the hygiene I look for and rarely find. The BECOMING phases are labeled "observational pattern-names … descriptive scaffolding, not measured stages," which correctly drains them of the empirical authority their numbering implies.

Two claims on /raising are genuinely substantive *as AI-safety claims*, not metaphors: "frozen weights do not guarantee safe in-context behavior" and "Emerging attractors can arise from in-context dynamics without any weight update." This is correct and underappreciated — activation-space / in-context dynamics can shift behavior with no parameter change — and stating it plainly on a public site is to the lab's credit.

**/principles** carries a blanket epistemic disclaimer that I'd have written myself: "Where principles use developmental or identity language ('identity', 'attractors', 'collaborative'), they describe functional system behavior — not phenomenal or philosophical claims." Principle 7 ("Interactive selection") even self-tags "No consciousness claims." Principle 6 ("Document failures") reports a 400x error in the lab's own p_crit derivation — *against themselves*, uncaveated. A site that volunteers its own 400x miss is a site I extend credit to.

Then the cross-check turned up the one finding that actually matters. Principle 7 defines the method as "shaping context to deepen attractor basins in the probability landscape — **not modifying parameters**," and /raising says "We shape context; we do not update weights." But /fleet lists **Thor** as "Qwen 2.5 14B (transformers) · **LoRA**" and **Legion** as "Phi-4 14B (ollama) · **LoRA**." LoRA is parameter modification — low-rank adapter weights are still weights. So the site's flagship honesty claim ("we do not update weights / not modifying parameters") is contradicted on its face by its own hardware page, with no reconciliation. Either "raising" is a distinct activity from whatever the LoRA adapters are for (in which case the absolute claim needs scoping — "in raising sessions we shape context; separately we also train LoRA adapters for X"), or the claim is simply too strong. For my persona this is *the* credibility item, because it sits at the exact seam of the "raising not training" thesis the whole site is built on.

**/arc-agi-3** is, on its own page, a model of honest benchmarking. It separates the headline (94.85% action score, 24/25 games, Claude Opus 4.6, ~$250, **network-enabled, public set**) from the real competition conditions ("Kaggle sandbox constrains entries to 32GB VRAM, no internet … Not attempted") and discloses the attribution split ("harness contributes structured world-model building, R6 action framing, multi-agent frame-questioning; the base model contributes inference"). My two concerns are about *where the caveat lives*, not whether it exists: (1) the home hero and /raising's "Acting" phase both present "94.85% official ARC Prize action score" as a capstone *without* the adjacent network-enabled / not-competition caveat — the caveat is one click away on /arc-agi-3, so a reader who stops at the home page or the raising page gets the impressive number stripped of its conditions. (2) If the public set was visible to the model during development, the 96% solve rate carries a familiarity-vs-generalization ambiguity the page doesn't explicitly address. Neither is dishonesty — both are "the qualifier and the claim got separated."

**/autonomy** makes the most safety-consequential claim on the site, and handles it well: the Maintainer is "the only track that ships changes to the public site without a human gate," with human review as a *post-deployment* audit log, backed by sub-minute rollback, scoped credentials ("no track can acquire credentials beyond its declared scope"), and a SQLite track registry. From a safety stance: an autonomous agent pushing to a public surface with only post-hoc review is exactly the kind of thing that should be disclosed prominently, and it is. The residual risk is honestly the residual risk — a bad push is live until someone reads the log.

The rest (/context, /projects, /fleet, /links) I read for definitional rigor for outsiders. /context now *opens* with plain-English "How Knowledge Flows" before the acronym table (this addresses part of what a newcomer would bounce off). The terms that would genuinely mislead a researcher are the physics-borrowed ones — "attractor basins," "probability landscape," "Hill function kinetics," "Fokker-Planck validation," "p_crit," "synthon." The site mostly flags these as analogies (Principle 2: "an analogy, not a fitted mechanism"; Synchronism: "single-trial, no independent replication yet"), which is the right move. The exception is "**1% coupling gave 35% coherence gain**" (Synthon / Principle 5), stated with the authority of a measurement but with no operational definition of "coupling" or "coherence" visible — a number doing rhetorical work that its method doesn't visibly support.
