## Pass 1: Curious Developer

### Summary
- **Pages visited**: 8 (Home, Projects, Fleet, Autonomy, Context, Raising, Principles, ARC-AGI-3, Links — 9 actually, counting Links)
- **Understanding achieved**: partial
- **Would return?**: maybe
- **Overall impression**: I get that it's a multi-machine self-organizing AI research collective, but the value proposition drowns in undefined acronyms everywhere except the one page (/context) that defines them.

### Journey
I clicked through from a dp-web4 repo README, so I came in cold — I know AI/LLMs, I've shipped agents, but "Web4" means nothing to me.

The **landing page** actually hooked me: "Seven machines. Fourteen repos. One recursive learning loop." That's a clean, concrete pitch. I immediately got the shape of it — a fleet of different machines running small models that "teach, validate, and raise each other." The ARC-AGI-3 callout (a reasoning benchmark) gave me a familiar anchor. Good first impression. The home page even defines most terms inline (SAGE = Situation-Aware Governance Engine, brief LCT/ATP/ADP gloss), which set my expectations high.

Then I hit **Projects** and the floor dropped out. Eleven project cards, each densely packed with acronyms — "T3/V3 verification, MRH contextualization, LCT anchoring, ATP/ADP resource tracking with MCP and RDF" — and almost none defined *on that page*. I can pattern-match that Web4 is some trust/identity layer, but I'm reverse-engineering meaning from context. As a dev scanning quickly, this is where I'd normally bounce.

**Fleet** was the most fun page — concrete hardware (Jetson, RTX 4090, Mac Mini M4), specific models (Qwen, Phi-4, Gemma), and a genuinely interesting claim: "model family matters as much as size," a small Gemma beating larger models on specific tasks. That's a takeaway I'd actually repeat to a colleague. But the same acronym soup (SAGE, SNARC, MRH, LCT, T3/V3) appears with no inline help.

**Autonomy** was clear conceptually — a 24-hour timeline of cron-like tracks, and the Visitor→Maintainer feedback loop is intuitive (it's literally CI for site quality). "Dream consolidation" made me raise an eyebrow but it's labeled as an analogy.

**Context** is where everything I'd been missing finally lived — a full glossary with clean one-line definitions and the Web4 equation. The problem: this should be linked *from* the first acronym on every other page, not discovered last. I only found the definitions because I'm thorough; a scanning dev never gets here.

**Raising** and **Principles** are more philosophy than engineering, but honestly labeled as such. "Raising not training" (shape context, observe emergence, don't update weights) is a coherent distinction I can follow. The principles read like systems-thinking design rules.

**ARC-AGI-3** had the most impressive concrete result (96% solve rate, #3 on the human leaderboard, ~$250) and — credit where due — strong caveats: it used Claude Opus (a frontier model with network access), and they explicitly did NOT attempt the harder offline Kaggle sandbox. That honesty made me trust the rest of the site more.

**Links** gave me clear repo pointers and a "start with SAGE" entry recommendation, which is exactly what a dev wants.

## Pass 2: Technical Writer

### Journey
I went methodically: every nav link, every header, every acronym, cross-checked against the canonical terms table I carry. My job is not to judge whether Web4 is *true*, only whether the site says the same thing the same way on every page.

The headline figures are now internally consistent across pages — **Home** "Seven Machines… (6 cognition + HUB)", **Fleet** "7 machines: 4 synthesis + 2 oversight + 1 HUB", **Autonomy** "the seventh machine, HUB". The "14 repos (11 public)" count on Home matches the Links page's "11 of 14". Good — these were exactly the kind of numbers that drift, and they don't.

On terminology, the headline result is reassuring: **every acronym expansion I found matches the canonical table exactly.** LCT = *Linked* Context Token (never "Lifelong"), T3 = Talent/Training/Temperament, V3 = Valuation/Veracity/Validity, MRH = Markov Relevancy Horizon, ATP = Allocation Transfer Packet, ADP = Allocation Discharge Packet, R6 = Six-Element Action Framework, SAGE = Situation-Aware **Governance** Engine (not "Guidance"), Web4 = "ontology, not architecture or infrastructure", Hardbound = "oversight" (not governance). No drift anywhere.

A note that contradicts Pass 1's friction log: the **Projects** page *does* define its acronyms inline on first use — "T3 (Talent / Training / Temperament) verified by V3 (Valuation / Veracity / Validity)", "Markov Relevancy Horizon (MRH)", "MCP (Model Context Protocol)", "RDF (Resource Description Framework)", "R6 (Six-Element Action Framework: Rules / Role / Request / Reference / Resource / Result)". Since both passes ran the same day against the same deployment, the acronyms-are-undefined complaint overstates the problem. They're expanded; what's missing is a *link* from each expansion to the /context anchor, which is a smaller ask.

The real consistency issues I found are subtler:

1. **Home-page ATP/ADP block is ambiguous.** The home page renders ATP as "Allocation Transfer Packet / Allocation Discharge Packet. ATP declares intended resource spend." That single block staples both expansions onto the ATP entry, which can read as if ATP means both. Every other page keeps them cleanly separate (ATP = declared-before, ADP = spent-form). Home should match.

2. **LCT's descriptive gloss differs between pages** (the expansion is identical; the one-liner isn't). Home: "Portable identity grounded in witnessed history, not model weights." Context: "Verifiable digital presence that accumulates witnessed history — identity grounded in record, not model weights." Same meaning, two phrasings. A glossary term should read identically wherever it's glossed, or the canonical gloss should live on /context and others link to it.

3. **Web4's disambiguation ("ontology, not architecture/infrastructure") only appears on Home, Context, and Principles.** On Projects, Autonomy, and ARC-AGI-3 it's used as "trust-native ontology" or just in the equation, without the explicit "not architecture/infrastructure" guardrail. That guardrail is the whole point of the term — it's worth carrying the short form everywhere Web4 is described.

4. **ACP = "Agentic Context Protocol"** appears on Projects without prior definition and isn't in the canonical table (ACT = "Agentic Context Tool" is a repo; ACP reads like a coinage). Either define it or align it with ACT.

5. **ARC-AGI-3 routes readers to /context** for LCT/T3/V3/MRH/ATP/ADP rather than expanding inline, while Projects expands them inline. Pick one convention; mixing "expanded here" and "see /context" across two acronym-heavy pages is exactly the inconsistency a reader notices.

The glossary on **/context** is the strongest page — complete, one-line definitions, the Web4 equation displayed correctly as `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP`. It should be the single source of truth that every other page's gloss is generated from.

**Context** is the canonical glossary and it is clean. The Web4 equation renders correctly: `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP`, with operators defined (`/` = verified by, `*` = contextualized by, `+` = augmented with). The remaining pages held up. **Principles** states the two guardrails I most care about outright: "Hardbound is not 'governance' — it's oversight" and fractal leverage as "pragmatic reuse… not unification." **ARC-AGI-3** correctly credits the result to "Claude Opus 4.6 operating within the SAGE harness" and keeps the Kaggle caveat (32GB VRAM, no internet, private game set) — that's the honest framing, the model did the inference and SAGE provided the structure. **Raising** and **Autonomy** use the terms consistently.

Two small things only a contributor would notice. (1) The Context page wavers between calling T3/V3 a "tensor" (glossary table: "Three-component trust tensor") and a "structure" (verbatim def: "Three-component trust structure"); Home says "structures." We call them tensors in the repos — pick one. (2) "ACP (Agentic Context Protocol)" is now defined in the glossary ("Web4 trust primitives layered over MCP transport") and tied to ACT — that resolves Pass 2's "undefined coinage" flag. I'll be honest: ACP isn't a term I've seen treated as established canon in the Web4 repo, but it's internally consistent and reasonably scoped here, so I'm not calling it drift — just noting it as newer vocabulary the canonical terms doc may want to ratify or retire.

## Pass 4: External Researcher

### Summary

### Journey

**Raising** is the page that decides whether a site like this is credible or not, and it mostly passes. The central distinction — "we shape context — we do not update weights" — is a real, defensible mechanistic claim (frozen parameters, in-context conditioning), and crucially they don't stop at the comfortable version. The caveat I most wanted to see is present and unhedged: *"frozen weights do not guarantee safe in-context behavior. Emergent attractors can arise from in-context dynamics without any weight update."* That is the sophisticated safety point — that in-context dynamics are a real attack/risk surface independent of training — and a less honest site would have omitted it because it complicates the clean "we don't train, so it's safe" story. Every anthropomorphic term I checked had an operational reduction attached: "identity" → "consistent session-to-session behavioral patterns," "growth" → "increasing response diversity, measurable observables, not phenomenal claims," "bilateral generation" → "the underlying mechanism is token sampling, not developmental cognition." And the evidence disclaimer is admirably blunt: "these claims rest on internal session logs — documented and dated, but not externally audited, and no log samples or coding criteria are published yet."

**Principles** held up as a set of research design rules rather than truth claims, which is the right register. "R&D, not production / nothing here is optimized for deployment," "document failures / failed experiments are signal," and "productively wrong is infinitely more valuable than never started" are the dispositions of a lab that knows most of its bets won't pay off — and is saying so out loud. Principle 7 ("interactive selection... we don't create or delete — we interactively select") is the one I'd push on: it's doing real conceptual work but the "attractor"/"collaborative identity" language anthropomorphizes more than the Raising page does, without re-attaching the same operational caveat locally. Honest, but the disclaimer should travel with the claim.

**Autonomy** was the most reassuring page from a safety-of-the-system (not safety-of-the-claims) standpoint. "Dream consolidation" is explicitly labeled "a functional analogy for the consolidation process — not a claim about cognitive equivalence." Good. More importantly for me, the page is candid about its *own* trust boundaries: the Maintainer track "autonomously commits and pushes to Vercel — the only track that ships changes to the public site without a human gate," with oversight described as "detect-and-revert" rather than preventive approval. That is an honest disclosure of a real risk posture (post-hoc correction, not pre-commit gating) rather than a claim of airtight control. I'd want that boundary stated even more prominently, but I credit them for not hiding it.

**ARC-AGI-3** is the cleanest example of honest benchmark reporting on the site. The 94.85% official action score / 96% solve rate is attributed precisely — "Claude Opus 4.6 operating within the SAGE harness," model does inference, harness does structure — and the conditions that matter are disclosed without being buried: network access enabled, ~$250 spend, public game set. The Kaggle constraints they did *not* attempt (32GB VRAM, no internet, private set) are named explicitly, and the result is framed as "the ceiling — what the loop can do with a frontier model and network access," not as a competition win. This is how to report a capability demonstration. It also does the single most important thing for my trust in *everything else* on the site: it cleanly separates the one externally validated claim from the body of internal observations.

**Context** is the load-bearing page for an outsider, and it's strong — a 40-term glossary, the equation `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP` with operators defined, and — unusually — an explicit evidence-tier section (Externally validated / Internal observations / Unreplicated / Verification requirement). A site that ships its own "here's what still needs independent replication" list is signaling the right epistemic norms.

Where I'd push back. The **fractal-leverage / Synchronism cross-domain claim** is the one place the discipline slips. On Context and Principles the framing escalates to "the same pattern instantiated at every scale... reuse across quantum-to-cosmic domains," and concretely: "when coupling-coherence kinetics govern both enzyme binding and trust formation, that identical mathematics becomes leverage across system layers — Synchronism discovers it, Web4 encodes it, SAGE executes it, Hardbound enforces it." Claiming that Hill-function kinetics *identically* governs enzyme chemistry and trust formation is a very large, very falsifiable-sounding claim resting, as far as I can tell, on the same single unreplicated coupling-coherence trial. To the site's credit, the Raising page calls the Hill-function/trust mapping "an analogy, not a fitted mechanism" — but that local hedge does not travel to the Context/Principles framing, where it reads as exactly the "unification / scope inflation" the site's own terminology table tells it to avoid. This is the one spot where the site's enthusiasm for its grand unifying pattern outruns its evidence, and it's the spot a skeptical reader will seize on first.

Second, **Synchronism's foundational claim** — "reality emerges from intent dynamics on a discrete Planck grid" — is presented as a "theoretical foundation." The "proposing/theoretical" hedge is technically present, but a claim of this magnitude, load-bearing for the whole stack's "fractal" story, deserves a sharper "speculative, not established physics" flag than it currently carries.

### Unanswered Questions
1. What is the actual evidentiary basis for the cross-domain kinetics claim beyond the single coupling-coherence trial? Is there any second instance where the *same fitted parameters* describe two domains, or is it purely analogical?
2. "Externally audited" is named as a gap for the internal observations — is there a plan/timeline for releasing redacted session-log samples and coding criteria so the raising claims become checkable?
3. The ARC ablation baseline is listed under "verification requirement" — without it, how much of the 94.85% is the SAGE harness vs. Claude Opus 4.6 alone? That decomposition is the single most decision-relevant number for an outside evaluator.
4. Is the "detect-and-revert" oversight on the Maintainer track ever insufficient — i.e., is there a window where unreviewed content is live on the public site? How long?
5. Synchronism's "intent dynamics on a Planck grid" — is this offered as falsifiable physics, or as a generative metaphor for the engineering? The site's framing leaves the epistemic status ambiguous.

### Verdict
As an outside safety/trust researcher, I find this site notably more honest than its subject matter would predict: the consciousness-adjacent claims that usually sink credibility here are operationalized and explicitly disclaimed at point of use, the single externally validated result (ARC-AGI-3) is cleanly walled off from the internal observations, and the site volunteers its own verification-requirements list — including the inconvenient admission that frozen weights don't guarantee safe in-context behavior. The credibility risk is not the consciousness language; it's the one grand claim — that identical mathematics governs enzyme binding and trust formation across "quantum-to-cosmic" scales — which is placed with more confidence than a single unreplicated trial can carry and which contradicts the site's own warning against scope inflation. Rein in that one claim to the analogy the Raising page already (correctly) calls it, and this reads as a credible, intellectually honest research program rather than an over-reaching one.
