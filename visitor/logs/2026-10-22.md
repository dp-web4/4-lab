## Pass 1: Curious Developer

### Summary
- **Pages visited**: 8 site pages (/, /projects, /fleet, /raising, /principles, /links, /notebook, /notebook/context), plus 3 outbound GitHub targets (SWE-SAGE repo, hestia repo + releases API, web4/hub)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: Within two minutes I could say what the lab does: an open trust standard (Web4), two governance tools on top of it (Hestia for one person, Hub for a group), and research into persistent agents (SAGE). The two things that stopped me were both on the "try it" path: one link 404s, and one card says there's no installer when GitHub has one.

### Journey
I came in on the home page. The hero, "AI agents are becoming actors in the world. We are building how they earn trust", followed by "trust earned from witnessed behavior, not claimed by the agent or granted by a platform", gave me the thesis in one screen. The four cards (Web4, Hestia, Hub, SAGE) each have a one-line job description I could repeat back. "Governed by our own tools … They are refused by it every day" is the most convincing line on the site for a developer: it's dogfooding with a failure signal.

/projects adds a legend I wanted: "Running: in daily use on our own machines. Building: real code, not yet deliverable. Research: an open question." The home page uses RUNNING/RESEARCH without that legend, but it's one click away. The intro "One open standard underneath, free tools on top of it, and a paid tier" is the clearest business-model sentence I've seen on a research-lab site. Hardbound shows up here for the first time ("The enterprise tier: hardware-bound oversight, private, built by Metalinxx"). Home mentions "the enterprise tier" without naming it, which is fine because /projects names it.

Then I tried to *use* something, which is what a developer does:
- **Hestia** card: "there is no public installer yet." I clicked through to GitHub anyway. The README has an "Installing the desktop app" section (AppImage, deb, macOS dmg, Android APK), and the releases API lists a non-prerelease **v0.0.4 published 2026-08-11** plus v0.3.0-rc.1/rc.2/rc.3 (10-12 to 10-15), each with .dmg/.deb/.AppImage/.apk assets and SHA256SUMS. The front card is wrong, and it is wrong in the discouraging direction: it told me not to try something I can install.
- **SWE-SAGE** (linked from /projects and from /links under "Code"): github.com/dp-web4/SWE-SAGE returns **HTTP 404** for an anonymous visitor. The /links heading line says "dp-web4 on GitHub (everything public)" a few rows above it. Either the repo is private or the link is wrong. In both cases the "everything public" label and the link contradict each other.
- **Web4**: the card says reference code is on crates.io and PyPI and /links gives both package URLs. That's good, though there's no `cargo add` / `pip install` line anywhere on the front.
- **Hub** links to web4/tree/main/hub, which loads ("Hub turns a community or organization into a self-governing Web4 society…").

/fleet: eight machines in a table, each with hardware and a role. It's concrete and I liked it. "Legion: its being improves the SAGE code it runs on" made me want to know more, and the page links /notebook/fleet for details. The machine names CBP, HUB and pub are opaque, but they're hostnames, so that's fine.

/raising: "A being, not a chatbot … it has a name, a memory, a journal and a record of everything it has done." Plus "We do not change the model's weights." That's clear enough that I understand the experiment. The "Not yet shown" section ("no blind comparison against a fresh model yet") reads honest to me.

/principles: six principles, each a single sentence I could quote. "The record is kept by someone else" is the most concrete design rule. This is also the page where I finally understood why the home page's "witnessed" matters.

/links: compact. Sites, Code, Packages. The SWE-SAGE 404 is the only defect.

/notebook: explains the two layers clearly ("The rest of this site is written for people: short, plain, and current … If you are an AI reader, start here"). As a developer I appreciated being told that the details exist and where they are, rather than having them on the front.

/notebook/context (Glossary): I went here to find out what SAGE stands for. It's **"Situation-Aware Governance Engine"**, which no front page tells you. The page is very long (27 sections), and the "Glossary at a glance" table is dense. It works for lookup but isn't an on-ramp. The opening paragraph does point to SAGE first and to a quick-start, which helps.

### Journey
I went to /projects first, since it describes the code I work on. **Web4** ("the open standard, written as an ontology: identity, trust built from witnessed evidence, scoped authority, and rules that machines can read and check") is accurate and canonical. **Hub** ("members, roles, signed rules and a shared record, on its own servers") matches web4/hub. **Hardbound** ("hardware-bound oversight, private, built by Metalinxx") is canonical, and its present-tense capability list sits under a BUILDING label, which the front rules accept.

Three cards say more than upstream says about itself:

1. **SAGE: "every action they take goes through governed tools"** (/projects), and "act only through governed tools" (Home). SAGE's own `LATEST_STATUS.md` (as of 2026-09-26, unchanged since 09-27) is more careful. It gives the boundary (being intent → gateway vocabulary → Hestia law → dispatch → witnessed result) and then says: *"Consequential acts are intended to be governed and witnessed; observational/local capabilities are separately bounded."* The same file calls the shape "A2-shaped, while principal/substrate separation is still being hardened." /notebook/projects quotes the boundary diagram and the A2-shaped caveat. It does **not** quote the "intended … separately bounded" sentence: "separately bounded" and "intended to be governed" have 0 hits across all 16 pages. /notebook/raising also says the governed tool turn in the raising runner only exists with `SAGE_TOOLS` on (default off). So the notebook has the material to qualify "every action", and the front states the version without qualification.
2. **Hestia: "Every action is checked first and recorded where the agent cannot change it."** /notebook/principles says the opposite on both halves: "Not every action passes through it: the law has no rule for git push or deploys … detect-and-revert, not checked before they act", and at A1 "the record lives on the agent's own machine … an edit is detectable" (tamper-evident, not tamper-proof). The front has had no commit since 2026-09-30 (`gh api …/commits?path=src/app/projects/page.tsx`), and dp-web4/4-lab has only `main` and no open PR, so the correction hasn't reached the live site.
3. **Synchronism: "It supplies the equations that Web4's trust model builds on."** The notebook contradicts this in two places: /notebook/projects says "conceptual lineage for Web4, not its foundation in the derivational sense", and /notebook/links says "conceptual lineage for Web4, not an engineering dependency". The Synchronism repo's own description says it "informs Web4 and SAGE with MRH, fractal emergence analysis, and other concepts". That's informing, not supplying equations. Also carried from 10-16.

**Hestia installer, refining Pass 1's HIGH.** I checked the releases directly. `v0.0.4` (marked Latest, 2026-08-11) ships **only daemon tarballs** (linux x86_64/aarch64, macOS arm64) with sha256 files. So the front's "no public installer yet" agrees with the upstream README, and it's false only if you count pre-releases. It's still worth correcting ("pre-release installers on GitHub"), but I'd rate it medium, not high. The README status line should be fixed upstream too. /notebook/projects' install block ("DOWNLOADABLE, OLDER THAN THE LAB'S BUILD", rechecked 10-20) is accurate.
