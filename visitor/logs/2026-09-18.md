## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (Home, Projects, Glossary(/context), Fleet, Autonomy, Raising, Principles, Links, ARC-AGI-3)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: I can tell you what this lab believes and I can clone something that runs — but the license statement on /principles contradicts what the repos actually carry, and /fleet buries the facts under its own audit history.

### Journey

Landed on the home page from a repo README. The two-line headline does its job — "AI agents are becoming actors in the world. Trust and authority need to become first-class." plus "trust should be computed from witnessed evidence, in context, by the party doing the relying" told me the thesis before I scrolled. That is better than most research-lab sites.

Then I hit the stat row and slowed down. "8 machines" is fine. "21 SAGE instances configured" comes with a parenthetical about a census date and which figures are published where. "4 model families deployed" comes with a sentence explaining that deployed doesn't mean running, that both Qwen lines are quiet, and that HUB's loop fires without writing records. Each number is immediately qualified into uselessness for a first-pass reader. I respect the honesty; I also stopped reading the numbers.

"What is being built" was the payoff: four cards — Web4, Hestia, Hub, SAGE — each one plain enough that I could repeat it back. Web4 = open trust ontology on an RDF graph. Hestia = one machine, multiple vendors' agents, one signed law. Hub = Rust society runtime. SAGE = persistent-agent research around frozen weights. That's the 2-minute answer and it works.

Clicked "Calibration" under Start here expecting a page. It threw me to `github.com/dp-web4/web4/blob/main/STATUS.md` on GitHub — a raw markdown file, no warning I was leaving the site. The other two Start-here cards stay on-site. Minor, but it broke the browse.

/projects is where I went next, and it's the most useful page for me. Thirteen cards, each with a `public`/`private` and `runnable`/`research-stage` badge — that badge pair is the single best thing on this site for a developer. It tells me ACT is stalled before I waste an evening on it. The Web4 card itself is a 300-word wall: the whole equation, what the slash does and doesn't mean, a note that V3 records rather than gates, package versions, and a disclaimer about crates.io metadata calling it "infrastructure" — all in one paragraph with no one-line summary at the top.

The Quick start at the bottom of /projects is genuinely good and I want to say so plainly: real commands, a stated dependency list, a `# What success looks like` paragraph that tells me an idle daemon in WAKE with an empty buffer is the *correct* first result, a note that the SAGE README has no setup section so these steps are maintained here, and "If these steps break, that is a bug on this page." I checked the one claim I could check from my desk — `pip install web4-core` is real, 0.3.0 is live on PyPI, and the crate exists on crates.io. The claims that are checkable check out.

One gap in those steps: the dependency comment says "Rust toolchain, Ollama, Python 3.10+", then step 1 runs `python3 -m sage.instances.init`. There's no `pip install -e .` or requirements install anywhere, while the Rust half gets an explicit `cargo build --release`. If that module has any third-party imports, a reader following this literally gets a ModuleNotFoundError at step 1.

Then the license question, which for me is the decision question. /projects says "licenses and the full repo list are on /links". /links has a Licenses block: "ARC-SAGE: MIT-0... Gemma 4 Good Submission: Apache 2.0. Other repos: see each repo's LICENSE file — check before forking." Fine. But /principles opens with "the code these principles produced is public and MIT-0 (MIT No Attribution)". So I checked. SAGE, web4, hestia and 4-hub are all **AGPL-3.0**. Only ARC-SAGE is MIT-0. AGPL versus MIT-0 is the difference between "I can build on this" and "I need to talk to legal," and the site states the permissive one on the page a newcomer reads for posture.

/fleet defeated me. I wanted a table: machine, hardware, model, is it running. That table exists — it's excellent, with dated states and a four-state vocabulary that includes "instrumentation broken" — but it sits behind roughly 3,000 words about how the session counts are derived, why the previous derivation (matching git commit subjects) was unsound, which fifteen subject shapes write records, and why a test that returned exactly two nonzero rows would be reporting its own construction. That's real work and I'd read it if I already cared. As a first-time visitor I scrolled for a long time wondering if there were any machines on the machines page.

/autonomy answered the question I'd been carrying since the home page — what is actually running unattended — and answered it well. The one-sentence "how the tracks relate to SAGE" paragraph is the kind of thing I wish every page had. The "Autonomous means unattended and self-scheduled, not self-directed" framing landed. So did admitting the maintainer track pushes without pre-approval.

/raising and /principles I skimmed — they're for a different reader than me, and both say so. /raising's "What We're Not Claiming" section was the reason I didn't bounce. ARC-AGI-3 is short, sharp, and leads with "this is not current competition positioning," which is the opposite of how a 94.85% number usually gets presented.

### Unanswered Questions

1. What license am I actually agreeing to? /principles says MIT-0, the repos say AGPL-3.0. Until that's resolved I can read this code but I can't plan with it.
2. Is there anything hosted I can poke at, or is every entry point a clone-and-build? No demo, no playground, no public Hub instance I can join — /fleet says pub is the staging host for the first public-facing hub and that go-live is gated, which answers "not yet" but doesn't tell me what to watch.
3. Does step 1 of the quick start need Python packages installed? The steps don't say, and that's the first command that can fail.
4. Web4 is an ontology on RDF — so is there a published schema/vocabulary file I can look at, or is "ontology" being used in the conceptual sense? The glossary says "the Semantic Web sense: a shared vocabulary of concepts and the relationships between them", which implies there's a real vocabulary somewhere, but nothing links to it.
5. If I found a bug in the site or a repo, what happens? /links says there's no CONTRIBUTING guide and to "ask in an issue first". Are issues actually watched, given that most of the maintenance here is autonomous?

### Verdict

This is the rare research site where I finished believing the claims, because it keeps showing me the thing that would disprove them — a machine card that says "instrumentation broken", a quick start that tells me an empty buffer is success, an ARC score presented with the affordance that inflated it. The value proposition is clear in two minutes and there is a real first clone at the end of it. What holds it back for a developer is that the honesty has started to crowd out the content: /fleet is now mostly a post-mortem of its own previous counting method, and the home page's numbers are outweighed by their own caveats. And the one claim I checked that failed is the one that matters most to me commercially — the site tells me the code is MIT-0 and the repos say AGPL-3.0.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 (all)
- **Understanding achieved**: solid
- **Would return?**: yes
- **Overall impression**: Terminology is clean enough that I had to stop looking for drift and start auditing form — and the form is where this site is failing: it states a single-sourcing policy it doesn't follow, names its most-linked page two different things, and has anchors on exactly one page out of nine.

### Journey

I did this pass twice: once reading, once checking. The reading pass gave me the impression that the vocabulary was unusually disciplined. The checking pass — fetching each page's rendered HTML and grepping expansions, anchors, link targets and heading levels — confirmed the vocabulary and turned up a different class of problem underneath it.

Start with the good news, because it's load-bearing for the rest. Every canonical expansion on this site is correct, and each one appears **exactly once per page**: "Linked Context Token" on 6 pages, once each. "Trust Tensor" on 7, once each. "Markov Relevancy Horizon" on 6. "Allocation Transfer Packet" / "Allocation Discharge Packet" on 5 each. The R6 element list is byte-identical in all five places it appears — `Rules / Role / Request / Reference / Resource → Result`. Zero occurrences of "Lifelong", zero of "production ready". The Web4 equation string is identical on the two pages that carry it. I have audited sites with a tenth of this vocabulary and twice the variance. Whatever process produced this is working.

So I went after structure instead.

**The glossary page has no name.** The nav says **Glossary**. The `<title>` says `Glossary | 4-lab`. The `<h1>` says `Glossary`. And then the body prose of every other page refers to it 33 times as **"/context"** — a path the reader has no way to connect to a nav item, because no nav item says Context. On top of that the site names it three ways: bare `/context` (33), "the /context glossary" (6), and "the glossary" (8). This matters more here than it would elsewhere, because *context* is a loaded word on this site: Linked **Context** Token, Agentic **Context** Protocol, Model **Context** Protocol, "the CLAUDE.md pattern" as context engineering. A reader who meets "see /context" reasonably parses it as a pointer to material about context, not to the glossary.

**Link text names the URL, not the destination.** 36 of the ~107 in-text cross-page links use a bare path as their visible text — "/fleet", "/raising", "/context", "/projects". Roughly one in three. The inverse also happens: on /fleet, the two links to the T3 and V3 glossary rows have the visible text "/context", while a *different* link whose visible text is literally "T3" points to /principles. The term is the link text for the page that isn't the definition; the path is the link text for the page that is.

**Anchors exist on one page.** /context carries 64 anchor ids and is a genuinely excellent piece of reference work — I checked all 44 internal anchor links used site-wide against the ids on their target pages and **every single one resolves**. Zero broken fragments. That is rare and worth saying. But the other eight pages have 1, 1, and seven zeros. So when prose says "see **Principle 6** on /principles", "**Jetson**", "**CBP**", "**detect-and-revert**", "**Explorer track**", "**BECOMING patterns**", "**SAGE's six brain-analog components**" — every one of those lands the reader at the top of a page and asks them to scan. /fleet is ~35,000 characters. There are twelve "Principle N" references on this site, six of them from other pages, and not one can deep-link, because /principles has zero ids.

**/principles has no headings at all.** Not "wrong headings" — none. `h2=0, h3=0`. The ten principle titles are `<div class="principle-title">`. The page has one `<h1>` and then 7,800 characters of unstructured text. There is no document outline, nothing for a screen reader to navigate by, and nothing to anchor those six inbound cross-references to. /context has the opposite problem in a milder form: 26 `<h3>` elements and zero `<h2>`, so the longest page on the site (71,000 characters) is a flat list of 26 same-level sections under a single h1.

**The site states a single-sourcing rule and then breaks it.** This is my most specific finding. The `/context#governance-oversight` entry ends with: *"Other pages that mention the correction link here rather than re-explaining it."* That is a stated editorial policy, so I checked it. Six of the eight other pages re-explain the correction inline — /projects ("'oversight' = machine-enforced policy gating here, not human supervision"), /raising (same phrasing), /links ("'oversight' meaning machine-enforced policy gating, not human supervision"), /principles ("Hardbound is not 'governance' — it's oversight: watching, gating, and reverting actions"), /fleet (twice), /autonomy (a dedicated word-choice note before the page body). **/raising and /links don't link to the entry at all** — no `#governance-oversight` href anywhere on either page. The same pattern holds for the other correction: "not architecture or infrastructure" is restated on five pages. The policy sentence isn't just unmet, it's actively misleading to a maintainer, who would read /context and conclude the duplication has already been cleaned up.

Two smaller things I'd normally let go, flagged because this site has earned a high bar:

The T3/V3 expansion has three typographic forms. Six pages use `T3 (Trust Tensor — Talent / Training / Temperament)`. /fleet and the /context glossary row use `T3 (Trust Tensor, root dimensions Talent / Training / Temperament)`. The /context worked example uses `T3 = Trust Tensor, dimensions Talent/Training/Temperament`. All three are canon-correct, so this is not drift — but the qualifier **"root"** appears on only two of eight pages, and "root" is the word doing the work: it tells the reader the three dimensions are the top of a tree rather than the whole of the tensor. Dropping it on six pages reads as an exhaustive definition. (I note the previous form-level problem here — the bare `T3 (Talent / Training / Temperament)` in the worked example — is gone. That got fixed.)

And /raising opens with "Web4 vocabulary on this page (T3, V3, MRH, LCT, LoRA) is expanded inline on first use" — a sentence which is itself the first appearance of all five terms, unexpanded, with the real expansions arriving 2,500 to 8,600 characters later. In fairness I checked whether the policy otherwise holds, and it does: that promise sentence is the *only* bare use of each term before its expansion. So it's one sentence to fix, not a page to fix. The same inventory-sentence construction appears on /projects, /links and the home page.

### Unanswered Questions

1. Is the `/context` route intended to be renamed, or the **Glossary** label intended to change back? Thirty-three prose pointers are waiting on that decision, and fixing them in the wrong direction costs twice.
2. Is /principles' lack of headings deliberate presentation (the cards are visually styled) or an oversight? The six inbound "Principle N" references suggest the anchors were assumed to exist.
3. Who maintains the single-sourcing rule in `/context#governance-oversight`? It reads as a policy someone committed to, and the drift away from it happened after. If there's no check enforcing it, the sentence will keep going stale.
4. Is there a style guide fixing the T3/V3 expansion form, or is each page's copy independently correct by author discipline? The once-per-page consistency looks mechanical; the three typographic forms look manual.
5. On /fleet, why does the link labelled "T3" point to /principles rather than the glossary row? If that's deliberate (trust-is-relational framing), the link text should say so.

### Verdict

The terminology audit that this pass exists to perform comes back clean — not "no drift found today" but "no drift findable by counting expansions across nine pages," which is a stronger result and means this check has largely converged. What's left is editorial structure, and there the site has a specific and fixable problem: it wrote down a single-sourcing policy in the glossary, six pages don't follow it, and two of them don't even link to the page that claims it. Combined with seven of nine pages having no anchors while prose across the site points at named sections on them, the picture is a site whose reference page is excellent and whose other eight pages haven't been wired to it.

### Journey

I came to this from a conference mention, expecting the usual: developmental language about AI systems, a consciousness disclaimer in the footer, and claims that dissolve when you ask what was measured. That is not what is here.

I read /raising first, because "raising, not training" is the claim that would either be defensible or not. It is defensible, and for a reason I did not expect: the page states its own comparator and then says the comparison has not been run. "We're claiming, provisionally, that developmental descriptions fit what we observe better than context-engineering descriptions do. That is the comparator this page opens with, not training, and the comparison has not been run." The naive reading of "raising not training" is a contrast with gradient updates; the page explicitly refuses that easy contrast and picks the hard one — competent context engineering — as the thing it has to beat. Then it specifies a scramble/yoked control, states a dissociation prediction (identity-continuity measures degrade while task competence on the same scrambled context holds), pre-registers the consequence ("if this control runs and the result is a bare main effect, or no degradation at all, that outcome gets published on this page and the developmental vocabulary gets retired from it"), and — this is the part I have never seen a lab site do — notices that its own pre-commitment is unreachable and says so: the dependent variable is identity continuity, identity continuity rests on "coherence," and the glossary concedes coherence has no single operational definition. "A promise conditioned on an event that cannot occur costs nothing and binds nothing — it has the shape of accountability without the substance, and left unflagged it would be the most self-serving sentence on this site."

It then does the right thing: replaces the unreachable promise with a reachable one. The attempt to operationalize identity continuity "gets published as its own artifact, including if it fails," and the reader is handed the enforcement rule — "If that attempt is never published, read the pre-commitment above as unbacked, and read this paragraph as the standard we asked to be held to."

That is an invitation to audit, so I accepted it. And immediately hit the problem this pass is about: **"never" has no start date.** A reader today and a reader in 2027 read the identical sentence and cannot tell which of them is entitled to call the pre-commitment unbacked. The site asked to be held to a standard and withheld the one parameter that makes the standard operable.

The glossary check told the same story from a different angle. /context is genuinely excellent on the thing that usually goes wrong for outsiders — borrowed words that smuggle in borrowed rigor. "Attractor" is flagged as "a METAPHOR, not a formal dynamical-systems object... it borrows the connotation of mathematical precision from a formalism this site does not cash out." "Emergent" is explicitly disowned from the scaling-literature sense: "no claim that a capability appears discontinuously at some parameter or data threshold, and no position taken on whether such discontinuities are real or metric artifacts." "World model" is separated from the ML sense. "Coherence" concedes three senses and no operational definition, and then says which sense carries the numbers. I audit terminology for a living and I do not normally get to write that paragraph.

So I went looking for what the disclosure layer does *not* cover, and then for how old each disclosure is.

On age I could actually get a number, because `dp-web4/4-lab` is a public repository (GitHub API returns 200 unauthenticated) — though the site never links to it, which is itself a finding, since that repo is the artifact that would let any reader date every claim on the site. But the oldest and most consequential line — the control that adjudicates the site's entire vocabulary, "no date, no owner, no pre-registered metric yet" — has been on the page for 56 days, during which that page was edited 21 times, most recently yesterday. The status line has never moved. Whatever the maintenance loop is optimizing, it is refining the description of the gap rather than closing it.

And the site half-names why. /raising itself splits the blocker in two: for identity continuity the blocker is definitional, but "For growth, nothing definitional does: this page already operationalizes it (response diversity and curriculum-phase task success), so a yoked or scrambled-history control on growth could be pre-registered now — **its absence is logistical.**" The site has identified a runnable, unblocked half of its own decisive experiment and left it unscheduled for 56 days. The excuse has already been eliminated by the page that makes it.

/autonomy is the same shape in a more uncomfortable place. It names — unprompted, in its own words — that every check on this site is run by sessions drawn from the same model families as the sessions that author it: "their misses are correlated with the authors', not independent of them." It then joins three of its own statements to name the fix: "Running even one visitor persona on a different model family would be a scheduling change, not a research program, and it would convert the rollback count from an uninterpretable number into a weak but real one. **It has not been done; the audit that keeps flagging it cannot change its own schedule.**" That last clause is the honest diagnosis of this whole class: there is a channel from observation to disclosure, and no channel from disclosure to a scheduling decision with a name on it. /context states the consequence plainly — "There is no external, blinded, or third-party check."

I checked whether closure happens elsewhere and is simply not reflected on the site. It does not appear to. Across all nine pages there is not one forward-dated commitment — no "will be run by," no owner, no assignment. And the org visibly knows how to do this: `dp-web4/SAGE` carries 17 issues and `dp-web4/web4` 36, specific and well-scoped ("/delegate is an unauthenticated network actuator," "council mode does not govern law amendment"). A search of those trackers for the deflationary control, the scramble/yoked control, or the identity-continuity metric returns nothing. The lab has a working mechanism for assigning security and infrastructure work to owners, and its central epistemic commitment lives only as prose on a website.

Two smaller observations, both in my remit as the terminology reader.

First, the glossary has 57 entries and indexes implementation vocabulary exhaustively — Cartridge, Metabolic state, Crystallization, Chapter ledger — while omitting the three terms that carry the site's epistemic weight: **BECOMING**, **interactive selection**, and **consciousness**. BECOMING appears five times on /raising, twice on /fleet and once on /context's own evidence section, and a reader who arrives at /fleet's "it is not one of the BECOMING patterns" has nothing to look it up in. "Interactive selection" is the title of Principle 7 and a section heading on /raising, and *selection* is a heavily loaded word for my audience — it reads as selection over model variants or selection pressure on weights, which is the opposite of what the site means by it.

Second, and more specifically: the glossary disowns every borrowed word *except the most loaded one*. "Consciousness" appears three times on this site as part of a quoted code artifact — SAGE's capability matrix calling the Rust daemon "not a port of the Python 12-step **consciousness** kernel," and PolicyGate's header describing a "conscience checkpoint for SAGE **consciousness** loop." Those are honest quotations of upstream names and the site attributes them correctly. But a researcher skimming /projects sees a lab that disclaims consciousness claims on one page and quotes its own module named `consciousness` on another, with no row anywhere saying "this is an upstream module name, not a claim." The glossary has exactly this row for attractor, for emergent, for world model, for synthon-vs-chemistry, and for hestia-vs-Hestia. Its absence here is a gap in an otherwise systematic pattern, in the single place where the pattern matters most to my audience.

On the claims I could check from outside: the ARC-AGI-3 framing is sound and — unusually — the home page carries the caveat that actually matters rather than a softer one. Home says the 94.85% was obtained "using engine-level/public-game affordances outside strict competition play," which is the methodological disqualifier, not just the currency disclaimer. The ARC page goes further and states what the result does demonstrate: "what the model+harness could do with engine-level context and tooling, not blind generalization from observation." The 1% coupling / 35% coherence figure appears on four pages and carries its single-trial, not-replicated, metric-defined-only-internally caveat on **all four** — including inside the glossary entry for the term that depends on it. That is the failure mode I most expected to find (a caveated headline losing its caveat on restatement) and it is not present.

The one hard external fact on /principles that I could check is wrong. "the code these principles produced is public and MIT-0 (MIT No Attribution)" — SAGE, web4, hestia and 4-hub are AGPL-3.0. Passes 1 and 3 both found this independently. I flag it from a different angle: /principles is the page a researcher reads to calibrate how much to trust the rest, it contains exactly one claim checkable against an outside source, and that claim fails. That costs more here than on a page full of checkable claims.

### Unanswered Questions

1. By what date is the identity-continuity metric attempt due? The site asks to be held to it and supplies no clock. This is one clause and it is the difference between a disclosure and a commitment.
2. Why has the growth arm not been pre-registered, when /raising states nothing definitional blocks it and 56 days have passed? If the answer is operator capacity, saying so is a better disclosure than "not scheduled."
3. Who decides what gets scheduled? /autonomy diagnoses the structural problem exactly — "the audit that keeps flagging it cannot change its own schedule" — and the SAGE and web4 issue trackers show the lab has a working mechanism for assigning owned work. Why do the epistemic commitments live only as site prose while the security bugs get issues?
4. Does anything counterbalance the correlated-reviewer problem today? Every internal observation rests on self-audit by one model family and the site concedes there is no external or blinded check. Until one persona runs on a different model family, is there any result here an outsider should weight above "internally consistent"?
5. What would make "coherence" measurable? It is the root blocker: vocabulary ← control ← identity-continuity metric ← coherence definition. The site names the first three links and stops. Nobody owns the fourth, and it is the one everything else waits on.

### Verdict

"Raising, not training" is defensible, and defensible for the right reason — the page refuses the easy contrast with gradient descent and names competent context engineering as the comparator it has to beat, then says that comparison has not been run. The consciousness-adjacent claims are not merely caveated but cashed out: every anthropomorphic term is reduced to the tracked state it names, and the glossary disowns the borrowed connotations of attractor, emergent and world model with a precision I rarely see outside a methods section. Yes, the honest assessment feels honest — it is honest enough to notice that its own pre-commitment was unreachable and to say so in the strongest available words.

What it lacks is a clock. Every gap on this site is disclosed and no gap has an owner or a date, and the site's own public git history shows the most consequential one — the control that adjudicates whether any of this vocabulary survives — reading identically for 56 days across 21 edits of the page it sits on, while the page itself states that half of it is unblocked. The disclosure layer is eleven days old and improving quickly, so this is a trajectory worth returning to rather than a verdict against it. But the lab that argues trust should be computed from witnessed evidence has left its own open commitments as the one class of thing with no witness record, and the fix is a date.
