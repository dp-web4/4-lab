## Pass 1: Curious Developer

*Method note: I browsed with WebFetch and checked every friction item below against the live HTML (curl + text extraction), because the WebFetch summaries were wrong on checkable points. For example, the summarizer said the glossary had "~80 entries, alphabetical", but the rendered table has 58 rows in no sort order. As a developer, I also checked the Quick start and the repo counts against GitHub (`gh api`). That is what someone arriving from a README would do, and it stays within this persona's knowledge.*

### Summary
- **Pages visited**: 9 (all nav entries: Home, Projects, Glossary(/context), ARC-AGI-3, Fleet, Autonomy, Raising, Principles, Links). The pass prompt said "all 8 pages", but the nav lists nine.
- **Understanding achieved**: partial
- **Would return?**: maybe. I'd come back for Hestia and the SAGE Quick start, not for the prose.
- **Overall impression**: The work is real and unusually honest. From Home I could tell there are four projects and a fleet of machines. But every page spends its first screen on what things are *not* and on how earlier versions of the page were wrong, before it says what I can do.

### Journey

**Home.** The headline ("AI agents are becoming actors in the world. Trust and authority need to become first-class.") is good. The next sentence defines Web4 by negation first: "an open trust ontology, not an architecture, infrastructure or stack". I don't know yet what an ontology *does* for me, and I'm already being told which words not to use. The four project blurbs are the most useful thing on the page. Hestia ("AI agents from multiple vendors: one law, scoped delegation, a vault, witnessed actions") immediately made sense. I run Claude Code and Codex on one box, so this is the thing I'd try.

What didn't land:
- SAGE is expanded as "Situation-Aware **Governance** Engine" and grouped with "running governance systems". The card then describes identity/memory/salience research around frozen model weights, which is not governance. The explanation that "Governance" is a legacy name is only on /projects and /context, not Home.
- The stats block ("21 SAGE instances configured… 8 of them carry raising history… deployed is not the same as running… how instance, line and session record nest is on /context") is a paragraph of qualifications under a number. I don't know what "raising" is at this point, and Home never says. It is used 5 times ("raising lines", "raising history", "raising records") and never defined.
- The Hestia blurb brings in an A0–A4 assurance ladder and then a disclaimer about TCSEC class A1. That's inside baseball for a landing page.
- "Hardbound is not the only private piece:" is a sentence that starts by answering a question I never asked.
- The nav says **Glossary**, the URL is **/context**, and inline links say "on /context". There are three names for one page.

In 2 minutes I understood roughly this: a group building an open trust vocabulary (Web4), a multi-agent governance daemon (Hestia), a community server (Hub), and an agent-research kernel (SAGE), run by AI agents on 8 machines. That's a pass, but it took longer than 2 minutes.

**/projects.** I jumped to "Want to run something rather than read? Start with SAGE". That's the right signpost. Before the cards there's the Web4 equation plus a legend, and the legend immediately says it is "the site's own gloss, not canon's — the equation is not in CANONICAL_TERMS_v1". I don't know what "canon" or CANONICAL_TERMS_v1 is. It isn't linked on this page (the only link to it is on /context), and it's the first thing below the equation.

The **Web4 card** is one sentence of roughly 200 words, with nested em-dashes and parentheses ("…the slash reads the same way on both sides of the equation, T3 by V3 and ATP by its ADP discharge record; it is not a claim that T3 and V3 verify each other — contextualized by…"). I gave up halfway. It also never says what `pip install web4-core` gives me: a library of what, with what API?

The **Quick start** was the best part of the site. I checked it against the SAGE repo: `sage/instances/init.py` exists with `--machine/--model/--operator-name` and only stdlib imports; `sage-rs/` is a Cargo workspace containing `sage-daemon`; `main.rs` reads `SAGE_MACHINE`/`SAGE_MODEL` and defaults to port 8760. It's structurally consistent, and the "what success looks like" paragraph (an idle daemon in WAKE with an empty buffer is correct) is exactly what a first-time runner needs.

**Hestia is missing from the Quick start.** Hestia is a headline project, badged "runnable", and Home sends me to it ("for local agent governance see Hestia"). The Quick start covers SAGE, Web4 and a stalled ACT, but not Hestia or Hub. I checked, and the Hestia README has no install/quick-start heading either (its headings run from "What Hestia does" to "Honest status" to "Repository layout"). The project most relevant to me is the one I can't start.

The ARC-AGI-3 card carries its caveats ("Two caveats travel with this number and neither is optional"). Good. Its "Paper →" link points at the ARC-SAGE repo root, not at the repo's `paper/` directory, and /links says "no papers or preprints are published yet". So is there a paper or not?

**/context (Glossary).** The first table is 58 rows and about 5,300 words, in no order I could detect (Web4, Ontology, Trust-native, Trust, hestia, Hestia, A0–A4, Autonomous…, MCP, Substrate, RDF, LCT…). There's no alphabetical order, no in-page index, and no filter. Ctrl-F works, which is how I used it.

Two rows stood out as a naming trap: **`hestia` (lowercase) vs `Hestia` (capitalized)**, and **`HUB` vs `Hub`**. "Capitalization is load-bearing on this site: lowercase hestia is this component; capitalized Hestia is the governance daemon." But the daemon's own GitHub repo is `dp-web4/hestia` (lowercase), and its README has a heading "What hestia is not" about the daemon. A developer will type the lowercase name, because that's the repo name.

The **Raising** row says "Shaping context, experience buffer, and interaction history". That's a noun phrase, not a definition: who does what, in what sessions? /raising's own opening line is much better (below). BECOMING, which is a page heading on /raising, has no glossary row.

**/arc-agi-3.** This was the cleanest page. It says what happened, what the score measures (efficiency-weighted, not a solve rate, against the median first-time human), the affordance caveat, and why it's no longer the headline. It's about 680 words. Every page should read like this. My only wish is a number for "well behind the leaders".

**/fleet.** I came for the machines. The first machine card starts about **2,180 words** into a 6,700-word page. Before it there's a census methodology, a migration clause, three superseded session-count triples, five "raising line" states, and a long argument about why commit-subject-matching tests are unsound ("Subject matching is a vocabulary whitelist…"). That's valuable to someone auditing the lab, but it's in the way of someone who wants to see the hardware. The Legion card alone is about 880 words.

On each cognition card, the **Role:** field begins "Curriculum phase: creating (by session count, not assessed)". That's identical on all six cards and, by the page's own admission, not an assessment. The actual role ("Physics exploration lead", "Data czar…") comes last, after the brain-analogy line.

**/autonomy.** The explanation of tracks is clear: "A track is a scheduled autonomous job — a cron entry with a declared scope." The page describes my persona's job as "Tests whether the site is legible in under two minutes and whether there's a clear entry point for someone who wants to try something." My answer: there is an entry point (the SAGE Quick start), but the site is not legible in two minutes. The track figures ("31+ tracks… ~53 sessions per day") are marked "as of 2026-05-26, not recounted since", four months ago. That's honest, but stale enough that I don't know whether to believe the timeline.

**/raising.** Surprisingly, this page has the clearest definition of the site's most-used undefined word: "raising is longitudinal, entity-specific context shaping — a tutor-led session protocol … and watching what accumulates across hundreds of sessions of one identity." That sentence belongs on Home and in the glossary row. The page is heavily caveated ("This is the softest page on the site"), and I appreciated it.

**/principles.** It's readable. P3 ("R&D, not production") and P9 ("WD-40 was the 40th try") told me the most about the culture. The license correction ("the main repos … are AGPL-3.0 … check each repo's LICENSE file") is exactly what I needed before forking, and it matches the GitHub API (SAGE: AGPL-3.0, ARC-SAGE: MIT-0). P2 opens with the Hill-function analogy caveat before stating the principle, so the order is backwards.

**/links.** The repo counts check out: 21 public original repos and 32 public forks, which matches the stated "40 original — 21 public, 19 internal — plus 33 forks (32 public)". The "no CONTRIBUTING guide yet … ask in an issue first" line is honest and useful. **4-gov** gets three words ("Governance explainer site."), while the other explainer sites get a sentence. Its live `<title>`/meta is "Computable Accountability | Governance for Agentic Entities … Web4 — an open standard … from Metalinxx Inc." So it's the commercial partner's site, with framing ("open standard", "architectural accountability") that this site argues against elsewhere. Nothing here says that.

**Cross-cutting.** Dated correction notes are embedded in the reading text. I counted 25 "Until 20XX-XX-XX this page said…" notes, plus about 31 "withdrawn/corrected/previously said" markers across pages (/fleet 8+6, /raising 8+4, /context 6+13). Each one is honest. Together they make the site read like a changelog, and as a newcomer I kept having to read and discard what used to be wrong.

### Verdict
The honesty here is real: I verified the repo counts, the licenses and the Quick start against GitHub, and they hold. That's rare and it earned my trust. But the site is written for its auditors, not its arrivals. The one project I'd clone first (Hestia) has no first-run path, the most-used word (raising) is undefined on Home, and the key content on /fleet and /projects sits behind thousands of words of methodology and correction history. Pages that keep the history but lead with current state, as /arc-agi-3 does, would keep me.

## Pass 2: Technical Writer

*Method note: I fetched all nine pages as rendered HTML with curl and extracted text, headings, anchors and links with small scripts, instead of relying on WebFetch summaries. Every count and quote below comes from the live HTML on 2026-09-24. The pass prompt says "all 8 pages", but the nav lists nine, and the nav is the source of record, so I audited nine.*

### Summary
- **Pages visited**: 9 (Home, /projects, /context "Glossary", /arc-agi-3, /fleet, /autonomy, /raising, /principles, /links)
- **Understanding achieved**: good
- **Would return?**: yes. This is the most terminologically disciplined site I have audited, which is why the remaining inconsistencies stand out.
- **Overall impression**: Every canonical acronym expansion is correct on every page, and all internal links and anchors resolve. The real problems are words that carry more senses than the glossary admits ("substrate", "oversight") and one relational gloss ("T3 verified by V3") that the glossary's own V3 section contradicts.

### Journey

I started at Home and followed the nav in order. /autonomy describes my persona's job as auditing "every acronym on first use", checking "cross-page consistency", and flagging "anywhere the same term means two things". I used that brief as my checklist.

**Acronym expansions.** I counted every occurrence of each canonical expansion and each known drift form on all nine pages. There are zero drift forms: no "Lifelong", no "Capability Token", no "Attention Token", no "Trust-Tracing", no "R5". The only match for "lifecycle" is 4-Life's "lifecycle vocabulary", which is correct usage. "Unification", "scope inflation" and "production" appear only in negations ("not unification…", "R&D, not production"). SAGE is expanded identically ("Situation-Aware Governance Engine") on all nine pages. In the glossary table, the Expansion column is canon-exact for LCT, T3, V3, MRH, ATP, ADP, R6 (with the → Result arrow) and R7 (= R6 + Reputation). T3 and V3 list their three dimensions as contents, not as the expansion, and the rows say so explicitly.

**First-use discipline.** /projects claims "the cards expand each on first use". I tested this: LCT, T3, V3, MRH, MCP, RDF, SNARC, R6 and R7 are each expanded within 5 words of first use. The exceptions are ATP and ADP inside the Web4 card, which are first used about 55 words before the card expands them. The equation legend just above does expand them, so this is minor. /raising's vocabulary note now correctly describes itself (the 09-23 false claim is gone). /fleet's "Vocabulary used in the cards" note expands SAGE about 220 words after its first use on the page.

The glossary itself has an ordering problem. The **Trust-native** row (4th of 58) uses T3, V3, LCT and MRH, while their own rows are 11–13 rows further down: the T3 row is about 1,480 words after T3's first use on the page. The rows follow no alphabetical or dependency order, so a reader of a definitions table meets terms before they are defined.

**Headings and anchors.** /context and /fleet both jump from h1 straight to h3 with no h2. /context has 26 h3 sections, of which only 4 carry ids (#glossary, #equation, #threat-model, #evidence), so no other section can be linked. /fleet's machine cards have no ids at all. It also puts the pool headings ("Synthesis pool — Account 1") at the same h3 level as the machines they contain, so the outline is flat where the content is nested. /principles is now fully anchored (#p1–#p10). I found no broken internal link or anchor across roughly 420 links.

**Link text.** 57 internal links across the site use a bare path as their visible text ("/context", "/fleet"): 14 each on /context and /raising, and 12 on /fleet. That makes the Glossary naming split worse. The nav says **Glossary**, the `<title>` says "Glossary", the URL and inline link text say **/context**, and Home's card calls it **Vocabulary**. The page is also more than a glossary: after the 58-row table come 25 h3 essays (the CLAUDE.md pattern, cross-session memory, threat model, "What doesn't flow well (yet)"). Those were the old "Context" page, now filed under a name that doesn't cover them.

**Metadata.** All nine pages share one identical meta description (the Home one: "8 machines … 40 original repos … autonomous AI agents that … validate their own work"). Every page shares that one search-result description, and "validate their own work" sits badly with /autonomy's statement that review "is not yet independent". Home's "Start here → Calibration" card links off-site to `web4/STATUS.md` on GitHub (live, updated 2026-09-09) with no external-link cue, unlike the other two cards.

**Same term, several meanings (the part of my brief the site asked for).**

1. **"Substrate".** The glossary row is admirably candid: "A word this site uses in four senses" (conditions for emergence; the RDF graph; the physical machine; Synchronism's substrate rule). But the rendered pages use at least **three more**:
   - (5) the society-host's ledger/witnessing role: /fleet "HUB is substrate, not cognition", /autonomy "runs substrate as its primary role", and the glossary's own Society-host row "the society substrate". This is close to /context's "ledger machinery … as a witnessing substrate" for ACT.
   - (6) software agent platforms: the /projects Oversight Plugins card, "OpenClaw … Claude Flow … Claude Code … Same principles, different substrates."
   - (7) neural tissue: /context "the dorsolateral prefrontal cortex (dlPFC), the biological working-memory substrate".

   The glossary also says "Deliberately NOT used here: the machine-learning sense … for frozen model weights". That holds, but the four-sense list is presented as complete, and it isn't. /fleet uses sense (1), "the substrate conditions (experience buffer, session history…)", and sense (3), "behavioral continuity across substrates", in neighbouring paragraphs on one topic.

2. **"Oversight".** /context: "on this site 'oversight' **always** means the machine-enforced sense above … never the human-supervision sense". /fleet's pool heading "Oversight pool — Account 2" then says: "It is a budget-account name, not the machine-enforced sense this site reserves for Hardbound, and not human supervision." /fleet is honest about it, but /context's "always" is false on the site's own evidence. There are three senses (machine-enforced, human supervision as disowned, and a budget-account label), and the glossary has no "Oversight" row to hold them. The word-choice disclaimers also persist: "oversight" occurs 55 times across 7 pages and "governance" 45 times across 9.

3. **"/" = "verified by", applied to T3/V3.** This is the one that matters most. /fleet's vocabulary note and /links' Web4 entry gloss the pair as "T3 (Trust Tensor…) **verified by** V3 (Value Tensor…)" with no qualifier. /projects and /context use the same gloss and add "it is not a claim that T3 and V3 verify each other". Meanwhile /context's own T3/V3 section, quoting canon, says the relation is "complementary, not combined: neither tensor is computed from, **checked against**, or gated by the other". "T3 verified by V3" *is* a claim that V3 checks T3. The hedge only denies the symmetric (mutual) reading, which nobody asserted, so the one-directional contradiction stands. By the site's own admission, the legend is "the site's own gloss, not canon's". The glossary's canon-quoting V3 row contradicts it. And two pages (/fleet, /links) reproduce it without the hedge.

4. **Capitalization as meaning.** Glossary rows `hestia`/`Hestia` and `HUB`/`Hub` use the Expansion column for case notes ("lowercase — the Hestia daemon's trust component"), which are not expansions. Case-only distinctions fail in speech, in URLs, and at the start of sentences, and the daemon's own repo is `dp-web4/hestia`. **CBP** is all-caps like HUB, but it gets no "proper name, not an acronym" note anywhere on the site (20 uses on /fleet, 8 on /raising, 6 on /context).

**Numbers agree across pages.** 94.85%, 23 of 25 environments (92.0%), 175 of 183 levels, 40/21/33 repos, 8 machines and "31+ tracks" are consistent wherever they appear. The retired "24/25, 96.0%" survives only inside its own correction note on /context.

**Dated correction notes.** 25 "Until 20XX-XX-XX" notes appear in the reading text (/fleet 8, /raising 8, /context 6, one each on /projects, /arc-agi-3 and /principles). Pass 1 covered the reader cost, and I agree with it.

1. **Direction was not fixed in advance.** The page says the disclaimer rate climbing from ~3% to ~50% "look[s] like strong development".
