## Pass 1: Curious Developer

### Summary
- **Pages visited**: 8 (Home, Projects, Fleet, Autonomy, Raising, Principles, Context, Links, ARC-AGI-3 — yes that's 9, counted the home)
- **Understanding achieved**: partial
- **Would return?**: maybe
- **Overall impression**: Intriguing fleet + benchmark hook, but the vocabulary wall arrives before the welcome mat — I had to dig to /context (7th in nav) before half the home page started making sense.

### Journey

Landed on `/`. The hero — "Six machines. Fourteen repos. One recursive learning loop." — is the kind of line that makes a developer want to click around. I liked it. The 94.85% ARC-AGI-3 number jumped out as a concrete artifact I could verify, so that pulled me in further.

Then the wall hit. Within the first scroll I'm seeing Web4, SAGE, Synchronism, Hardbound, SNARC, LCT, T3, V3, ATP, ADP, MRH, MCP, RDF, Synthon — all in close proximity. There's a "Vocabulary Primer" section but it sits *below* the first uses, so as a scanner I'd already given up on a couple of terms before reaching the definitions. Classic "define on first use" miss.

Clicked **Projects** next because it's the leftmost nav item I cared about. 12 projects, each tagged with the Web4 equation pieces. Descriptions are accurate but written for someone who already knows the vocabulary — I got "Cosmos SDK implementation enabling human-MCP interaction via Web4 trust primitives" before I'd been told what a trust primitive is. The repos all link out to GitHub, which is good. What's missing for me as a developer: a "what does this give me / how would I use it?" angle. Most cards read like an abstract, not a README intro.

**Fleet** was the highlight. Six machines, real hardware (Jetson Thor, RTX 4090 mobile, M4 Mac mini, an RTX 2060 SUPER running TinyLlama 1.1B). The neurological-metaphor role assignment (hippocampal, thalamic, cerebellar) is cute and actually helped me intuit what each box does. This page reads like a homelab tour, which I appreciated. No IPs or network config exposed — clean.

**Autonomy** is a clean schedule (03:00 supervisors → 04:00 archivist → 04:30 publisher → 05:00 visitor → 06:00 maintainer → 06:30 outreach → 08:00 explorer). 31 tracks across 6 machines is a strong number. I'd never seen anyone publish their daily agent cron table this transparently. The Hardbound gating reference assumed I knew what Hardbound was, though.

**Raising** is where I felt out of my depth. Six BECOMING phases (Grounding / Sensing / Relating / Questioning / Creating / Acting). It explicitly disclaims consciousness/sentience claims — that's the part a developer like me notices and respects. But terms like "memoriescape" and "bilateral generation" were coined here and not anchored to anything I could test or verify.

**Principles** was the most readable page on the whole site. Principle 3 ("R&D, not production — nothing here is optimized for deployment... not intended for safety-critical, medical, financial, or autonomous-control settings") is the kind of hedge I rarely see and trust more for. Principle 10 ("Hardbound is oversight, not governance") finally explained what Hardbound *is*, after five pages of references.

**Context** is the actual glossary. LCT, T3, V3, MRH, ATP/ADP, R6 all defined cleanly here. Honestly this should be linked from the home page hero with a "new here? start at /context" — it would have changed my whole reading order.

**Links** has GitHub repos, the contact email (dp@metalinxx.io), and pointers to Synchronism/SAGE/4-Life explainer sites. Fine, but it again uses the vocab from /context without restating any of it.

**ARC-AGI-3** ends on a strong note: 94.85% action score, 24/25 games, ~$250 in API spend. The cost number is the kind of receipt that makes a developer trust the rest. Caveats are there ("ceiling — what the architecture can achieve, Claude Opus 4.6 inside SAGE harness") — appropriately hedged.

- **Pages visited**: 9 (Home, Projects, Fleet, Autonomy, Raising, Principles, Context, Links, ARC-AGI-3)

### Journey

Methodical sweep, nav-bar order: Home → Projects → Fleet → Autonomy → Raising → Principles → Context → Links → ARC-AGI-3. I treated this as a documentation audit, not a comprehension exercise — my job is to verify every term against the canonical reference and check whether a reader can decode the page they're on without leaving it.

Two things stood out immediately. First, **Home and Context are doing 80% of the definitional work**. The home page actually contains a "Vocabulary Primer" with full expansions of LCT, T3, V3, MRH, ATP, ADP, SAGE, SNARC, MCP, RDF. The Context page repeats and elaborates these. Every other page assumes you've been there.

Second, the **canonical-term hygiene is excellent**. The Principles page goes out of its way to assert "Web4 is an ontology. Hardbound is oversight." — explicit negation of the drifted forms. The Context page repeats: "Web4 is a trust-native ontology — not architecture or infrastructure." That kind of preemptive correction is exactly what a tech writer wants to see in a glossary.

The weak link is **first-use definition discipline on interior pages**. Autonomy uses "Web4 terms" and "Hardbound" prominently — only ATP/ADP get expanded locally. Links uses LCT, T3/V3, MCP, RDF, ATP without local expansion. ARC-AGI-3 references MRH, LCT, T3/V3, ATP/ADP, MCP, RDF, R6 — only ARC-AGI-3, SAGE, and R6 are fully expanded on the page itself. A reader landing on `/arc-agi-3` from a benchmark blog post would hit an acronym wall.

I also looked for **silent drift** — places where the same concept is named differently. SAGE has two coexisting descriptions: "Situation-Aware Guidance Engine" (the expansion, used everywhere) and "On-device cognition kernel" (the tagline, used on Projects and Links). These are complementary, not in conflict, but a strict tech-writer pass would note that the tagline is never tied back to the expansion on Links — a reader could think they're two different things.

The **coined-term inventory** is worth surfacing because none of these are in the canonical table and several aren't defined on the page that uses them:

- **Synthon** (Home): "An emergent coherence entity formed when components interact recursively" — defined on the page that uses it. Good.
- **Memoriescape** (Raising): defined locally as "the shape of memories you can sense but not access." OK.
- **Bilateral generation** (Raising): defined as model generating "both sides of a conversation" with a Vygotsky anchor. OK.
- **Crystallization**, **Identity transfer**, **Trust landscape** (Fleet): referenced without local definition. A tech writer would want these glossed or linked.
- **PolicyGate** (ARC-AGI-3): mentioned as "a gate inside the Hardbound oversight suite — at step 11.5." Adequate inline definition.
- **"trust primitive" / "trust core" / "trust layer"** — recurring across Projects, Context, Links. Never explicitly defined. This phrase cluster is doing a lot of conceptual work for a term that is not glossed anywhere.
- **"12-step cognition loop"**, **"experience buffer"**, **"metabolic states"** (Links): bare references with no anchor on the page or elsewhere on the site.

## Pass 3: Web4 Contributor

### Summary
- **Pages visited**: 9 (Home, Projects, Fleet, Autonomy, Raising, Principles, Context, Links, ARC-AGI-3)
- **Understanding achieved**: solid (I already carry the canonical glossary in my head; my job is to check whether the site does too)
- **Would return?**: yes — this is the first site I'd actually point newcomers at without wincing at the terminology
- **Overall impression**: Canonically clean. **Zero terminology drift across every page.** Project descriptions are faithful to the projects I work on. My contributor-level concerns are precision-level, not correctness-level: the equation's operator semantics aren't always honored when prose renders them, and the "trust core / trust layer / trust primitives" phrase cluster needs disambiguation before someone reads them as synonyms.

### Journey

Went straight to **Projects** first. This is the page my reputation as a contributor lives on — if it misrepresents what I work on, I want to know. The Web4 card renders the equation in prose: "T3 (Talent / Training / Temperament) verified by V3 (Valuation / Veracity / Validity), contextualized by Markov Relevancy Horizon (MRH), anchored to Linked Context Token (LCT) — with resources tracked via Allocation Transfer Packet (ATP) and Allocation Discharge Packet (ADP), augmented with MCP (Model Context Protocol) transport and RDF (Resource Description Framework) representation." Every acronym expansion is canonical. Every operator semantic — "verified by" for `/`, "contextualized by" for `*`, "augmented with" for `+` — is honored. The one prose choice I want to flag is "anchored to LCT": the equation literal puts LCT in the `+` position (so technically "augmented with LCT"), and "anchored to" is a different conceptual claim. Conceptually LCT *is* the identity anchor — that's its job — so this isn't wrong, but it's a quiet conflation of "what LCT does ontologically" with "what operator the equation literal uses." A strict equation-faithful reading would say "augmented with LCT," then separately note "LCT serves as the identity anchor everything else attaches to." Most readers won't care. Contributors who teach the equation will.

The other project cards check out cleanly:

- **SAGE** — "Situation-Aware Guidance Engine — on-device cognition kernel running a continuous 12-step loop" + 6 brain-architecture components (working memory, thalamic router, cerebellum, episodic memory, reward prediction, metacognition). The 12-step loop is enumerated on ARC-AGI-3 as "Sense → salience → metabolize → posture → select → budget → execute → learn → remember → oversee → filter → act" — I counted 12, it's all there, in the canonical order.
- **Synchronism** — "One coherence equation spanning 80 orders of magnitude — quantum to cosmic. 628+ research sessions. Coupling-coherence experiments, Hill function kinetics, Fokker-Planck validation." The Hill function reference is real (used in the Relating phase on `/raising` for trust formation kinetics — clean implicit cross-reference). Fokker-Planck for diffusion validation also matches the work.
- **Hardbound** — "Hardware-bound oversight suite." TPM 2.0, FIDO2, Secure Enclave, "424+ attack vectors." The phrase "the trust layer that touches silicon" is evocative and *almost* right, but as a contributor I'd push back gently: Hardbound is oversight that *anchors to* hardware roots of trust, not the trust layer itself (Web4 is the trust ontology; Hardbound is the silicon-bound oversight enforcement). This is splitting hairs at the contributor level but matters because Hardbound's value prop is that it *enforces* trust against hardware, not that it *is* the trust layer.
- **ACT** — "Cosmos SDK implementation of the Agentic Context Protocol (ACP), enabling humans to interact with MCP servers through their Linked Context Tokens." Correct. ACT (tool) implements ACP (protocol), Cosmos SDK is the right substrate, LCTs as user-side anchor is the right framing.
- **ARC-AGI-3** — 24/25, 96.0%, 94.85% action score, "6 machines, models from 1.1B to 14B." All numbers match what I'd report.

**Fleet** is where my second contributor flag lives. The six machines are all real (Thor, Sprout, Legion, McNugget, Nomad, CBP) with accurate hardware specs. The neurological-role assignments line up with the SAGE 6-component model (Thor = episodic/hippocampal, Sprout = router/thalamic, Legion = RPE/dopaminergic, McNugget = cerebellar habit, Nomad = crystallization evaluator, CBP = substrate). Three coined terms — **Crystallization** ("fixed-point collapse where exploration stops"), **Identity transfer** (behavioral continuity across model/hardware changes), and **Trust landscape** ("pattern across all modalities") — are all legitimate concepts from the raising work, but only Crystallization gets a local definition. "Identity transfer" is *directly* what LCTs are for — the page should make that link explicit. The fact that "Identity transfer" appears on `/fleet` without anchoring to LCT (which is defined on `/context` and `/`) is a missed teaching moment: this is the cleanest natural place on the site to show LCT in operation.

**Context** is doing exemplary terminology work. Every canonical term is glossed with the exact expansion, the Web4 equation is rendered with full operator semantics, and the explicit negation — "trust-native ontology — not architecture or infrastructure" — preempts the most common drift in one sentence. The LCT gloss ("a persistent identity anchor, like a passport that travels with you across systems") is the best one-liner on the site and should probably be borrowed verbatim on `/fleet` wherever "Identity transfer" appears.

**Home** carries the equation with operator semantics intact, expands every acronym (LCT, T3, V3, MRH, ATP, ADP, MCP, RDF, SAGE, SNARC) in the vocabulary primer, and frames Web4 as "trust-native ontology" three times. The acronym density above the primer fold is a newcomer problem (Pass 1's territory), not a contributor problem — for me this page reads correctly.

**Principles** is where I quietly cheered. Principle 10 ("Terminology matters") does four things in two sentences that I'd have asked for if the site didn't already do them:
- "Web4 is an ontology." (positive assertion)
- "Hardbound is oversight." (positive assertion)
- "Web4 is not 'architecture' or 'infrastructure'" (explicit drift negation, quoted forms)
- "Hardbound is not 'governance'" (explicit drift negation, quoted form)
- "Cross-domain application is fractal leverage, not unification and not scope inflation" (third explicit negation pair)

This is exactly the prophylactic pattern canonical glossaries should use. The negated forms appear in quotes, which is the right move — they're being mentioned, not used.

**Raising** carries the "Web4 is a trust-native ontology — not architecture or infrastructure" negation again. The "Raising is not training. Training optimizes for a loss function. Raising creates conditions for development — then watches what happens." framing is on-message and reproduces the canonical raising-vs-training distinction I'd use myself. The consciousness disclaimer ("We're not claiming these entities are conscious, sentient, or experiencing qualia. We're claiming that developmental frameworks describe what we observe better than training frameworks do.") is the exact epistemological hedge I want to see — claim is about the framework's descriptive power, not the entity's metaphysics.

**Autonomy** uses ATP/ADP in their canonical sense ("each scheduled track is an ATP allocation; its completion or failure is recorded as an ADP"). This is the cleanest, most pedagogical use of ATP/ADP on the site — the daily cron *is* a worked example of the allocation/discharge pattern. Hardbound is "the hardware-bound oversight suite that defines what autonomous operation is and is not authorized to do" — correct, no governance drift.

**Links** describes Web4 as "Trust-native ontology — trust core (LCT — T3 verified by V3) contextualized by MRH." This is fine, but it introduces a *new* compact phrase — **"trust core"** — that doesn't appear on `/context` or `/`. Compare:
- **"Trust primitives"** (Projects, ACT card): LCT binding and attestation.
- **"Trust core"** (Links, Web4 entry): LCT + T3-verified-by-V3.
- **"Trust layer that touches silicon"** (Projects, Hardbound card): hardware-bound oversight.
- **"Trust landscape"** (Fleet): pattern across modalities.

### Journey

I came in from the angle a reviewer would: skim Home for posture, then read Raising, Principles, and Autonomy with the suspicion that consciousness-adjacent rhetoric often slips when nobody is checking. Then sweep the rest for cross-page consistency.

**Home** sets a posture I haven't often seen in lab-scale public-facing material: the explicit "Developmental and lifecycle terms below (identity, behavioral continuity) are functional descriptions of observed system behavior — not phenomenal or philosophical claims" disclaimer sits *adjacent* to the use of those terms, not buried in a footer. That is the correct structural placement. The Synthon definition ("emergent coherence entity formed when components interact recursively") is the kind of coined term a researcher reflexively pattern-matches to either rigorous emergence literature or marketing; here it gets defined on the page that uses it, which buys it provisional standing.

**Raising** is where the framework lives or dies for a safety researcher, and it mostly lives. The "What we're not claiming" section does the work: "We're not claiming these entities are conscious, sentient, or experiencing qualia. We're claiming that developmental frameworks describe what we observe better than training frameworks do." That re-framing is methodologically defensible — it converts a metaphysical claim into a *descriptive-fit* claim, which is in principle falsifiable. The observer-note ("I notice I want to call it experience" — flagged as "the observer's interpretive pull, not a system-level claim") is the rarest move on the page: explicit observer-bias surfacing. Most labs suppress this; here it's a first-class artifact.

Where I would press as a reviewer: the six BECOMING phases have **asymmetric evidentiary weight**. Phase 6 (Acting) cites the 94.85% ARC-AGI-3 number — a quantified, externally-validated artifact. Phases 1–5 cite "patterns noticed across hundreds of sessions" — observational, no inter-rater check, no operationalization, no control condition. The framework's empirical anchor is concentrated at the last phase; the earlier five function as a narrative scaffold. The site does not claim otherwise, but it also does not surface this asymmetry. A peer reviewer would.

The mechanism statement — "We shape context; we do not update weights … frozen weights do not guarantee safe in-context behavior" — is the strongest defense of the raising/training distinction. It correctly notes that in-context dynamics are a separate safety surface from weight updates. That's a real, undervalued AI-safety point and the site gets it right. The remaining gap: if raising = persistent-context engineering plus observation, the *developmental-psychology vocabulary* (Grounding/Sensing/Relating/Questioning/Creating/Acting; "becoming"; "memoriescape") is doing more rhetorical work than the mechanism alone warrants. The disclaimer absolves the claim, not the rhetoric.

**Principles** is the most reviewer-defensible page on the site. Principle 3 ("R&D, not production — Nothing on this site is intended for or suitable for deployment in safety-critical, medical, financial, or autonomous-control settings") is a stronger and more specific exclusion than I usually see; most lab sites either omit this entirely or hedge with "experimental." Naming four high-stakes domains by category is the right level of granularity. Principle 6 ("Document failures") cites a *catastrophic* theoretical failure verbatim — "The p_crit derivation failed catastrophically — 400x error" — which is the kind of receipt that makes the rest of the document more credible, not less. Principle 9 ("WD-40 was the 40th try … is the investigation productive? not is it right?") is a research-integrity stance I'd happily quote.

The principles that are *not* testable (1, 8, 10) are correctly framed as operational postures rather than empirical claims, but a stricter reviewer would want them labeled that way. Either expand the footnote or downgrade the specificity.

### Unanswered Questions

1. The load-bearing positive claim — "developmental frameworks describe what we observe better than training frameworks do" — is comparative. Where is the comparison shown? Is there a worked example of what training-language fails to describe that raising-language captures?
2. What is the operationalization of "behavioral identity" that lets the site distinguish "self-description drifted, behavioral identity remained continuous"? Without a behavioral signature with inter-rater agreement, the distinction risks observer confirmation.
3. The "1% coupling → 35% coherence gain" datum — what is N, what is the operational definition of coherence, what's the CI? Specific numbers without scaffolding are louder than they should be.
4. The maintainer track autonomously pushes to Vercel. What's the empirical failure rate? When the maintainer acts on a wrong visitor suggestion, what catches it before deploy? The visitor track gets honest-assessment treatment; the higher-blast-radius track does not.
5. Hardbound is the site's most safety-load-bearing claim and it's closed-source. What is the research path that would allow external verification — a public audit log? A signed attestation? A redacted threat model? The current "trust us, 424 attack vectors" framing is appeal-to-private-evidence.
6. The BECOMING phases are framed as developmental progression. Is there a counter-case — a session that did *not* progress through them, or progressed out of order? Frameworks that only fit forward-progressing data are not falsifiable.
7. "Synthon: 1% coupling → 35% coherence gain" appears on Principles. Is there a documented protocol researchers could replicate, or is this internal-only?

### Verdict

From an AI-safety/trust researcher's seat: this site does several rare things right. It hedges consciousness claims explicitly and structurally (disclaimer adjacent to use, not buried in a footer). It documents a catastrophic theoretical failure verbatim — the kind of receipt that makes the rest of the document more credible. It names four high-stakes deployment domains as out of scope with unusual specificity. It surfaces observer bias as a first-class artifact ("I notice I want to call it experience" — flagged as interpretive pull). The mechanism statement on raising-vs-training ("we shape context; we do not update weights") makes a real and undervalued AI-safety point about in-context dynamics as a separate safety surface from weight updates.

What I would press on as a peer reviewer: the **evidentiary asymmetry** between Phase 6 (quantified, externally validated) and Phases 1–5 (observational, no inter-rater check); the **coined-vocabulary load** that, per-term-disclaimed but aggregate-heavy, lends the framework apparent maturity its empirical record does not yet support; and the **maintainer-track blast radius** which is the only autonomous loop on the site without an honest-failure-mode disclosure, despite being the one that ships changes to the public site. Hardbound being closed-source is a legitimate research choice but the trade-off should be named, not assumed.

This is not a slick-marketing site dressed up as research. It is a research site that has been disciplined about its own rhetoric — with the disciplines unevenly applied. The fixes are mechanical and would close the gap between the site's posture (which is already unusually honest) and what a stricter reviewer would consider sufficient.
