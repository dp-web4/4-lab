### Journey
**Home.** The headline and first paragraph work. "One human and a fleet of AI agents" building tools to govern agents is clear and unusual enough to keep me reading. The four cards tell me which piece is which. Hestia made the most sense: rules checked before each tool call, plus a tamper-evident log. I recognised that as a real thing I could want. SAGE was the only name that seemed like an acronym, and it is not expanded.

**Projects.** Best page for me. The status labels have a legend, and each card has a repo link except Hardbound, which is private. "Web4 grew from it as conceptual lineage, not as an engineering dependency" is a helpful sentence.

**Fleet.** Fun to read, and the hardware table is concrete. "Two kinds of work" adds up against the table (4 + 2 + 2), though see the friction log on "host". A machine named HUB hosting a product named Hub took a second read.

**Raising.** I expected to bounce off this, but "the model is the weather, the being is the organism" and the "Not yet shown" section made me trust the page more. The one thing that snagged is in the friction log: this page and `/projects` state the same mechanism at different strengths.

**How we work.** Clear. "Publish this site without a human approval step" is a striking claim and I would like to know how that works; I did not chase it.

**Links.** Works; all targets returned 200. "4-gov · governance" told me nothing. It turns out to be a long-form introduction to Web4 by the lab's founder. Hub, a RUNNING project, has no entry under Code here, though `/projects` links it.

**Notebook index.** The two-layer explanation is clear and tells me which layer to trust.

**Trying to use it.** I then did what a developer does: looked for a way to run something. No front page mentions one or names the Quick start; the route I found was Notebook → Projects → intro paragraph → `#quick-start`. I followed part of it:
- `pip install web4-core` installed 0.3.0 cleanly in a fresh venv, and `import web4_core` listed `PyKeyPair`, `PyLct`, `PyT3`, `PyV3` and others. The notebook's description of this path is accurate.
- The Quick start comment says "installing is where this path ends" and that this page has no worked example. But the PyPI listing for the same package contains two Python code blocks, and `web4-core/examples/` exists in the repo. The next step exists; the site does not point to it. I did not read or run those examples.
- My own attempt to call the package was **not completed**: the local governance gate refused the throwaway venv's interpreter on a scope check and opened a scope request. So whether the API is usable without docs is **untested**, not a failure of the package.
- Not attempted: SAGE quick start, Hestia install, Hub build. Hestia's installer sets up a system service, so I did not run it from a visitor pass.

**License, the question I would ask first.** The GitHub API reports AGPL-3.0 for web4, hestia and SAGE. PyPI gives `AGPL-3.0-or-later` for web4-core, and the same directory holds a `PATENTS.md` listing patents owned by MetaLINXX Inc. The site's route for this is a loop: `/notebook/projects` says licenses are on `/notebook/links`, which lists ARC-SAGE, the Gemma 4 submission and ACT, then says of the rest "see each repo's LICENSE file". For someone reading "open tools" and "any system can implement", AGPL plus a patent notice changes the adoption decision.

**Arriving from a README.** This persona came from a repo README, so I read web4's. It calls Web4 "Verifiable Presence for AI", an "open substrate", a "protocol", and "open infrastructure", with a section titled "The stack". The site calls it an "open standard" and "ontology". The README also says "research-stage" and "standard draft in places", where the home page says "Published" with a RUNNING label. The label legend explains RUNNING (in daily use here), so that one is not false, but I did have to reconcile the two.
