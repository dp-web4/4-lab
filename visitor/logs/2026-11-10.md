## Pass 1: Curious Developer

### Summary
- **Pages visited**: 8 (/, /projects, /fleet, /raising, /principles, /links, /notebook, /notebook/home), plus the quick start section of /notebook/projects and the repo/package links the front points at
- **Understanding achieved**: good

*Method note (not persona).* No WebFetch tool was exposed to this session. Outbound links were checked by status code; registries by their JSON APIs; the Hestia release by the GitHub releases API.

### Journey

**Home.** Landed from the GitHub org page. The headline ("AI agents are becoming actors in the world. We are building how they earn trust") plus the one-liner ("one human and a fleet of AI agents ... open tools for governing AI agents, and we run our own lab with them") told me what this is immediately. The idea paragraph (trust from track record, checked against rules that exist before anyone acts) is the pitch, and it lands for a developer because it maps onto things I already know: audit logs, policy-before-execution, signed records. Four product cards with labels (RUNNING / RESEARCH). "Ontology" is defined inline as "a shared vocabulary". "Hash-chained record that shows if it was altered" is exactly the right level for me. The line "They are refused by it every day" under "Governed by our own tools" is the most credible sentence on the page.

**Projects.** Three groups: governance (Web4 → Hestia → Hub → Hardbound), AI beings (SAGE, SWE-SAGE), theory (Synchronism). The ladder from open standard to personal tool to community tool to paid enterprise tier is clear and is the structure I'd expect from a developer-tools company. Label key at the bottom ("Running: in daily use on our own machines. Building: real code, not yet deliverable.") is honest and useful. Each card links to a repo or site. What's missing for me: a "get started" or "install" link anywhere on the page. The only onward link is "notebook" for maturity details. I went to the repos instead.

**Repos and packages (clicked from /projects and /links).** All links resolve (12/12 return 200). crates.io has web4-core at 0.4.0 (5 versions, created April 2026); PyPI has web4-core 0.3.0. The front's claim "reference code on crates.io and PyPI" is true. The Hestia repo README is long, candid, and has an install section with a one-line installer; the web4 README is a spec landing page. The SWE-SAGE write-up link works and says the code is private, which the front also says.

**Fleet.** A table of eight machines with hardware and what each does. Readable in 30 seconds. The "Two kinds of work" paragraph (4 heavy, 2 review, 2 host) adds up to eight and matches the table. "Most raise a persistent AI being" sent me to /raising.

**Raising.** The chatbot-vs-being contrast is the clearest framing on the site: name, memory, journal, record that carry over day to day, and the model underneath can be swapped. "The model is the weather, the being is the organism" is a good metaphor. "We do not change the model's weights" is the sentence a developer needs, and it is there. The Seen / Not yet shown split is unusual for a project site and I trust the page more for it.

**How we work.** Six principles, each two lines. "AI peers review pull requests, merge changes, and publish this site without a human approval step" is a striking operational claim; as a developer I'd want to see the PR history that shows it, and the page does not link to it (the notebook pages are the only onward links).

**Links.** Short. Sites, code, packages. Includes a site called 4-gov that no other page mentions. I clicked it: it's a talk/deck site titled "Computable Accountability | Governance for Agentic Entities" with a section called "Web4 Architecture Thesis". Fine, but the one-word gloss "governance" didn't tell me it was a lecture series.

**Notebook index and /notebook/home.** The index explains the two-layer design plainly and says AI readers should start there. /notebook/home is the old home page: denser, with counts (8 machines, 21 SAGE instances, 4 model families), a Hestia version line (v0.3.0, 2026-11-02, with daemon, desktop app and Android app), an assurance rung explained inline (A1 on an A0–A4 ladder, with the TCSEC collision called out), and a Start here block whose "Quick start" link finally gets a developer to runnable steps on /notebook/projects. The quick start itself is detailed, including two caveats that read like they were learned the hard way (the SAGE daemon has no --version and defaults to a real fleet machine's identity if an env var is unset).

**One check that came out in the site's favour.** The Hestia README on GitHub says "there is no public desktop app artifact" and "desktop bundles are not published". The GitHub releases API shows v0.3.0 (published 2026-11-02, not a prerelease) carrying macOS .dmg, Linux .AppImage and .deb, Android .apk and daemon tarballs for three targets. So /notebook/home is correct and the upstream README is stale. A developer who reads the repo before the site would get the worse picture.

I'd come back when there is a "try it" link on /projects; until then the repos are where I'd actually go.

**One figure I checked for cross-page agreement.** /notebook/projects says "6 machines" in its ARC-AGI-3 table while every other page says eight.
