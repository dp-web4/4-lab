### Journey
I went to /projects first, as a contributor would. The Hestia card is where the front and upstream part.
- **"No public installer yet"** (/projects) is false. `gh release list` shows v0.0.4 marked Latest since 2026-08-11, with prebuilt daemon tarballs for Linux x86_64/aarch64 and macOS arm64. v0.3.0-rc.3 (2026-10-15, pre-release) adds a .dmg, a .deb, an AppImage and an Android .apk. The notebook's Hestia card already transcribes the v0.0.4 install steps. So the front contradicts the notebook too.
- **"A record the agent cannot edit"** (Home) and **"recorded where the agent cannot change it"** (/projects) say more than Hestia claims for itself. README line 163: "all of the above is profile **A1**, a cooperative gate running as the same UID as the operator. Tamper-**evident**, not tamper-proof." It links a bypass catalogue "including two environment variables that suffice today". The notebook states A1 / tamper-evident correctly (/notebook/projects, /notebook/home, /notebook/context A0–A4 row). Only the front is unhedged, and the gap is a false fact, not a missing caveat. "Cannot edit" is a capability claim that upstream withdraws.

The Synchronism card on /projects says "It supplies the equations that Web4's trust model builds on". The web4 agent guide (`AGENTS.md` line 107) says "Blue-sky conceptual lineage; not an engineering dependency". /notebook/projects quotes that line and says "a lineage rather than a derivation". So the front claims the derivational relation the notebook explicitly denies.

On the equation, I compared the notebook legend with upstream. /notebook/context and /notebook/projects both say the legend (`/` = "verified by", `*` = "contextualized by", `+` = "augmented with") "is the site's own gloss, not canon's … the reading is ours to defend". The provenance note is dated 2026-09-09. The note searched only the README and CANONICAL_TERMS_v1, and it missed two upstream sources that both predate it:
- `whitepaper/sections/03-the-equation/index.md` is titled **"The Canonical Equation"** (last commit 2026-07-10). It has the operator table verbatim and reads "trust tensors that are *verified by* value tensors and *contextualized by* each entity's Markov Relevancy Horizon".
- `web4-standard/GLOSSARY.md` (2026-08-19) says "**Operators**: `/` = "verified by", `*` = "contextualized by", `+` = "augmented with"" and "Web4 is an **ontology**".

So the T3-verified-by-V3 reading is upstream's, from the whitepaper and the standard glossary, not the site's. The part the site did add is the "both sides" extension, "ATP verified by the ADP discharge record". Upstream's §3 reads ATP/ADP as "a value cycle" and doesn't apply "verified by" to it. The attribution is inverted: the site disowns the half upstream publishes and presents its own extension under the same disclaimer. The same blind spot appears in the ontology note on /notebook/context. It says the ontology framing is held in the agent guide and "obliquely" in canon's T3 entry, but the standard glossary and whitepaper say it outright. The tension that does exist is inside upstream: CANONICAL_TERMS_v1 has T3/V3 "Complementary, not combined", against the whitepaper's "verified by". That is an upstream conflict to log, not a site reading to own.
