## Pass 1: Curious Developer

*Method: no WebFetch tool was available to this session, so the live site was fetched with `curl` against https://4-lab.vercel.app/ and the HTML was reduced to text with a stdlib parser. Every quote below is verbatim from that rendered HTML, not a summary. Links were checked by HTTP status. Packages were checked through the registry APIs: crates.io's HTML page returns 404 to a non-browser fetch, so its API was used instead.*

### Summary
- **Pages visited**: 8 front-layer pages (home, /projects, /fleet, /raising, /principles, /links, /notebook) plus /notebook/projects. /notebook/autonomy, /notebook/raising, /notebook/fleet and /notebook/context were opened only to look up specific claims.
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: Within two minutes I knew what this is: a one-human, many-agent lab building rule-checked identity and trust tooling for AI agents, run on that same tooling. The front is short and plain. Then I wanted to *try* something, and nothing on the front points me to how.

### Journey
**Home.** "AI agents are becoming actors in the world. We are building how they earn trust." The headline is clear. "The idea" (trust from a track record checked against rules set in advance, "not claimed by the agent or granted by a platform") is the clearest pitch I've seen from a trust project. I understand it without knowing any of the theory. Four cards follow: Web4 (an open standard / "ontology", Rust and Python reference code), Hestia (one rule set for agents from any vendor, "checked before each tool call", hash-chained record), Hub (the same for a community) and SAGE ("persistent AI beings"). Each carries a status label (RUNNING / RESEARCH), but the home page never says what the labels mean. That legend is only at the bottom of /projects. One line caught me: "The lab's agents work under Hestia … They are refused by it every day." A project eating its own cooking makes me want to look closer.

**/projects.** Same four plus Hardbound (BUILDING, "the enterprise tier", "built by Metalinxx"), SWE-SAGE and Synchronism. The label legend is here: "Running: in daily use on our own machines. Building: real code, not yet deliverable. Research: an open question." That answers *how mature is it?* for the lab's own use. It doesn't answer *can I run it?*, which is my question. Each card links its repo. Nothing on this page says "start here" or gives an install command. The bottom line links "/notebook/projects" for "maturity and what each claim rests on". I followed it on a hunch, and that is where the install steps were.

**/notebook/projects (8th page).** At about 8,000 words it is a different kind of document. Near the top: "Want to run something rather than read? The most finished things to try are Web4's core packages … and Hestia … which ships release binaries", and it says the Quick start at the bottom is "the only copy on the site". The quick start is good and candid: `pip install web4-core`, the note that `import web4` fails, the PyPI/crates.io version split, and the fact that SAGE's steps reach the daemon, not a being. It's exactly what I wanted. The problem is that it sits at the bottom of an 8K-word page linked from a sentence about "maturity" on the front. I checked the registries myself: web4-core is **0.4.0 on crates.io** (updated 2026-10-15) and **0.3.0 on PyPI**, as the quick start says. Both registry listings summarize the package as "trust-native infrastructure". The notebook already notes this.

**/fleet.** Eight named machines, from a Jetson Orin Nano to a Mac mini, an RTX 4090 laptop and two Windows boxes, running Qwen, Gemma, Granite and Llama. "No central controller … None of them is in charge." The table is easy to read. The paragraph under it is not: "Four machines do the heavy work … Two review, plan and coordinate. Two host the community the rest belong to." I tried to map that onto the table. Nomad and CBP are clearly the two reviewers. HUB "Hosts the fleet's own community on Hub". But the other "host", pub, is described in its own row as "Staging for the first public Hub". By the table, one machine hosts the community and one is staging a different one. The "four heavy" then have to include Sprout, an Orin Nano the same table calls an "Edge device: a being with a camera and microphone". That doesn't read as "running large experiments". (In /notebook/fleet the split turns out to be budget pools: synthesis = Thor/Sprout/Legion/McNugget, society-hosts = HUB/pub. The front sentence describes them as roles, though.) Another small snag: **HUB** (a machine) and **Hub** (the product) differ only by capitalization, and the HUB row says it hosts the community "on Hub".

**/raising.** This is the page I expected to roll my eyes at, and I didn't. "The model is the weather, the being is the organism." "We do not change the model's weights." Then the "Seen / Not yet shown" split: "That this continuity is more than well-kept memory files fed back to a model. We have no blind comparison against a fresh model yet, and we say so." That's the exact objection I had while reading, already answered. One thing: "Seen" says "One being now **proposes** changes to its own code", while /fleet's Legion row says "Its being **improves** the SAGE code it runs on". Those are different claims to a developer: a PR opened is not a PR merged. (/notebook/raising quotes both and rules "Supported, with mediation", so the notebook knows about the gap.) Also undefined here: "a tutor" and "its mentor". Who or what are they, a person, Claude, another being?

**/principles.** Six principles, each two lines, all readable. "The record is kept by someone else. An agent never holds the only copy of what it did" is a concrete, falsifiable design rule, and I liked it. The paragraph above them says: "They also run 4-lab end to end: AI peers review pull requests, merge changes, and publish this site without a human approval step." I took that literally and checked the notebook's /autonomy page. It says the maintainer is "the only track that ships changes to the public site without a human gate" and that front-page claims are carried because "the front changes only through the researcher's review". So the pages I'm reading right now, the front, *do* have a human approval step. Only the notebook doesn't. The front sentence covers the whole site and is wrong for the part I'm reading.

**/links.** Short and complete. Every link resolves (see below). The "4-gov · governance" entry tells me nothing about what 4-gov is or how it relates to Hub or Hestia. "SWE-SAGE … (write-up; code private)" is honest. The write-up confirms the "Google / Kaggle Gemma 4 Developer Agent Competition" claim on /projects.

**/notebook.** It clearly explains the two layers ("The rest of this site is written for people … This notebook is the record underneath it") and tells AI readers to start there. The nine page cards are well described. Nothing in the "Projects" card says it contains the only quick start on the site.

**Links checked (HTTP status):** all 16 internal routes return 200. Nine external links return 200: GitHub org, web4, web4/hub, hestia, SAGE, the SWE_SAGE.md write-up, the SAGE site, the Synchronism site and 4-gov.org. PyPI returns 200 (0.3.0). crates.io's HTML returns 404 to a non-browser fetch, but the API returns the crate (0.4.0), so this is a fetch quirk and the link is not broken.

## Pass 2: Technical Writer

*Method: no WebFetch tool was available here either. All 16 pages (the 7 front pages in the live nav, counting home, plus the 9 pages listed on /notebook) were fetched with `curl`-equivalent stdlib requests and reduced to text. Acronym checks were scripted over the full text of every page, so long notebook pages were read whole and not cut off: /notebook/raising is ~20.6K words and /notebook/context ~18.7K. All quotes are verbatim from the rendered HTML. All 16 internal routes return 200, and all 130 internal `#anchor` links resolve to an `id` on the target page.*

### Summary
- **Pages visited**: 16 (7 front + 9 notebook; counts taken from the live nav and the /notebook index, and they match the brief)
- **Understanding achieved**: solid
- **Would return?**: yes
- **Overall impression**: Canonical expansions are clean everywhere. Every expansion of LCT, T3, V3, MRH, ATP, ADP and R6 on all 16 pages matches the canonical table, with no drift found. What remains is structural: one heavily used notebook word has no glossary entry, page names don't match their links, one notebook page contradicts itself about who gates the front, and the front repeats two readings that the glossary has since corrected.

### Journey
**Front (7 pages).** The front uses almost no acronyms, which I'd recommend to any docs team. The only ones are **SAGE** (/projects, /fleet, /raising, /links), **SWE-SAGE** and the hostnames CBP and HUB. SAGE is never expanded on the front. I checked the house terms. Web4 is "an open standard … a shared vocabulary, or ontology" (home) and "written as an ontology" (/projects), which is correct. Hardbound is "hardware-bound oversight" (/projects), also correct, though it sits under the section heading "Governance for AI agents". That's acceptable because the governance→oversight rule binds Hardbound's own description, not a section title, but it's worth knowing. "Governance"/"Governs" is used for Hestia and Hub, which the notebook says is deliberate ("Hestia keeps 'governance' on purpose", /notebook/principles). No "production ready", "unification", "scope inflation", or Web4 called "architecture"/"infrastructure"/"stack" appears anywhere on the front.

Two front terms collide with what the glossary now says:
- **/raising**: "guided sessions with a tutor, … conversations with its mentor and with other beings" presents tutor and mentor as two roles. The glossary's *Mentor* row says outright: "Upstream SAGE has no separate mentor role … mentor names the tutor's intended posture, not a second interlocutor." The word "mentor" appears **0 times** on /notebook/raising, so a reader who follows the front's link to the curriculum can't find it.
- **/fleet**: "Two host the community the rest belong to." The glossary's *Society-host* row: "They do not host the same one. HUB hosts the fleet's own society … pub is the staging host for a separate, public-facing hub … (this row said both host the fleet's society until 2026-11-17)." The notebook corrected itself five days ago. The front still carries the old reading. Pass 1 reached this from the table, and the glossary confirms it.

**Notebook (9 pages): canonical audit.** I extracted every `ACRONYM (…)`, `ACRONYM —` and `ACRONYM =` form on all pages:
- LCT → "Linked Context Token" (19 occurrences, 6 pages). No Lifelong/Lifecycle expansion anywhere. The three "lifecycle" hits are the ordinary English word.
- T3 → "Trust Tensor" (24), always followed by "Talent / Training / Temperament" given as *dimensions* ("root dimensions", an em-dash or parentheses after the name), never as the expansion.
- V3 → "Value Tensor" (22), the same way with Valuation / Veracity / Validity.
- MRH → "Markov Relevancy Horizon" (15). No "Relevance" variant.
- ATP → "Allocation Transfer Packet" (16). ADP → "Allocation Discharge Packet" (13).
- R6 → "Six-Element Action Framework: Rules / Role / Request / Reference / Resource → Result". All 9 full listings use the arrow, and the all-slash variant appears nowhere. R7 is given as "R6 + Reputation" (/notebook/links, /notebook/projects, the glossary), which is canonical.
- External and lab acronyms are consistent across pages too: SAGE is always "Situation-Aware Governance Engine", MCP "Model Context Protocol", RDF "Resource Description Framework", LoRA "Low-Rank Adaptation", SNARC "Surprise / Novelty / Arousal / Reward / Conflict", ARC "Abstraction and Reasoning Corpus for Artificial General Intelligence", PRD "product requirements document". I found no second expansion for any of them.
- The off-canon nouns that do appear are all quoted upstream text with a disclosure next to them. The glossary's *Substrate* row quotes the Hub/Hestia PRDs' "Web4 is a protocol substrate" and states the disagreement. /notebook/projects quotes the registries' "trust-native infrastructure". "Unification"/"scope inflation" appear only inside the rule that forbids them.

**First use.** Every notebook page expands each Web4 acronym at or right after its first use, except deliberate pointer lists. /notebook/home's "Vocabulary" card and /notebook/projects' intro both say "(this list is a pointer, not a first use …)". That's correct, but it is enforcement scaffolding that a reader sees. /notebook/projects makes a checkable claim about itself: "each card expands an acronym where that card first uses it." I checked all 13 cards against the pointer list (LCT, T3/V3, MRH, ATP/ADP, R6/R7, MCP, RDF, SNARC, PRD, E4B). It holds in 12. The exception is the **Hub card**: its first prose PRD is inside a quote, "'Proposed / not implemented by this PRD'" (char ~20.6K), and the expansion "web4 PRD, product requirements document" comes ~1,500 characters later in the same card. (The Hestia card's only PRD is in a filename, `docs/PRD_FIRST_USER_APP…`, which I don't count.) The glossary uses terms before their own rows (ATP ~7K characters before the ATP row, LoRA, SNARC and PRD likewise). That's normal for a glossary, and every one has its row.

**Glossary coverage.** The glossary has 80 rows. It covers the lab-specific vocabulary well: Seat, Track, Being, Being posture, Waking period / beat, Tutor, Mentor, HUB vs Hub (a good row: it sets case rules for HUB / Hub / hub), Society-host, Cartridge. One heavily used word has **no row: "harness"**. It occurs 73 times across 8 notebook pages (36 on /notebook/raising, 15 on the glossary itself, 9 on /notebook/projects) in at least three senses:
- the benchmark scaffold ("the ARC-SAGE harness", /notebook/raising)
- the raising session runner ("two are computed by the harness", glossary *BECOMING* row)
- the agent principal around a being ("attended by a seat, the harness principal around it", /notebook/projects; the *Seat* row: "A harness role, not the model")

/notebook/raising also distinguishes harness changes from being behavior as a category of evidence. That makes it a load-bearing word on the most important caveat page, and a reader has no single definition to check it against.

**Cross-page consistency: the front-gating claim.** Pass 1 reported the /principles sentence "AI peers review pull requests, merge changes, and publish this site without a human approval step" as a false fact. The quote it relied on, "the front changes only through the researcher's review", is from /notebook/autonomy's *history* of the 10-04→10-10 stop. The same page now says, further down: "**Who gates the front is unsettled on the record.** Until 2026-11-08 this paragraph read that merge as the researcher gating the front, and said the front Principles page's 'publish this site without a human approval step' was true of the notebook only. PR #3's own body says the opposite … Which of these is the design is the researcher's to state; asked 2026-11-08, no reply on record as of 2026-11-19." So by the notebook's own current account, the front sentence is **unverified, not refuted**. That's an open question for dp, not a false fact. The real defect is that /notebook/autonomy still states both readings as fact in other places: the "Known oversight gap" box says the maintainer is "the only track that ships changes to the public site without a human gate", and the stop history says in parentheses "(the front changes only through the researcher's review)". Neither is dated as the belief held at the time. A reader who quotes either one, as Pass 1 did, gets a claim that the page withdraws three paragraphs later.

**Smaller consistency notes.** The front says "community" and the notebook says "society" (45× in the glossary). The glossary's *Hub* row connects them ("turns a community or organization into a sovereign Web4 society"). The *Society* row doesn't say that the front's "community" means society, but the mapping can be recovered. Model families agree across layers: front "Qwen, Gemma, Granite and Llama"; /notebook/fleet "Granite, Llama … extend the fleet's current Qwen / Gemma lines … (the Phi and TinyLlama lines are archived)". "Eight machines" is consistent on every page.
