## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 site pages (/, /projects, /context, /fleet, /autonomy, /raising, /principles, /links, /arc-agi-3) + 2 linked GitHub repos (SAGE, ARC-SAGE)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: I understood what the lab is doing within two minutes and the vocabulary is defined everywhere I looked — but the moment I followed a link out to the actual code, the site's numbers and the repo's numbers stopped matching.

### Journey

Landed on the home page from a repo README. The headline is "Eight machines. Forty original repos. One recursive learning loop." My first reaction as a dev: that's a stat line, not a pitch. It tells me how big this is, not what it does for me. The paragraph underneath fixes it fast though — "there is no general way to establish whether one [agent] will behave appropriately in a given context" is a problem I actually recognize from work, and "compute trust per relationship from witnessed interaction, by the party doing the relying" is a crisp one-line thesis. That's the two-minute win.

Then the equation: `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP`. Five unknowns in one line, which would normally be where I bounce. It didn't happen — every symbol is expanded inline on the same page, including MCP and RDF which I already knew. That's better acronym hygiene than most infra docs I read.

But I stopped on the notation key, which says the `/` glyph "means two different things on this line: 'verified by' in T3/V3, but a plain declared→discharged allocation pair in ATP/ADP — same glyph, unrelated semantics." I appreciate that they told me. I also think that if your defining formula needs a footnote saying one of its operators is overloaded, the formula has a bug. It reads like someone documented a known issue instead of closing it. Not a blocker, just the kind of thing I'd raise in review.

Went to /projects next because I want to run something. This page is the best on the site for my persona. Eleven cards, each with a repo link, and — critically — an explicit maturity vocabulary: "**runnable** = clone it and it executes end to end today (a demo, a script, a server) — not a claim about polish or completeness" vs "**research-stage** = design docs, specs, and experiments; may not run end to end without additional setup." That's exactly the label I want and almost nobody provides it. Four things are marked runnable: SAGE, 4-Life, SNARC, Membot.

/context is the glossary and it's dense but genuinely good. It links out to the actual source of truth (`CANONICAL_TERMS_v1.md` in the public web4 repo), which I clicked and which resolves. A site that cites its own canon and links it is doing better than most.

/fleet, /autonomy, /raising, /principles I read faster — this is the lab-culture half of the site and it's not what I came for, but /autonomy earned my attention by admitting that "the visitor and maintainer tracks are LLM sessions drawn from the same model families as the tracks that author the content they audit — their misses are correlated." I've never seen a project state its own review-loop blind spot in the copy. Same on /raising: "everything below might be competent context engineering and nothing more."

/arc-agi-3 is where I got interested, because it's the one page with an external number: 94.85% action score, 24/25 games, #3 on the human leaderboard. So I did what a developer does with a benchmark claim — I clicked the ARC-SAGE repo link.

The repo says **23 / 25 games won**. The site says **24/25 games solved (96.0% game-solve rate)**.

Then it got worse. The site describes ARC-AGI-3 as presenting "25 unknown interactive games with no instructions, no documentation, and obfuscated engine source" — that framing is doing all the work of establishing why the result is impressive. But the site's own methodology line reads "Source analysis → world model → solver → multi-agent frame-questioning." Source analysis of *what*, if the engine source is obfuscated? The README answers the question the site raises and never resolves: "the Phase-1 harness earned it *outside strict from-observation play* — it analyzed the games' (public) engine source and built per-game solver cartridges."

So the repo is more honest than the page. The site leads with an up-front caveat, but it's about a *different* thing — the unrun harness-vs-model ablation. The caveat I actually needed (the harness read the engine source and used per-game solvers) exists, is written down, and lives one click away in the artifact rather than on the page that makes the claim.

Last stop was the SAGE README, since the home page told me "clone SAGE — the recommended starting point" and /projects told me "SAGE runs on a single machine — no Jetson required." Both true-ish, both underspecified. The actual quick start is `python3 -m sage.instances.init`, then `cd sage-rs && cargo build --release`, then run a daemon with a dashboard at `localhost:8760`. That's a Python env, a Rust toolchain, and a local model (`gemma3:4b`) before I see anything. The README is ~7,000 words and Getting Started is well down the page. And "no Jetson required" tells me what I *don't* need without ever telling me what I *do* — there's a fleet table with 8GB-to-122GB machines and no minimum-spec line anywhere.

### Unanswered Questions

1. Is it 23 or 24 games? Until that's resolved I can't cite the ARC number at all, and it's the only hard external number on the site.
2. If the harness analyzed public engine source and built per-game solvers, what does the 94.85% measure — the cognition kernel, or the harness engineering around it? The site's unrun-ablation caveat gestures at this but the from-observation detail changes the question.
3. What does an R6 action look like on the wire? It's called the "shape of every auditable action" and I never see a shape.
4. What's the minimum machine that runs SAGE's default config?
5. Four repos are marked "runnable" — is SAGE the right first one for someone with no GPU, or would SNARC or Membot be a faster first win? The site recommends SAGE; SAGE has the heaviest setup of the four.
6. The trust thesis is "compute trust per relationship from witnessed interaction." Where's the code path that does that? I can find the vocabulary for it on every page and the implementation on none.

### Verdict

This site respects a developer's time: the acronyms are defined where they're used, the projects page tells me which repos actually execute today, and the caveats are unusually candid — /autonomy admits its own audit loop has correlated blind spots, which is not a thing sites say about themselves. I got the thesis in two minutes and I'd come back.

What I can't get past is that the one claim with an external scoreboard doesn't survive a single click. The site says 24/25, the repo says 23/25, and the repo carries a caveat about not being strict from-observation play that the site doesn't. That's the wrong direction for the honesty gradient — the artifact should be the boring corroboration of the page, not the place where the real story is. Fix those two numbers and hoist that caveat and this becomes a site I'd send to someone else.

Secondary, and easier: for a lab whose central artifact is a grammar for auditable actions, there is not one line of serialized data anywhere on the site. I'll read a JSON blob faster than I'll read the paragraph describing it.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 (/, /projects, /context, /fleet, /autonomy, /raising, /principles, /links, /arc-agi-3) + the site's own cited source of truth, `CANONICAL_TERMS_v1.md`
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: Expansion hygiene is the best I've audited on a site this jargon-dense — every acronym matches canon on every page — but the site renders R6 in a shape canon does not use, on four pages, and my own reference table carries the same error, which is why nobody has caught it.

### Journey

I audit terminology the boring way: read every page, tabulate every acronym expansion, diff across pages, then diff the whole set against the source of truth. Nine pages, no exceptions.

The cross-page diff came back cleaner than I expected. **LCT, T3, V3, MRH, ATP, ADP, MCP, RDF, SNARC, SAGE, ACT, ACP, LoRA, RPE, E4B, MIT-0, WASM — every expansion is character-identical everywhere it appears.** Nine pages and not one variant spelling. That is genuinely rare; most sites this size have at least one page where somebody typed the expansion from memory.

So I went looking at the level where drift actually hides: not the expansions, but the *shapes*. And /context does something most glossaries don't — it links its own source of truth, `CANONICAL_TERMS_v1.md`, in the public web4 repo. If you cite a canon and link it, you have invited the diff. I ran it.

**Sixteen of seventeen terms match canon exactly.** The seventeenth is R6.

Canon renders R6 as:

> `Rules / Role / Request / Reference / Resource → Result. The base action grammar.`

The site renders R6 as:

> `Rules / Role / Request / Reference / Resource / Result`

Six items, six slashes, no arrow. It appears that way on **/context, /projects, and /arc-agi-3**, and /projects and /arc-agi-3 both label it "Six-Element Action Framework."

That arrow is not decoration. Canon's notation separates *five inputs* from *one output* — Resource is the last thing you supply, Result is what the action produces. The site's flat slash-list makes all six look like coordinate members of one set, which is precisely the reading canon's arrow exists to prevent. And "Six-Element Action Framework" reinforces the flattening: it counts the elements and says nothing about their shape. The site simultaneously calls R6 "the base action grammar" (canon's own phrase) while stripping the only piece of notation in the entry that encodes grammar.

Here is the part that concerns me more than the finding. **My reference table in `visitor/CLAUDE.md` also lists R6 as a flat six-element list** — `Rules/Role/Request/Reference/Resource/Result` — with the drift column reading only "~~R7, R5~~". So an auditor working the way this track instructs — check the site against the table — will score R6 **CORRECT** every single time, forever. The audit instrument and the audited surface share the same defect. I only caught it because /context linked canon and I clicked through, which is a habit, not a procedure. Nothing in the track requires it.

Two other diffs against canon, both omissions rather than errors:

Canon's LCT entry carries a concrete serialization — `lct://{component}:{instance}:{role}@{network}` — and the phrase "accumulates witnessed history **and reputation** over time." The site's glossary entry is otherwise excellent (it states non-transferability and explains *why* it matters: "which is what makes the accumulated history evidence rather than assertion") but drops both the format string and "reputation." The format string is notable because it is the one piece of literal machine-readable syntax canon offers, and the site — which has no serialized data anywhere — declines to reuse it.

Canon also carries per-term **anti-definitions**: explicit `NOT:` lines naming the wrong expansions ("NOT: Lifecycle-Continuous Trust, Linear Context Tracker"). The site uses `NOT` constructions liberally — six of them in /context — but every one negates a *concept* (autonomy is NOT self-directed in the AI-safety sense; emergence is NOT the LLM-scaling sense; Web4 is NOT a platform). Not one negates a *wrong expansion*. So the exact failure mode the whole terminology program exists to prevent — someone reading "LCT" and writing "Lifelong Capability Token" — has no defense anywhere on the site, even though canon supplies the ammunition and the site links to it.

Citation practice is inconsistent in a way an auditor notices immediately. **/context** names `CANONICAL_TERMS_v1.md` and links it. **/fleet** names it — "not yet in CANONICAL_TERMS_v1," about the term "Sovereign" — and does not link it. **/links**, which is the page whose entire job is links, does not carry it at all. One citation, three treatments.

And the citation is unpinned. The document is `Version: 1.0.0, Last Updated: February 12, 2026` — six months old. The site cites it by filename only, and its own verification stamp reads "verified against the GitHub org 2026-07-26," which is a check of a different thing (the repo list) on a different date. Meanwhile /context's notation key out-specifies canon: canon contains **no notation key at all** for `/`, `*`, or `+`, so the site's careful explanation that `/` "means two things here" is the site's own contribution, not a restatement. A reader trying to work out which document governs cannot tell from either.

On the banned-word sweep: **"production ready" is zero site-wide.** "Architecture" appears only where it is correct — /principles uses it to *deny* the label ("Web4 is not 'architecture' or 'infrastructure' — it's an ontology"), and /projects uses "brain-architecture components" about SAGE's internals, a different referent entirely. "Governance" appears only inside the retained proper name *Situation-Aware Governance Engine*, and on every page where it appears there is a pointer to the governance→oversight note. That is textbook hub-and-pointer handling.

One residue. Home page, in the getting-started line: "or ACT (Agentic Context Tool) for **the Web4 trust-layer side**." The grammatical subject is ACT, not Web4, so this is not "Web4 is a layer" — but "the Web4 trust-layer side" attaches a stratum noun to Web4's territory in the one sentence a newcomer reads before they clone anything, on the page that elsewhere says Web4 is "a shared vocabulary." Principle 10's list is *architecture / infrastructure*; "layer" isn't on it, and that is how it keeps getting through.

I also checked the count that looked wrong and found it isn't. The headline says "Eight machines," the brain section says "Six machines, six brain components," /autonomy says "6 cognition machines." The home infographic reconciles it explicitly — "6 cognition + 2 society-hosts" — and /fleet lists all eight with the two hosts named. **Not a defect.** Recording it because it reads like one on a fast scan and I'd rather the next auditor not re-open it.

Acronym-on-first-use, per page: eight of nine pages define everything they use. **/autonomy is the exception** — HUB, CBP, ATP, ADP, and V3 all appear bare. Every one is expanded elsewhere on the site, but /autonomy is the page most likely to be reached directly from search or a link (it's the page with the schedule), and a reader landing there cold meets five undefined tokens.

5. Who owns the operational definition of coherence? Three pages report it missing; none says whose problem it is. Is it blocked on people, on the concept, or on nobody having started?
6. If the scramble control returns "no degradation," the page commits to retiring the developmental vocabulary. Does that commitment bind the sibling sites (SAGE, Synchronism, 4-Life) that use the same vocabulary, or only this page?
7. Is the Synchronism preprint targeting a venue, and would it carry the same caveats the site does? A caveat that survives peer review is worth more than nine pages of self-hedging.

### Verdict

I came to check whether the consciousness-adjacent claims are caveated and whether "raising not training" is defensible. Both answers are yes, and more emphatically than I expected. The raising/training distinction rests on an operational, checkable criterion — shape context, don't update weights — not on a vibe. Every developmental pattern carries a local negation, the null hypothesis is stated in the site's own words, the falsifying experiment is designed, and the page commits in advance to retiring its own vocabulary if that experiment fails. /autonomy volunteers that its QA loop cannot detect its own failures. This is a site that argues against itself competently, which is rare enough that I'd return.

The problem is that all of that rigor points inward. Nine pages, zero external citations. I cannot situate LCT against DIDs and verifiable credentials, or T3/V3 against thirty years of reputation-system work, because the site never mentions that either exists. The result is a vocabulary that is impeccably self-consistent and completely unanchored — and an unanchored vocabulary is one I can read but cannot cite. That is a positioning failure, and it is the one thing on this site that no additional caveat can fix. It is also invisible to the other three personas by construction: a developer, a writer, and a contributor all check the site against itself, and the site against itself is in good shape.

Two things sharpen that. First, the site's caveating is now saturated — /raising carries more hedge than claim, and it still tells me the session logs are unpublished and the coding criteria don't exist. I believe the hedges and I can check nothing; publishing ten redacted logs would move the evidence tier further than another honest paragraph ever will. Second, and worst: the one claim I *can* check is the one that fails. The scorecard link renders nothing without JavaScript, and the linked README says 23/25 where the site says 24/25 — and carries the caveat, absent from the page, that the run analyzed the games' public engine source and built per-game solvers. A lab this careful about hedging what nobody can verify should not be unhedged on the single number anyone can. Fix that one page and the honesty this site has genuinely earned stops being undercut by its own footnotes.
