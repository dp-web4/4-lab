## Pass 1: Curious Developer

### Summary
- **Pages visited**: 8 (seven front pages in the nav plus the `/notebook` index), plus outbound links checked by HTTP status
- **Understanding achieved**: partial
- **Would return?**: maybe
- **Overall impression**: The home page told me in under a minute that this is about how AI agents earn trust. What I'd actually install or run is less clear, and one repo link 404s.

### Journey
I landed on `/` from a GitHub README. The hero line, "AI agents are becoming actors in the world. We are building how they earn trust", plus "The idea" (trust comes from a track record checked against rules set in advance) gave me the pitch fast. The four project cards (Web4 / Hestia / Hub / SAGE) each fit in one sentence. Web4 is glossed inline as "a shared vocabulary, or ontology, that any system can implement", which was the first time I've seen "ontology" explained instead of just used. I liked that.

`/projects` repeats the cards with more detail and adds Hardbound, SWE-SAGE and Synchronism. The status labels (RUNNING / BUILDING / RESEARCH) are on every card, but they're explained only in a "What the labels mean" section at the very bottom. I worked them out by context before I got there. The Hestia card says "Runs on every machine in our lab; no public installer yet." As a developer, my next move was the repo. There I found a "Latest" release v0.0.4 (2026-08-11), three v0.3.0 release candidates (the latest dated 2026-10-15), and an "Installing the desktop app" section in the README. So the site's "no public installer" contradicts what I see on GitHub, unless "installer" means something narrower than a published release with install docs. The SWE-SAGE card names "the Gemma 4 developer-agent competition" without saying what that is, and its GitHub link **returns 404** (also linked from `/links`). That's the first thing I'd hit as a developer, and it looks like a dead or private repo.

`/fleet` lists eight machines with hardware and one-line roles. It's concrete and I enjoyed it. Model families are named generally, with detail deferred to `/notebook/fleet`. "CBP" and "pub" are just machine names, which is fine. "Its being improves the SAGE code it runs on" made me want to know more, and the page links onward.

`/raising` was the most interesting page. "The model is the weather, the being is the organism" is a memorable line. "Raising, not training" means no weight changes, development through experience and governed tools. The "What we have seen / Not yet shown" split reads as honest. Words like tutor, mentor and "waking periods" are used without saying who or what the tutor and mentor are (human? another model?). I had to guess.

`/principles` has six short principles. They're easy to read. "Hub" appears as "our own Hub" and assumes I remember the home card.

`/links` is a clean list of sites, code and packages. I checked them all: SAGE site, Synchronism site, 4-gov, SAGE repo, Hub tree and both package registries resolve (crates.io returns 200 through its API). **SWE-SAGE → 404.**

`/notebook` explains the two layers well: "short, plain, and current" for people, with evidence and caveats in the notebook. It lists nine notebook pages, including a Glossary at `/notebook/context`. That's where I'd go for acronyms, but nothing on the front pages points me to the glossary by name when I hit an unfamiliar term.

### Journey
The landing page has a clean structure: a hero H1, "The idea", "What we build" (four cards), "How the lab works" and "The full record". The nav (Projects / Fleet / Raising / How we work / Notebook / Links) is identical on all 16 pages. The footer repeats four of those links. Every internal route returns 200. `/arc-agi-3` redirects to `/notebook/arc-agi-3` as documented. No fragment link on any page points to a missing `id`.

The front pages use no Web4 acronyms at all. LCT, T3, V3, MRH, ATP, ADP, R6 and R7 occur 0 times across `/`, `/projects`, `/fleet`, `/raising`, `/principles`, `/links` and `/notebook`, so for canon terms the front is clean. The front does use house terms it never defines: SAGE, SWE-SAGE, the RUNNING/BUILDING/RESEARCH labels, tutor, mentor, "waking periods", tracks and dp-web4. I went to the notebook to see whether it backs them up.

The notebook pages are dense but consistent. Seven of the nine pages carry Web4 acronyms. I compared each expansion with the canonical table and they all match (table below). SAGE is expanded the same way on seven notebook pages: "Situation-Aware Governance Engine". So the developer's Pass 1 question ("does SAGE stand for something?") has an answer, but only in the notebook. `/notebook/projects` and `/notebook/raising` both open with a "terms used on this page" note. That is a good pattern.

Three things went wrong as I cross-checked.

1. **The two layers use different status vocabularies, and they disagree.** The front `/projects` labels are RUNNING / BUILDING / RESEARCH ("Running: in daily use on our own machines"). `/notebook/projects` uses runnable / research-stage ("clone it and it executes end to end today"). Web4 is **RUNNING** on the front and **research-stage** in the notebook. SAGE is **RESEARCH** on the front and **runnable** in the notebook. Neither page explains how one system maps to the other. Each label system is internally coherent: one measures use, the other measures cloneability. But a reader moving between layers sees two projects swap category with no explanation.
2. **The glossary has three names.** The notebook index lists it as "Glossary". Its route is `/notebook/context`. Notebook prose refers to it as a bare "/context" about 35 times (10 on `/notebook/fleet`, 7 on `/notebook/raising`, 5 on `/notebook/projects`), and sometimes as "the /context glossary". The bare `/context` redirects, so nothing is broken. But "Context" is not a label a reader can find in any nav.
3. **The glossary's completeness claim is false for the front's own vocabulary.** The `/notebook` index says the Glossary has "Every term and acronym used in the work". The glossary has 70 anchored entries, including `being`, `raising`, `seat` and `interactive-selection`. Front `/raising`, however, rests its "Raising, not training" paragraph on **tutor**, **mentor** and **waking periods**. "Mentor" and "waking" have **0 hits anywhere in the notebook** (all 16 pages; their only occurrences are on front `/raising`). "Tutor" has no glossary row. It appears in glossary prose, where it is described as "a fixed six-question script with a praise line delivered whatever the answer was" on four raising lines. A reader who follows the front's link to the notebook to find out who the tutor and mentor are gets nothing for "mentor". For "tutor" they get a description that reads very differently from "guided sessions with a tutor".

Smaller items: on `/notebook/context`, the at-a-glance "Trust-native" row uses T3/V3, LCT and MRH at about word 358. The LCT row, the first of their expansions, comes at about word 1,600. On `/notebook/principles`, "T3/V3" first appears at about word 358 unexpanded, and the expansion follows at about word 963. On `/notebook/raising`, "ARC-SAGE harness" (about word 296) comes before SAGE is expanded (about word 559). `/notebook/projects` states in its own prose that the front SWE-SAGE link "returns 404 to visitors". So the notebook documents a front defect that Pass 1 hit again today.

Next I read the Hestia card on `/projects` ("Every action is checked first and recorded where the agent cannot change it") and the Home card ("with a record the agent cannot edit"). Hestia's own README (L38–51, L162–163) says the opposite in bold. It is an "**early prototype**". The gate "does not … stop a sophisticated agent from routing around or gaming it". The README also states "two environment variables suffice today" to bypass the gate. Its assurance ceiling is "A1 — a cooperative gate running as the same UID as the operator. Tamper-**evident**, not tamper-proof." The SAGE README L133 says the same of the whole open stack. So does `/notebook/home` ("a cooperative and tamper-evident gate, not adversary-proof containment"). The `/notebook/context` ledger row adds "append-only by convention and process, not yet by hardware". I am not reporting a missing caveat. "Cannot change" and "every action" are factual claims, and upstream's own documentation contradicts both. "Recorded so that a change is detectable" would be true.

`/fleet` matched the notebook: the model families (Qwen, Gemma, Granite, Llama) and the eight machines. "Earn trust in each other from the record" is backed by SAGE's peer trust tracker on `/notebook/fleet` (per-peer T3 from health polls and delegated calls). `/raising`'s "every one of those actions is checked against rules before it happens" matches the notebook's gateway chain (intent → bounded SAGE gateway vocabulary → Hestia law → dispatch → witnessed result). I would still prefer "Hestia law" over "rules" there, given the A1 ceiling above.

On the notebook side I checked what changed upstream since yesterday. web4 **PR #914** ("docs(standards): state identity and delegation status as code has them", merged 2026-10-15) corrects web4's standards package against Hestia code (`5e1ba8e4`). The only mention is on `/notebook/home`.

That led me to a pointer sweep on `/notebook/context`. Six "home page"/"(Home, …)" references (Federation "listed … on the home page", substrate "the home page says weights", the MRH "home page's card", Delegation, Hestia "adjudicates" and world model) point to content that front Home no longer carries (0 hits for federation, weights, MRH, delegation, adjudicat).
