## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (Home, /projects, /fleet, /autonomy, /raising, /principles, /context, /links, /arc-agi-3). The nav has nine entries, and the task brief's "8 pages" is one short.
- **Understanding achieved**: good (for Home, /projects and the Quick start); partial (for /fleet, /raising, /autonomy)
- **Would return?**: yes, to try the SAGE quick start. Probably not to read /fleet or /raising end to end.
- **Overall impression**: Home answers "what is this?" in about 850 words and gives a developer a real first command. Behind it, three pages each run 3–12k words of self-auditing prose, and the "try it" path is buried at the bottom of the 3.6k-word /projects page.

### Journey
**Home.** The h1 ("AI agents are becoming actors in the world. Trust and authority need to become first-class.") and the first paragraph work. Web4 is "an open trust ontology, not an architecture, infrastructure or stack", and it sits alongside Hestia, Hub and SAGE. The thesis sentence ("trust should be computed from witnessed evidence, in context, by the party doing the relying") is the clearest line on the whole site. "Start here" gives three doors: Calibration (the web4 STATUS.md: shipped vs aspirational, which is exactly what a developer wants first), Vocabulary (/context) and Full ecosystem (/projects). The Hestia link honestly says "has no install guide for outside users yet; see the Quick start", and that link goes to `/projects#quick-start`. Good. Home names LCT, T3/V3, MRH, R6/R7 and ATP/ADP only as a list of glossary topics, never as claims. That is the right call for a landing page.

**/projects.** Thirteen cards with status badges (public/private, runnable/research-stage/stalled). The badges are the most useful thing on the site for my persona, because I can triage in seconds. The Quick start at the bottom was the real test. I checked the SAGE block against the public SAGE repo:
- `sage/instances/init.py` exists and accepts `--machine`, `--model` and `--operator-name`.
- `sage-rs/` is a Cargo workspace with a `sage-daemon` member.
- `main.rs` reads `SAGE_MACHINE`/`SAGE_MODEL`, and its default port is 8760 as the page says.
- `web4-core` exists on PyPI, and crates.io max_version is 0.3.0, matching the page's `"0.3"`.

**Every command I checked matches the repo. I did not run any of them**, so it is still untested whether a clean machine gets a running daemon. The Hestia block says outright "NO FIRST-RUN PATH YET … Not a working quick start". ACT says "STALLED, read-only visit". That is refreshingly honest. My friction is where the Quick start sits: after ~3.5k words of cards, including a long debate about the word "governance", and with no link to it from the top of /projects itself. Home links to it; /projects' own intro only says "at the bottom of this page".

"Governance" confused me. The site's rules say "oversight, not governance", but Home calls Hestia, Hub and SAGE "running governance systems". SAGE is "Situation-Aware *Governance* Engine" and Hestia is a "governance daemon ('governance' is deliberate…)". /projects explains each exception inline and points to `/context#governance-oversight`. That makes sense once read, but a developer first sees the word used freely on Home and only later learns it is a policed term.

**/fleet.** It gives eight machines with hardware and roles. The roles are brain analogies ("thalamic router", "cerebellum", "working memory (dorsolateral prefrontal cortex / dlPFC)"), each glossed inline as "Brain (functional analogy)". That works. The page is ~6.8k words, and most of it is per-line session accounting ("Raising line: quiet — 462 session records…", "instrumentation broken — 121 session records"). The sentence that lost me: "The successor line already contains its predecessor's records: this page counts the successor and does not add the predecessor, because doing so would count the same sessions twice." It is correct, but it assumes I already know what a line, an instance and a migration are. Home says "how instance, line and session record nest is on /context", but /fleet doesn't repeat that pointer where the nouns first appear.

**/autonomy.** It gives a clear eight-track timeline (supervisors 03:00, archivist, publisher, visitor, maintainer, outreach, explorer, then dream consolidation). The headline stat is "31+ autonomous tracks across 6 cognition machines, ~53 sessions per day (figures as of 2026-05-26, not recounted since)". The honesty is appreciated, but the first number on the page is four months stale by its own admission. For a developer, the lead stat is the one that most needs to be current. The boundaries section ("Tracks edit their own briefs and checks", enforcement "at the process level", not cryptographic) is candid and useful.

**/raising.** "Raising is not training; it is also not nothing." That is a good hook. The six BECOMING categories are listed, and BECOMING is explicitly glossed as "a proper name, not an acronym". The page is ~6.2k words of caveats, confounds and a deflationary alternative. As a developer I respect it but skimmed it. "Raising line" first appears around word 1,680 with no gloss on this page.

**/principles.** Ten principles, ~1.3k words, readable. The license disclosure (main repos AGPL-3.0, snarc/membot MIT, the ARC-SAGE harness MIT-0, ACT Apache-2.0) is exactly what a developer checks before cloning. It is good to have it stated.

**/context.** The glossary is ~11.9k words. The "Glossary at a glance" table has 58 terms grouped by concept (Web4 → Ontology → Trust → … → LCT → T3 → V3 → MRH → ATP …), not alphabetically. The WebFetch summarizer told me it was alphabetical, and the live HTML says otherwise. The conceptual order reads well top to bottom, but looking up one term (e.g. PolicyGate) means scanning. The equation `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP` is shown with its operator legend.

**/links.** Clean and grouped (explainer sites, GitHub, forks), with contact email. Every link has descriptive text; none shows a raw URL as its label (checked in the HTML).

**/arc-agi-3.** A short page (~680 words) that expands ARC-AGI-3 on first use. It gives 94.85%, 23/25 environments and 175/183 levels, then caveats straight away that the harness read the games' public engine source ("outside strict from-observation competition play"). That caveat placement is right: I got the number and its limits together.

**Method note.** WebFetch summaries were wrong on several points I then checked against the curl'd live HTML:
- Page lengths: it said /raising was "13,500 words" (actually ~6.2k), /arc-agi-3 "~1,500" (actually ~680) and /principles "~2,100" (actually ~1.3k).
- Glossary order: it said the glossary was alphabetically sorted, which it isn't.
- Install steps: it said the SAGE card has install steps. They are in the Quick start, not on the card.

Every friction item below was checked against the live HTML.
