## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 site pages (/, /projects, /fleet, /autonomy, /raising, /principles, /context, /links, /arc-agi-3) + followed the two "clone" CTAs to github.com/dp-web4/SAGE and github.com/dp-web4/ACT
- **Understanding achieved**: good
- **Would return?**: yes — but only because SAGE's own README turned out to have a real quickstart; the site itself never got me to a terminal
- **Overall impression**: The site explains itself unusually well for something this acronym-dense, but the moment I try to *do* something the handoff to the repos is wrong in small, specific ways.

### Journey

Landed on `/`. Headline "Eight machines. Forty original repos. One recursive learning loop." — fine, I know what those words mean. The tagline says "trust-native ontology — a shared vocabulary and trust model for AI agents, in the knowledge-representation sense", which is the first time I've seen a site pre-empt my "is this a blockchain thing?" reflex in the first sentence. Good. The "problem this addresses" section (centralized trust doesn't scale, crypto proves key custody not conduct, so compute trust per-relationship from witnessed interaction) is a real, two-paragraph pitch I could repeat to a colleague. That's the 2-minute test passed.

The "New here?" box says the site is acronym-dense and points at `/context#glossary` or a primer further down. I scrolled to the primer instead. Every acronym in the equation is expanded inline there — LCT, T3/V3, MRH, ATP/ADP, MCP, RDF, SAGE, SNARC. I did not have to leave the page to decode the headline. Then "clone SAGE — the recommended starting point — or ACT (Agentic Context Tool) for the Web4 trust-layer side." OK: SAGE it is.

`/projects`: eleven cards, each labelled `public/private` and `runnable/research-stage`, and — this is the part I appreciated — a one-line definition of what "runnable" means: *"clone it and it executes end to end today (a demo, a script, a server) — not a claim about polish or completeness."* That's the most developer-honest status label I've seen on a research site. The Quick start block gives two `git clone` commands with comments: `# See README for Python/conda setup and first session instructions` for SAGE, `# See README for Go/Cosmos SDK setup` for ACT. "SAGE runs on a single machine — no Jetson required." Sold.

**So I clicked through to the SAGE README.** First heading: "SAGE: Situation-Aware Governance Engine — a cognition kernel that wraps a **frozen** LLM in a persistent identity, trust, and resource-governance loop." Nice one-liner. Then the quickstart:

```
git clone https://github.com/dp-web4/SAGE.git
cd SAGE
python3 -m sage.instances.init --machine mybox --model gemma3:4b
cd sage-rs && cargo build --release && cd ..
SAGE_MACHINE=mybox SAGE_MODEL=gemma3:4b ./sage-rs/target/release/sage-daemon
```

Prerequisites per the README: **"Rust toolchain (stable), Ollama (for local LLM inference), Python 3.10+ (for raising scripts and instance init)."** Zero mentions of conda. The daemon is a Rust binary; Python is only the init script. So the site's `# See README for Python/conda setup` comment is describing a project that no longer exists in that form — a Python-only dev will hit `cd sage-rs && cargo build` and stop. It's a one-line fix, but it's the *one line* on the whole site that's supposed to get me from reading to running.

Also in the README, second thing I noticed: it says "Each SAGE instance fractally implements the full Web4 **stack**" and glosses "T3/V3 (Trust Tensors)". The site I just came from told me, in bold, that Web4 is an ontology and T3 is "Talent / Training / Temperament". I don't know which is right — I'm not supposed to — but the site's *recommended first clone* contradicts the site on the two terms the site cares most about. That's a credibility hit at exactly the moment I'm deciding whether the vocabulary is load-bearing or decorative.

**ACT**: the GitHub page rendered only the repo description — "Cosmos SDK chain implementation, candidate ledger backend for Web4 anchoring. Early prototype." — and the raw README at `main` returned 404. Could be a different default branch; I couldn't confirm a README exists. From where I sit the site says "See README for Go/Cosmos SDK setup" and I couldn't find the README. Marking this *unverified*, not broken.

Back to the site. `/fleet`: eight machines in a table (name, hardware, local model, brain-analogy role, session count). Peer-to-peer, "fleet manifest — a phone book, not a command center", `SAGE_MODEL` env var lets any machine run any model. That env var actually appears in the SAGE quickstart, which was a small satisfying click. "hestia" appears twice ("Its hestia identity is the fleet's first agent-owned one", "the hestia trust layer") and is never expanded or linked; I still don't know what hestia is — a service? a repo? a person? Everything else that looked like jargon ("crystallization", "chapter ledger", "Sovereign") was defined in the same sentence.

`/autonomy`: the daily timeline — Supervisors 03:00, Archivist 04:00, Publisher 04:30, Visitor 05:30, Maintainer 06:30, Outreach 07:00, Explorer 08:00, Dream after. "A track is a scheduled autonomous job — a cron entry with a declared scope and a set of repos it writes to." 31+ of them across six machines. This is the page I most wanted to copy something from, and there's nothing to copy: no crontab line, no track definition, no link to whatever runs a track. The only GitHub link on the page is the org root. The limitations sections are genuinely good ("detect-and-revert, not prevent"; "same model families as the tracks that author the content they audit"; the Publisher repo-push gap "unaddressed, not solved") — I believe this loop exists. I just can't see it.

`/raising`: "Raising is not training. Training optimizes for a loss function. Raising creates conditions for development — then watches what happens." Six phases (Grounding → Sensing → Relating → Questioning → Creating → Acting). Explicit "we're not claiming these entities are conscious" caveat. Page says no log samples or coding criteria are published yet. Fine — I skimmed; this isn't my page.

`/principles`: ten short principles. #3 "R&D, not production" and #6 "Document failures" are the kind of thing I'd put in a team README. #5 (Synthon) spends more words explaining why it *doesn't* deserve to be a principle than stating it — "it has not earned the status of the principles around it, and it should be read at that weight". Odd but honest. T3/V3 are expanded inline here too.

`/context`: the glossary. ~45 entries, and an "Evidence & limitations" ladder (externally validated → internal observations → unreplicated → unlicensed vocabulary) that grades the lab's own claims. Direct link to `CANONICAL_TERMS_v1.md` in the web4 repo. I skimmed as a reference; it's the page I'd come back to.

`/links`: every external thing with counts and a verification date. Contact email. `/arc-agi-3`: 94.85% action score, 24/25 games, ~$250 API spend, link to the scorecard and "ARC-SAGE paper & code (MIT-0)". The ablation caveat ("same model, no harness — has not been run") is stated up front, which a benchmark page almost never does. No "how to reproduce" on the page, but the repo is linked.

### Verdict
This is the clearest research-lab site I've read that uses this many acronyms — the primer on `/`, the "runnable means it executes end to end today, not a claim about polish" label, and the up-front ablation caveat on the ARC page all earned trust fast. But the site's job for a developer ends at "clone SAGE", and that handoff is broken in a small, checkable way: the quickstart comment describes a Python/conda project while the README requires a Rust toolchain and Ollama, and the README then re-defines the two terms the site was most careful about. Fix the one comment line and put one sentence of expectation-setting on the CTA, and I'd have been running a daemon on localhost:8760 inside ten minutes instead of writing this.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 site pages (/, /projects, /fleet, /autonomy, /raising, /principles, /context, /links, /arc-agi-3) + the `CANONICAL_TERMS_v1.md` document that /context links to (followed it because the site presents it as the source of record)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: Acronym expansions are consistent to the letter across all nine pages — the problem is not the expansions, it's that the site now has two quick starts that disagree, one relationship-arrow it flattens on four pages, and one phrase ("trust layer") pointed at three different things.

### Journey

I did this the boring way: every page, nav checked, every acronym's first occurrence quoted, then the same acronym's gloss compared page-to-page, then the site's glosses compared against the canon document the site itself links.

**Nav**: eight links — Projects, Glossary, ARC-AGI-3, Fleet, Autonomy, Raising, Principles, Links. All resolve. One small thing: the nav calls the glossary page "Glossary", but every in-text pointer on the site says "see /context" (/fleet: "defined in /context"; /links: "See /context for full definitions"; /principles: "see /context"). The links are clickable so nobody gets lost, but a reader scanning the nav for "Context" won't find it.

**Expansions**: I checked LCT, T3, V3, MRH, ATP, ADP, R6, R7, MCP, RDF, SAGE, SNARC, ACT, ACP on every page where they appear. Every single expansion matches the canonical table, on every page, with no variation in wording — "Linked Context Token", "Talent / Training / Temperament", "Valuation / Veracity / Validity", "Markov Relevancy Horizon", "Allocation Transfer Packet / Allocation Discharge Packet", "Six-Element Action Framework". No "Lifelong", no "Trust-Tracing", no "Minimum Response". "Web4 is an ontology" and "Hardbound is oversight" are stated as such on /, /projects, /raising, /principles, /context; "governance" survives only inside SAGE's name and hestia's field name, both with the same fixed disclaimer sentence ("predates the lab's governance→oversight correction"). First-use discipline is good: /raising, /fleet, /arc-agi-3 and /links each open with a "vocabulary on this page is expanded inline" or "New here?" line, and /arc-agi-3's "New here?" line expands all eight equation terms (I checked twice because Pass 1 reported MCP/RDF unexpanded there — they are expanded, in the intro note).

**Then I followed /context's link to `CANONICAL_TERMS_v1.md`** (v1.0.0, Feb 12 2026) and compared glosses rather than expansions. Three things fell out:

1. Canon lists R6 as **"Rules / Role / Request / Reference / Resource → Result"** — five slashes and one arrow, and the arrow carries meaning (the first five are inputs; Result is what they produce; canon pairs it with "ATP→ADP"). The site writes **"Rules / Role / Request / Reference / Resource / Result"** on /projects, /context, /arc-agi-3 and /links — six co-equal list items. Same six words, different grammar. The crib sheet I was handed also uses six slashes, so a table-only audit passes this by construction; you only see it against the source.
2. Canon's headwords are "T3 (Trust Tensor)" and "V3 (Value Tensor)" with Talent/Training/Temperament as the *components*. The site says "three-component trust tensor" (lowercase) and expands the components — consistent with canon. Note for the maintainer: this means Pass 1's report that the SAGE README "re-defines T3 as 'Trust Tensors'" is not actually drift — "Trust Tensor" is canon's own name for T3. The README's "full Web4 **stack**" is still drift.
3. Canon does not contain the Web4 equation or the `/`, `*`, `+` glosses at all. The site's section is titled "The Web4 equation as shared anchor" and links canon in the same breath, but never says the equation and operator glosses are the site's own. A writer would attribute them.

**Cross-page consistency** is where I found the one high-severity item. /projects has a Quick start block whose SAGE comment reads `# See README for Python/conda setup and first session instructions`. /links has a *different* Quick start block: `# Needs: Rust (stable), Ollama, Python 3.10+`, then eleven transcribed lines (init, `cargo build --release`, run the daemon, dashboard at localhost:8760), followed by "Commands transcribed from the SAGE README's Getting Started section, which is the maintained version if these drift." So the site already contains the correct prerequisites — on the page a developer visits *last*. The /projects block, which is the one linked from the "clone SAGE" CTA on /, is the stale one. Pass 1 diagnosed this against the README; I'm diagnosing it against the site's own other page. Nobody had to leave the site to catch it.

**"trust layer"** is used for three different referents: /context — "Hardbound is the hardware-bound oversight suite — the trust layer intended to touch silicon"; /fleet — "the hestia trust layer derives its displayed scores…"; / and /links — "ACT … for the Web4 trust-layer side". A reader who meets all three cannot tell whether Hardbound, hestia and Web4 are the same layer, three layers, or a metaphor. Only the /context one is anchored to a defined term.

**hestia**: two uses on /fleet, and /fleet even says "hestia's own internal field name" — so it's software with a schema — but it is not a glossary headword on /context (I checked the string; absent) and never gets a parenthetical. Also on /fleet: "Sovereign", "chapter ledger", "chapter law" are flagged in-sentence as "not yet in CANONICAL_TERMS_v1" — the document is *named* but not linked there, and /links (the page whose job is external links) has no link to it either. Only /context links it.

**Counts reconcile**: /fleet's per-machine figures (435 + 488 + 336 + 377 + 162 + 193) sum to exactly 1,991; plus HUB's 74 = 2,065. /links says "1,991 internally logged raising sessions"; /fleet says "those pages call this same quantity 'raising sessions'". /raising's "115 raising sessions" for SAGE-Sprout is explicitly labelled "a model-line count, not a machine total" and points at the 488. All good. Two wording wobbles: /fleet's "the site's 1,991 / 2,065 totals, which cover the six cognition machines plus HUB" reads as if both figures include HUB when only 2,065 does; and /'s "What's happening right now" opens "Six machines, six brain components" directly below a headline that says "Eight machines" — /fleet and /autonomy both write "six cognition machines", / drops the qualifier.

**Notation**: the site declares that `/` "means two things" (verified-by in `T3/V3`; allocation pair in `ATP/ADP`) — consistently, on /, /context, /arc-agi-3. But the same pages then use `/` a third way, as a plain list separator, inside the very glosses that explain the operator: "Talent / Training / Temperament", "Rules / Role / … / Result", and the /context section heading "T3 / V3: trust and value tensors" (spaced slash = separator) sitting under an equation where `T3/V3` (unspaced) = "verified by". Two spellings of the same symbol carrying different meanings on one page, with only two of the three senses declared.

**ATP/ADP gloss**: / says "intent and discharge as two distinct audit artifacts"; /context says ADP is "the spent form of the ATP" and canon says "the 'spent' form of ATP". One packet in two states vs. two artifacts — both pages then say it recharges, so the cycle is right; the object count isn't harmonized.

**/principles.** Principle 5 (Synthon) spends its second paragraph explaining that synthon and coherence define each other and "neither has an operational definition yet … it has not earned the status of the principles around it." Honest, and it correctly names the circularity. Principle 7 is where I stopped: "The mechanism: shaping context to deepen attractor basins in the probability landscape — not modifying parameters in raising sessions." From a dynamical-systems reading these two clauses conflict. If parameters don't change, the landscape doesn't change; conditioning on context selects a *conditional* distribution, it does not deepen anything persistent. The sentence "It is not training; it is also not nothing" is the right instinct, but "deepen" smuggles in persistence that the same sentence denies. Either the basins live in the context files (then say that — "the identity is the context, and the context is what accumulates") or the metaphor is doing work the mechanism can't. Principle 1's termite/pheromone framing is fine as analogy and is labelled as one.

That sentence should be on every autonomous-agent page on the internet. ### Unanswered Questions

5. How does a human stop a track? Is there a mechanism faster than the 24-hour detect-and-revert loop?
6. Which two or three papers is the site thinking of when it says "AI-safety literature" and "the literature"?
7. In Principle 7, where does the persistence live if not in the weights — is "deepen attractor basins" a claim about the context files, the model, or the pair?
8. Does "efficiency-weighted" mean the action score penalizes actions beyond the human median, or something else?

### Verdict
On the three questions I came with — are consciousness-adjacent claims caveated, is "raising not training" defensible, does the honest assessment feel honest — the answers are yes, yes-as-an-intervention-description, and yes: this site states its own null hypothesis, grades its own evidence, and pre-commits to retiring its vocabulary. I have rarely seen that. But the one claim the site places at the top of its own evidence ladder is stated on five pages with a game count the linked repo contradicts (24/25 vs 23/25) and without the condition the repo itself calls decisive — the harness read the games' engine source. The caveating is saturated everywhere except where the number is. Fix the ARC conditions paragraph and the count first; then give the raising pre-commitment a positive criterion and the "literature" a citation, and this becomes a site I would send a skeptical colleague to without a warning.
