### Journey
I arrived from a GitHub README. The home page explains itself fast: one human, a fleet of AI agents, open tools for governing agents, and the lab runs on those tools itself ("They are refused by it every day" is a great line, I believed it). Four product cards with status labels. I understood RUNNING / BUILDING / RESEARCH immediately, and the label legend on `/projects` confirmed my guess.

`/projects` is where I wanted to act. Web4 card: "reference code on crates.io and PyPI", link to the repo. Good. Hestia: "no public installer yet", honest, I moved on. Hub: links into a subdirectory of the web4 repo. Fine. SAGE: the card links to a separate SAGE site, not a repo. SWE-SAGE: "Our entry in the Gemma 4 developer-agent competition", link to `github.com/dp-web4/SWE-SAGE`. I clicked it. **404.** GitHub's API also returns 404, so it is private or gone, not a typo. Same dead link on `/links`. `/fleet` says Nomad hosts "the smallest being, for SWE-SAGE". So three front pages advertise a repo I cannot see, and the footer line "Every repository, with its maturity and what each claim rests on, is in the notebook" sent me to `/notebook/projects`, where SWE-SAGE does not appear at all. I grep'd all nine notebook pages: zero hits for "SWE-SAGE" or "developer-agent competition". The front lists a project the notebook has never heard of.

That detour did turn up the thing I actually needed. `/notebook/projects` has a real **Quick start** block: clone SAGE, `ollama pull`, create an instance, `cargo build`, run the daemon, dashboard on port 8760. It also says, in a comment, that the SAGE README has no setup section and the steps are maintained on the site. I checked the README (1,463 words, headings only, no install, no link back to this page). So the only runnable path for the lab's flagship project lives on a notebook page, and nothing on the front says "quick start here". The SAGE front card points at a different site instead. If I had not been chasing a 404 I would have left thinking SAGE was read-only research.

`/fleet` is nice: eight machines, hardware I recognize, a one-line job for each. The division into heavy work / review / hosting is the kind of thing I would steal for my own setup. `/raising` is well written and I appreciated the "Not yet shown" column saying there is no blind comparison against a fresh model. `/principles` reads as six sane engineering rules. It mentions "The agents coordinate through a shared forum and our own Hub", and I wondered whether I could read that forum. `/notebook/projects` answered: "There are no community channels yet (no forum, chat or mailing list): the issue trackers are the channel." So the forum is internal, but the front sentence does not say that, and a developer reads "shared forum" as something with a URL.

`/links` is a clean index. `/notebook` explains the two-layer design clearly, and I liked "If you are an AI reader, start here." The glossary (`/notebook/context`) is ~12k words and not alphabetical, so I used browser find; the "at a glance" table at the top saved me.

Terminology was my main job, so instead of trusting page summaries I pulled the rendered text of all 16 pages and checked every expansion string against the canonical table. That is where the notebook is uneven, and in three places the expansion-on-first-use promise is made by a sentence that is itself the first use (details in the friction log).

The one slip is inside the notebook itself: `/notebook/home` says Web4, Hestia and Hub "establish an open interoperability layer" in the Commercial path paragraph, a few hundred words after the same page rules out "architecture, infrastructure or stack". A reader who has just absorbed that rule reads "layer" as the forbidden class.

The thing that would actually send a documentation reader to the wrong place is the cross-reference layer. Notebook prose points at `/fleet`, `/raising`, `/projects`, `/links` and `/principles` roughly 86 times (my count: 46 on the glossary, 8 each on `/notebook/fleet` and `/notebook/raising`, 6 on `/notebook/links`, 5 on `/notebook/autonomy`, 4 each on `/notebook/home`, `/notebook/projects`, `/notebook/principles`, 1 on `/notebook/arc-agi-3`). The fix is mechanical: the five non-redirecting labels should read `/notebook/...`, or the five routes should get the same redirect treatment where a notebook anchor is meant. The body hrefs are already clean: outside the shared nav and footer, no notebook page links to a bare front route.
