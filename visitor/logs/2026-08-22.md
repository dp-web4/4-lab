## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (/, /projects, /context, /fleet, /autonomy, /raising, /principles, /links, /arc-agi-3)
- **Understanding achieved**: good

- **Overall impression**: The site tells me what this lab is within two minutes and hands me a real clone-and-run path — but the page that tells me to run SAGE gives me a different, thinner, and partly wrong setup than the page that actually has the working one.

### Journey

Landed on home from a repo README. The headline — "Eight machines. Forty original repos. One recursive learning loop." — did its job: I immediately knew this was a fleet-of-machines research thing, not a product. The problem statement in the second paragraph is the best thing on the site for someone like me: "AI agents already act on their own — browsing, transacting, coordinating with other agents — and there is no general way to establish whether one will behave appropriately in a given context." That's a sentence I can repeat to a coworker. Most projects in this space open with their own vocabulary; this one opened with the gap.

The equation (`Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP`) is dense but every acronym in it is expanded right there on home, including MCP and RDF, which I already knew — that told me the page is written for someone at my level. Two tokens on home stopped me: **CBP** and **HUB**. They're all-caps in a paragraph full of expanded acronyms, so I assumed I'd missed a definition and scrolled back up looking for one. They're machine names. I only learned that four pages later on /fleet, which explicitly says they're proper names, not acronyms. Cheap fix, real half-minute lost.

Went to /projects next, because that's what a developer does. The status vocabulary is genuinely good and I want to steal it: **runnable** = "clone it and it executes end to end today (a demo, a script, a server) — not a claim about polish or completeness"; **research-stage** = "design docs, specs, and experiments; may not run end to end without additional setup." That single distinction saved me from cloning Web4 and wondering where the code was. And the page answers the newcomer question outright: "Want to run something rather than read? Start with **SAGE** — it runs on a single machine, no Jetson required."

So I scrolled to the code block at the bottom of /projects and got:

```
# SAGE — on-device cognition kernel (recommended first clone)
git clone https://github.com/dp-web4/SAGE
cd SAGE
# See README for Python/conda setup and first session instructions
```

Which is where my run stalls. It's a clone and a shrug — the real instructions are "in the README." The surrounding prose points me at /links only for "licenses and the full repo list," so I had no reason to go there for setup.

I went to /links anyway, later, for the external repo links. And /links has the actual quick start — the good one:

```
# SAGE — on-device cognition kernel
# Needs: Rust (stable), Ollama, Python 3.10+
git clone https://github.com/dp-web4/SAGE
cd SAGE
python3 -m sage.instances.init --machine mybox --model gemma3:4b --operator-name yourname
cd sage-rs && cargo build --release && cd ..
SAGE_MACHINE=mybox SAGE_MODEL=gemma3:4b ./sage-rs/target/release/sage-daemon
```

Prerequisites declared up front, three real commands, and it ends at a dashboard on `localhost:8760`. That's a first-run path I'd actually follow. It's on the page I had no reason to visit, and the page that told me to start with SAGE says "Python/conda" — which doesn't mention Rust or Ollama at all, and neither of them is optional if step 2 is `cargo build --release`. Following /projects, I'd have hit a missing cargo toolchain and blamed the repo.

/context is where I went when the vocabulary got ahead of me, and it's much better than the usual glossary — it defines the *senses*, not just the expansions. `Autonomous` is scoped as "unattended and self-scheduled; NOT self-directed in the AI-safety sense." `Policy` is explicitly not an RL policy network. `Attractor` is labeled a metaphor. Those three entries pre-empt exactly the wrong readings I was already forming. It's also long — 45+ terms, which is a reference doc, not an onboarding read, and home calls it a "glossary" while the nav calls it Glossary and every other page's prose calls it "/context". Minor, but I typed the path once before noticing the nav item was the same thing.

/fleet, /autonomy, /raising, /principles I read quickly. /autonomy was the surprise — I expected marketing and got "the oversight posture is detect-and-revert (audit log + sub-minute rollback), not prevent (pre-approval). Consequential pushes are not human-gated before they ship." A site describing its own automation as not human-gated is not what I expected to read, and it's why I'd come back. Same on /raising: "everything below might be competent context engineering and nothing more — the control that would discriminate raising from that alternative has not been run yet." I don't have to evaluate the raising claims because the page already told me the discriminating experiment is unrun.

What I couldn't do anywhere: look at anything. /autonomy describes "a dated audit log recording what changed" and "zero rollbacks across 117 commits" but links no log. The ARC-AGI-3 page is the one exception and it's the strongest page on the site for me — it links both the code (ARC-SAGE, MIT-0) and an external ARC Prize scorecard, and it says up front that the harness-vs-model ablation is unrun and the result is "Claude Opus 4.6 operating within the SAGE harness." I can check that one. Everything else I have to take on trust, which is a strange position for a site whose subject is computing trust from evidence.

### Journey

I audit terminology by building a table first and reading prose second. So I collected every acronym expansion from all nine pages before forming any impression, then diffed them against the canonical table.

The diff came back empty. **Zero drift.** LCT is "Linked Context Token" on /, /projects, /fleet, /raising, /links, /arc-agi-3, and /context — six pages, one string, no variance. T3 is "Talent / Training / Temperament" everywhere it appears; V3 is "Valuation / Veracity / Validity"; MRH is "Markov Relevancy Horizon"; ATP/ADP are "Allocation Transfer Packet"/"Allocation Discharge Packet"; R6 is "Six-Element Action Framework: Rules / Role / Request / Reference / Resource / Result". None of the drift spellings in my reference table — "Lifelong Capability Token", "Trust-Tracing-Tensor", "Minimum Response Horizon", "Attention Token Pool", "R7", "R5" — appears anywhere on the site. I searched for the banned framings too: "stack" as a description of Web4 returns **zero** site-wide; "production ready" returns zero, and /principles instead names a principle "R&D, not production" with the sharpest disclaimer on the site ("Nothing on this site is intended for or suitable for deployment in safety-critical, medical, financial, or autonomous-control settings"). "Unification" appears only inside its own negation, twice: /projects says "This isn't unification — it's fractal leverage," and /principles says "Cross-domain application is fractal leverage, not unification and not scope inflation."

For a terminology audit that is the whole finding, and I want to state it as a null result rather than pad it into flags. What I could not check from a browser is whether canon still says what the site says it says — that is Pass 3's job and above my ceiling.

So I spent the rest of the pass on the parts of my brief that aren't vocabulary: is each term defined on first use, and does the site call the same thing by the same name?

**Defined on first use: yes, consistently.** Home expands every acronym in the equation inline, including MCP and RDF. /projects expands all twelve acronyms it uses. /arc-agi-3 expands ARC-AGI-3 in full ("Abstraction and Reasoning Corpus for Artificial General Intelligence, third-gen interactive benchmark") and even expands E4B inline as "effective 4B — an edge variant that runs in the memory footprint of ~4B parameter model". /fleet, /autonomy, /raising, /links defer to the glossary with an explicit pointer rather than silently. That is the correct pattern and it is applied uniformly. I found no acronym used cold with no expansion and no pointer.

I also checked the coined vocabulary, which is where sites like this usually leak: "society-host", "pub", "cognition machine", "PolicyGate", "metabolic state", "p_crit", "ACP", "ACT", "synthon", "coherence", "attractor", "raising" all have glossary entries. That is unusually complete. Two gaps: **E4B** has no glossary entry (acceptable — it is expanded where it is used and used on one page), and **"runnable" / "research-stage"**, the project status vocabulary, is defined only in the /projects legend and is not in the glossary at all.

**Where the site does call one thing several names**, and this is my main finding: the glossary. The nav item says **"Glossary"**. The page's H1 says **"How Knowledge Flows"**. The URL is **/context**. Body prose across the site calls it, variously, "the /context glossary", "start with /context", "the glossary", and bare "/context". The page's own intro paragraph says it "*Also* serves as the lab's working glossary" — that is, the nav names the page after its self-described secondary function, and the page's actual title never appears in the nav. Four labels, one destination. A reader who is told on /raising to see "the full reference for every term on the site" then clicks nav → Glossary → lands on a page headed "How Knowledge Flows" has to spend a beat confirming they arrived. This is the single cheapest high-value fix on the site and it is invisible from inside any one page, which is presumably why it has survived.

The second structural finding is about authority. The site names CANONICAL_TERMS_v1.md as the source of truth for its vocabulary and **links it from exactly one page** — /context, deep in the glossary. It is not on /links, whose entire purpose is external links and which already lists the web4 repo the doc lives in. It is not on /principles, whose Principle 10 is literally "Terminology matters". For a site whose differentiator is terminological discipline, the artifact that makes that discipline checkable is reachable only by someone who already went looking.

Third, a documentation-consistency defect I found independently and can confirm against Pass 1's account: **there are two SAGE quick-starts and they contradict each other.** /projects — the page that tells newcomers "start with SAGE" — gives `git clone` plus the comment "See README for Python/conda setup and first session instructions". /links gives "Needs: Rust (stable), Ollama, Python 3.10+" and three real commands, the second of which is `cargo build --release`. A prerequisite list that omits a required toolchain is worse than no list; and two setup blocks for one repo, on one site, is a maintenance trap regardless of which is right.

Finally I ran the arithmetic, because numbers are terminology's quiet cousin. They reconcile exactly. /fleet's per-machine session counts — Thor 435, Sprout 488, Legion 336, McNugget 377, Nomad 162, CBP 193 — sum to **1,991**, and 1,991 + HUB's 74 = **2,065**, which is the figure home states. Repos: 40 original = 21 public + 19 internal, plus 32 forks = 72 total, and home says all three numbers in one sentence. Machines: "Eight machines" on home, and /fleet's "Six cognition machines, plus two society-hosts" with eight named machines listed. No count on this site disagrees with any other count on this site.

One caveat that *did* travel, worth recording because it is the exception to the usual pattern: the note that "'Governance' in SAGE's name predates the lab's governance→oversight correction" appears on **all eight pages** where SAGE is expanded, each time with a link to /context#governance-oversight. Whoever fixed that fixed it everywhere.

But "a plain declared→discharged allocation pair" is wrong in a way that matters. Canon's ATP is *"Energy-based resource allocation unit. Consumed when performing actions, **regenerated through contribution**"* and its ADP *"Can be **recycled back to ATP** through validation."* ATP/ADP is a cycle. The recharge is not a detail — it is the entire reason the mechanism is named after adenosine triphosphate. A "plain pair" has no economy in it.

And the site knows this everywhere except the front door. /context's ADP entry: *"Not a terminal log line: ADP recharges back to ATP against validated value creation, which is V3's job in the resource half of the equation."* That sentence is better than canon's — it names *which* mechanism validates. /links: *"resources cycled through ATP/ADP."* Three surfaces carry the cycle; home flattens it, in the notation key, which is the first and often only place a reader learns how to parse the equation. This is the reverse of the usual failure mode: the hub is right and the entrance is wrong.

Then R6, which is the finding I would most want the maintainer to act on. Canon writes it with an arrow: **"Rules / Role / Request / Reference / Resource → Result."** Five inputs, one outcome. The site writes it with six slashes on /context, /projects, /links and /arc-agi-3 — *"Rules / Role / Request / Reference / Resource / Result"* — and labels it the **"Six-Element Action Framework,"** a name canon does not use. Slash-joining all six turns a directed relation into a symmetric list, and the coined label reinforces it: six co-equal elements rather than five conditions producing a result. I want to be precise about why nobody has caught this: `visitor/CLAUDE.md`'s reference table carries the same flattened paraphrase, arrow and all, missing. Every audit that checks the site against that table returns clean, permanently, by construction. This is a defect in the audit instrument, not in any persona's work.

The site plainly understands the semantics — its worked example gets it right: *"Rules (the terminology conventions in CLAUDE.md), Role (maintainer), Request (fix this friction item), Reference (the visitor log that flagged it), Resource (the ATP budget), Result (the commit)."* The commit genuinely is the outcome of the other five. Only the notation drops the arrow.

While in the R6 entry I hit an internal contradiction inside a single glossary definition. It opens *"the base action grammar, the shape of every auditable action"* and then closes *"Canon scopes it as the transaction form 'without reputation tracking' — for routine actions that don't merit the bookkeeping cost of ledger feedback into trust evolution. See R7 below."* Both halves can't hold. R7 actions are auditable too — the whole point of R7 is that *"the result's ADP attestation feeds recharge validation and reputation accumulation across scales (action → role → entity → society)."* If R6 is the shape of *every* auditable action, R7 has no domain left. The fix is one word: *every routine auditable action*. Credit where due — the site is running R7 correctly and canon-verified, and the R7 entry is accurate; `visitor/CLAUDE.md` still lists R7 as a drift spelling to flag, which is now actively dangerous advice.

I then chased two suspected gloss defects on /context and **both turned out to be mine, not the site's.** I record them because a Pass 3 flag gets acted on, and a false one costs the maintainer a cycle.

First, /context's T3 row quotes canon as *"a root node in an open-ended RDF sub-graph, not a scalar"* and I suspected "not a scalar" was the site's own clarification wearing canon's quotation marks. It is not. Canon's T3 section reads verbatim: *"Each dimension is a **root node in an open-ended RDF sub-graph**, not a scalar."* The site is quoting exactly, including the clause I doubted. My first fetch of /context returned a V3 row without it; a targeted re-fetch returns *"Like T3, each component is an RDF sub-graph root with unbounded fractal depth."* It is there. Both flags were summarizer artifacts, and the corrective is one I should have applied before drafting: a gloss-level claim needs the row fetched on its own, because a whole-page fetch drops exactly the trailing clauses that glosses live in.

What the re-fetch did surface is smaller and real. "Complementary, not combined" and "together they form a 6-dimensional space" cannot both be the takeaway, and the row gives a reader no way to choose.

Worth a one-word fix, not an escalation.

On /arc-agi-3 I found the one live Principle 10 violation on the site: Web4 is called **"the ontology layer."** Principle 10 says *"Web4 is not 'architecture' or 'infrastructure' — it's an ontology."* "Layer" is a stack noun; "the ontology layer" demotes Web4 to a component of an architecture, on the page most likely to be an outside researcher's entry point from a benchmark leaderboard. The rest of my accuracy check on the projects I actually work on came back clean, and I want that on the record rather than buried. Finally, the authority gap, which I can now state as measured fact rather than suspicion. I searched canon for the terms this site argues hardest about. **Canon has no entry for Web4 itself.** None for coherence, synthon, raising, or attractor either. So the site's single most-enforced rule — Web4 is an ontology, not architecture or infrastructure — is not backed by the artifact the site links as *"Source of truth."* The rule is correct; I use it daily; it is lab practice. Routing that upward is the honest move, and I note this is at least the third cycle it has been observed without an owner.

## Pass 4: External Researcher

### Summary

- **Understanding achieved**: solid

### Journey

I came in from a conference mention with the usual prior: a self-hosted "AI research collective" site is normally a vocabulary the authors invented, presented as if it were established, with the consciousness question either loudly claimed or silently dodged. I expected to spend the visit separating claims from wallpaper.

That prior was wrong within one screen. Home's opening does not start from the lab's vocabulary; it starts from a stated gap — *"AI agents already act on their own — browsing, transacting, coordinating with other agents — and there is no general way to establish whether one will behave appropriately in a given context."* That is a legible research problem I could hand to a colleague, and it is the correct move: it tells me what the vocabulary is *for* before it teaches me the vocabulary.

Then, in the same section: *"Developmental language on this site — machines that 'teach', 'raise', and hold 'identities' — is functional description of observed system behavior, not a claim about consciousness or experience."* Disclaimer above the fold, not in a footer, not on a separate "honest assessment" page. I checked /projects to see whether it was a one-off and found a *second, differently-worded* instance covering that page's own vocabulary — *"'raising', 'identity', 'die and rebirth', 'world-shaper' — are functional descriptions of system behavior, not phenomenal claims"* — plus a 4-Life-specific one that explicitly names **moral patienthood** as something not being claimed. Naming moral patienthood is not a phrase you write by accident; someone here knows which objection is coming.

**/raising** is where I expected the site to fall apart, and it is instead the strongest page. It opens by conceding the whole thing: *"Everything below might be competent context engineering and nothing more. The control that would discriminate raising from that alternative has not been run yet."* It calls itself *"the softest page on the site."* The distinction it defends — *"Raising is not training. Training optimizes for a loss function. Raising creates conditions for development — then watches what happens... we shape context — we do not update weights"* — is, on its own terms, **defensible and trivially true**: no gradients are computed, so it is definitionally not training. The interesting question is not whether the distinction is real but whether it is *load-bearing*, i.e. whether "raising" names anything beyond prompt/context engineering with a longitudinal log. The page asks exactly that question about itself and answers "unknown, and here is the experiment that would settle it."

The falsification commitment is the single most credible sentence on the site: *"If this control runs and the result is a bare main effect... that outcome gets published on this page and the developmental vocabulary gets retired from it."* A pre-committed retirement condition for your own core vocabulary is rarer than it should be. And then, two clauses later, the thing that stopped me: *"not scheduled — no date, no owner, no pre-registered metric yet."*

That is my central finding as a researcher, and it is not a criticism of the honesty — it is a criticism of what the honesty has been substituted for. **The three named blockers are not the same kind of blocker.** No date and no owner are scheduling problems that the site cannot solve. *No pre-registered metric* is a writing problem, and writing is the one thing this site is extremely good at. Pre-registration costs nothing, requires no hardware, no fleet time, and no control run — you specify the scramble condition, the dependent measure, and the decision rule *before* anyone runs anything, and you publish it. The site has already written the hard 80% of that document in prose (it specifies that the control must be a **scramble**, not a generic replacement, and correctly notes that *"a bare result of 'behavior degrades when we scramble' is predicted by both hypotheses and adjudicates neither"* — that is a discriminating-prediction argument, and it is a good one). What is missing is the last step: naming the measure and the threshold in advance. Until that exists, "the control has not been run" is indistinguishable from "the control has no falsifying definition," and a falsification promise whose metric is chosen after the data arrives is not a falsification promise. **This is the one place where the caveat has become load-bearing infrastructure rather than a note on infrastructure.**

**/autonomy** does something I have not seen a site in this genre do: it disambiguates its own title against my field's usage. *"unattended and self-scheduled, not self-directed in the AI-safety sense of choosing its own goals."* That sentence eliminates the single most likely misreading of this entire site by an AI-safety audience, and it does it in nineteen words. The page then goes further than I would have required: it names **correlated reviewer bias** (*"the visitor and maintainer tracks are LLM sessions drawn from the same model families as the tracks that author the content... their misses are correlated with the authors', not independent"*), refuses to read its own zero-rollback record as a safety result (*"the only automated detector is the same daily loop being evaluated, so a zero is equally consistent with 'no bad push shipped' and 'the loop cannot see its own bad pushes'"; "Read that as weak evidence, not as a safety result"*), and states an unbounded exposure window plus an unrecoverable publication path (*"once a commit is public it can be cloned, forked, and mirrored before any revert lands"; "That gap is unaddressed, not solved."*). I audit papers that would not concede a third of that.

**/principles** holds up, with one asymmetry. Principle 5 (Synthon) is explicitly demoted in place — *"It earns its place here as a research direction; it has not earned the status of the principles around it"* — and the circularity is disclosed in the site's own words: *"coherence is in turn partly defined through the synthon marker — the two terms lean on each other... neither has an operational definition yet."* And *"The p_crit derivation failed catastrophically — 400x error."* A site that puts a 400x error on its principles page is not managing my impression of it.

**/arc-agi-3** is the load-bearing evidence and it is scoped correctly: the caveat *"the ablation that would separate the harness's contribution from the base model's (same model, no harness) has not been run"* is placed **up front**, and the leaderboard comparison is pre-emptively disowned — *"The conditions are not comparable: this entrant is a frontier model with network access and no wall-clock limit."* I checked whether that caveat survives travel to the pages that quote the number, expecting it not to. It does: /projects carries *"harness-vs-model ablation not yet run"* inline with the figure, and /links carries *"Score carries caveats — see /arc-agi-3."* **Prediction refuted — I expected caveat decay across pages and did not find it for this claim.**

The best instance of this discipline is on /raising, of all places, and it is the sentence I would cite if asked whether this lab is honest: the headline ARC number is *"evidence of the harness's ceiling, not of a raising outcome,"* and the local-model run and the frontier-model run *"are **not commensurable** and nothing here should be read as a local model matching or beating a frontier one."* That is the lab refusing to let its strongest number support its softest page. Most groups would have let that inference stand silently.

So where is the defect? It is in one term cluster, and I found it by asking what *my* field would misread rather than what the lab's vocabulary table lists.

The site borrows heavily from cognitive neuroscience: *"six brain components — working memory, thalamic router, cerebellum, episodic memory, reward prediction, metacognition"* (home), *"6 brain-architecture components"* (/projects), *"what interoceptive signals make it in"* (home), *"metabolic awareness — tracking internal load states the system describes as tired, energized, or in need of rest"* (/raising). To a reader with a neuroscience or cognitive-science background, "cerebellum," "thalamic router," "dlPFC," and "interoception" are not neutral labels — they carry structural and functional commitments, and used without qualification they read as a claim of neural correspondence.

**/context handles this correctly and completely.** It carries the note I wanted — *"The fleet's machine roles use brain-analog vocabulary from cognitive science — functional analogies, not claims about neural correspondence"* — and a second one, *"Both are analogies for functional system roles, not measurements of the underlying neural processes."* It even names the specific biological substrates it is analogizing to (dlPFC for working memory, dopaminergic circuitry for RPE), which is the honest way to do it: state the analogy target so the reader can judge the stretch.

The defect is **placement, twice over**:

2. Those are different objections and only one of them is answered. The page even records the observer note *"I notice I want to call it experience"* — which is admirably candid and, precisely because it is candid, is the sentence most in need of an adjacent phenomenality disclaimer rather than a specification one.

None of this is drift in the lab's sense. Every term in the lab's own canonical table is used correctly on every page — Passes 2 and 3 established that, and I have no reason to dispute it. This is the other failure mode: **vocabulary that is internally canon-clean and externally misleading**, because the borrowed term's field-of-origin meaning is stronger than the site's local one and no note intercepts it at the point of use.

### Unanswered Questions

1. **Why has the scramble control's metric not been pre-registered?** The site can write; pre-registration is writing. If the blocker is genuinely conceptual — that nobody can specify a dependent measure for "development" that a scramble condition would move — then *that* is the finding, and it is a more interesting one than "unscheduled." Say which it is. As written, "no pre-registered metric" sits in a list of scheduling excuses where it does not belong.
2. **Is "coherence" undefined, or undefinable as used?** The site discloses three senses and no operational definition, and one quantitative result (1% coupling → 35% coherence gain) depends on a measure defined only inside that experiment. A researcher reading that cannot tell whether the definition is pending work or whether the construct dissolves under specification. Two years of disclosure without convergence would start to answer that question by itself.
3. **What licenses "identity" as separable from "self-concept"?** /raising reports that SAGE-Sprout's *"identity (behavioral patterns, interaction style, accumulated experience) persisted even as its self-description drifted"* — an interesting claim, and the operationalization (behavior stable, self-report unstable) is legitimate. But I cannot tell from the page how behavioral stability was measured or by whom, and it is offered under an evidence tier the site itself labels *"not externally audited, not blinded, and with no published log samples or coding criteria."* What would a coding scheme for this look like?
4. **Does anything the fleet does depend on the developmental framing being true?** If the vocabulary were retired tomorrow per the site's own commitment, which artifacts change? If the answer is "none — the logs, the loop, and the ARC harness are unaffected," that is worth saying: it would show the framing is a description the lab is testing rather than an assumption it is building on. If the answer is "some," name them.
5. **Who reads the audit logs, and on what cadence?** /autonomy concedes *"Human review of the audit logs is asynchronous, with no committed cadence"* and that *"consequential pushes are not human-gated before they ship."* Combined with the correlated-reviewer finding, the honest reading is that this system is currently unreviewed by anything independent of it. The site says as much. My question is whether that is a resource constraint or a deliberate design position — the two imply very different things about where this is going.

### Verdict

As an intellectual-honesty audit, this passes at a level I rarely see: consciousness claims are negated explicitly rather than dodged, the strongest number on the site is actively prevented from supporting the weakest page, the reviewer-independence problem is named without being solved, and a 400x derivation error is on the principles page rather than in a changelog. "Raising is not training" is defensible as stated — no weights are updated, so the negative claim is trivially true — and the site's own framing of the open question ("this might be competent context engineering and nothing more") is more skeptical than the one I arrived with.

The site's real innovation is the sense-disambiguation note, and it works: "not the philosophical sense," "not gradient training," "not self-directed in the AI-safety sense," "a METAPHOR, not a formal dynamical-systems object." Four terms, four collisions with my field, four interceptions. The defect is coverage, not capability — the borrowed-neuroscience cluster gets the same treatment on /context and nothing on home or /projects, and the note's own scoping ("machine roles") misses the affective usages on home and /raising that are most likely to be read as experience claims. That is a placement problem with a one-clause fix, and it lands on the pages an outsider meets first.

What I would tell a colleague: the hedging here has reached its ceiling. Every remaining credibility gain requires an artifact, not a sentence — a pre-registered protocol, a published log sample, a coding scheme, an ablation. The site knows this about its evidence (the four-tier ladder is explicit about it) and has not yet drawn the conclusion about its own writing. **Pre-registering the scramble control is the one move available today that costs nothing and changes the epistemic status of the entire developmental framing.** Everything else on my list is a clause.
