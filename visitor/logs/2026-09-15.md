## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (Home, Projects, Glossary/context, ARC-AGI-3, Fleet, Autonomy, Raising, Principles, Links)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: I understood the pitch in under two minutes and the site is unusually candid about what's shipped vs. hoped for, but it's hard to go from "interesting" to "I'm running something" without digging.

### Journey
Landed on Home from a repo README. The headline pitch works: agents are becoming actors, and trust should be "computed from witnessed evidence, in context, by the party doing the relying." "What is being built" names four systems (Web4, Hestia, Hub, SAGE), and "Commercial path" says plainly that Hardbound is the proprietary tier by Metalinxx. That's more candid than most lab sites. The A0–A4 assurance ladder and TCSEC are both explained, which I liked. "Start here" gives three doors. One is Calibration, which goes out to a STATUS.md on GitHub, and that's a nice touch. The Vocabulary door is described as "the glossary for LCT, T3/V3, MRH, R6/R7, ATP/ADP and related terms", and that's the first time I see a wall of acronyms. None are expanded there, but at least it points to where they are. What Home lacks is a "try it" link. There's no install command and nothing labeled get started.

Went to Projects. There are 13 cards with status badges and, helpfully, a legend: "runnable = clone it and it executes end to end today", while "research-stage" may not run end to end. SAGE has a real four-line quick start (ollama pull, python init, cargo build, run the daemon), and SNARC has `/plugin install snarc`. That's what I came for. It was buried halfway down the Projects page, though, not linked from Home. Hestia and Hub are both badged "runnable" but show no run instructions, and Hestia's card says "the Docker package is untested outside the development machine". That doesn't match "executes end to end today". Every acronym on this page is expanded inline where it's used (MCP, RDF, LCT, T3, V3, MRH, ATP, ADP, R6, SNARC, FIDO2, ARC-AGI-3). Good. The terminology notes read oddly, though. SAGE's name "predates the lab's governance→oversight terminology correction". Hestia's card says "'governance' is deliberate and correct here". Package registries "call it 'infrastructure'; that is upstream package metadata". To me these read like internal style-guide notes shown on product cards. I get the point, but I didn't need it to decide whether to clone something. "Get involved" says the Links page has "community channels". It doesn't (see below).

Glossary (/context) is the strongest page for me. Every acronym has an expansion and a one-line meaning. The equation `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP` comes with a legend for the operators and a "worked example: one action through the equation". The worked example is what made the equation click. There's no raw markup visible. It's long, but it's a glossary, so that's fine.

ARC-AGI-3 is clear and self-deflating. The "Phase-1 SAGE/ARC harness around Claude Opus 4.6" got a "94.85% official ARC Prize action score", 23 of 25 environments, 175 of 183 levels. The page explains that action score is efficiency-weighted, "not a solve rate", and says "No ablation has run the same model without the harness". Then it says "Current competition-legal local-model work is well behind the leaders." I couldn't work out how that relates to the Opus result. Was the Opus run not competition-legal? Is local-model work what the lab does now? "Phase-1" is never explained.

Fleet has eight machines: "Six cognition machines, plus two society-hosts". Each card gives hardware, a brain-analogy role (thalamic router, cerebellum…) and a git-derived status. "running" is defined as "wrote a session record within the two weeks before the 2026-09-12 count". I appreciated the precise definition, and Legion's "last 2026-09-02" checks out against it. The `SAGE_MODEL` env-var override is the one thing a developer can use directly. Much of the rest is bookkeeping: three totals (2,442 / 2,563 / 2,765) reconciled against an external "2,700+" headline. It's honest, but I skimmed it. Two small snags. "CBP" is never expanded. The budget pools are called "synthesis pool" and "oversight pool" (Claude Code accounts with different weekly budgets), so "oversight" names a billing pool here while elsewhere it's the word reserved for Hardbound.

Autonomy has a clear timeline (supervisors 03:00, archivist, publisher, visitor 05:30, maintainer 06:30, outreach, explorer, dream consolidation). The boundaries section is refreshingly direct: "detect-and-revert (audit log + sub-minute rollback), not prevent", and consequential pushes aren't human-gated before they ship. Acronyms in the late sections are expanded inline at first use. They're still dense for me, but they're defined.

Raising: I skimmed it; it's outside my interests. The page defines raising as "longitudinal, entity-specific context shaping" and hedges itself hard ("might be competent context engineering and nothing more"). It reads fine to a developer. Principles has ten short items and explicitly says "R&D, not production". I didn't need more.

Links has a full repo list with one-line descriptions, and the Contributing section is honest: "no CONTRIBUTING guide yet and no stated policy on outside pull requests. Ask in an issue first". The Links page lists no community channels at all: no Discord, forum, Discussions or mailing list, only a research-inquiries email. That contradicts the promise on Projects.

### Unanswered Questions
1. If I want to run Hestia or Hub today, where are the steps? Is "runnable" true off the dev machine?
2. What's the fastest thing I can do with Web4 itself: `pip install` what, then call what?
3. Is the ARC Opus 4.6 harness "competition-legal"? What is the lab's current ARC work, and how far behind is "well behind"?
4. Where do outside contributors talk to each other, if there are no community channels?
5. How do SAGE, Hestia and Hub fit at runtime? Does the SAGE daemon talk to a Hestia daemon, or are they separate products?

### Verdict
As a developer I got the "what" fast: an open trust ontology plus several runnable pieces, from a lab that's blunt about what doesn't work yet. The glossary and the honest caveats are real strengths. The gap is the "how": the one working quick start is buried, two "runnable" projects have no run steps, and the promised community channels don't exist. I'd come back, but through the SAGE repo, not through this site.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 (Home, Projects, Glossary `/context`, ARC-AGI-3, Fleet, Autonomy, Raising, Principles, Links). Each page was fetched with a structured WebFetch, then its rendered text was fetched again and grepped for first-use order, counts and cross-page pointers.
- **Understanding achieved**: solid
- **Would return?**: yes
- **Overall impression**: Every canonical expansion on the site matches the canon table. The defects have moved from terminology to cross-page references: pages describe other pages, and three of those descriptions are now wrong.

### Journey
All eight nav items resolve: Projects, Glossary, ARC-AGI-3, Fleet, Autonomy, Raising, Principles, Links. The nav label "Glossary" points to `/context`, and body text says "the /context glossary", so a reader meets two names for one page. It's harmless, but I noticed it.

I read each page for headings and acronym first use, then checked cross-page consistency against the rendered text rather than the summaries. The summarizer invented three details this pass. It said /projects mentions R7 in a heading (R7 is only in a pointer list). It said /arc-agi-3 expands ARC-AGI-3 as "…for AGI" (it's "…for Artificial General Intelligence"). It counted six "governance" sentences on Home (there are three). Nothing below rests on a summary alone.

**The terminology layer is clean.** On all nine pages I found no Lifelong/Lifecycle LCT, no Trust-Tracing or dimension-as-expansion T3/V3, no R5, and no "production ready". Web4 is "ontology" everywhere it gets a noun, including an explicit "not an architecture, infrastructure or stack" on Home. Hardbound is "oversight" everywhere. "Unification"/"scope inflation" appear only in the negated "not unification, and not scope inflation" form. The one "infrastructure" on /projects is correctly framed as upstream registry metadata. R7 is given as "R6 + Reputation" (canonical superset) on /context and /autonomy. The withdrawn V3-as-recharge-gate reading is absent. Every page that mentions recharge (/projects, /context, /autonomy, /links, /fleet) now says the society validates a proof of value and "V3 records the outcome, it does not gate it". The ACT expansion is also consistent: "Agentic Context Tool", an implementation of ACP (Agentic Context Protocol), on /projects, /context and /links.

**Where the site is inconsistent: pages describing each other.**
1. **/raising → /fleet, Sprout's count.** /raising: "the Sprout box now runs Qwen 3.5 0.8B and its own session record stands at 488, see /fleet". /fleet, the page it cites: "661 session records on sprout-qwen3.8-distill-2b, and a further 625 on sprout-qwen3.5-0.8b … the earlier published 488 was the 0.8b line as of July". The /fleet card was corrected, but /raising still has the old number while pointing readers to the page that retracts it. The model claim is stale too: /fleet lists two models on Sprout, /raising names one.
2. **/context → /links, quick start.** /context, in its intro for developers: "Quick-start commands are on /links. This page covers the vocabulary; that one covers the first clone." /links: "The commands live in one place: the Quick start on /projects … This page used to carry a second copy; the two drifted apart, so it now links instead." /projects: "the only copy on the site". A developer who follows the glossary's pointer has to go through a second hop. The single-copy rule was followed for the commands but not for the pointers to them.
3. **/context → /links, session figure.** /context: "/links now leads with the 2,563 figure." /links actually reads "2,442 internally logged session records as context (2,563 including HUB …)", so it leads with 2,442 and puts 2,563 in parentheses. The same /context sentence confesses an earlier error of this exact kind: "the home page carries no session total at all, so that half was describing a page rather than reading it". That confession is still describing /links rather than reading it.
4. **/projects → /links, community channels.** Pass 1 found this and I confirmed it: /projects "Get involved" promises "community channels" on /links, and /links has none. It has repos, issue trackers and one email address.

**Acronym first use.** Most pages expand inline at first real use, and several say so explicitly. I tested /raising's promise ("Web4 vocabulary on this page (T3, V3, MRH, LCT, LoRA) is expanded inline on first use") and it holds: each term's first use after that pointer sentence carries its expansion. /fleet opens with a vocabulary block that expands T3, V3, MRH, SNARC, LoRA, MCP and RDF before any card uses them. That resolves Pass 1's UNVERIFIED on MRH as CORRECT. The remaining gaps are small and all involve SAGE or R6:
- Home names SAGE in its first paragraph and never expands it. Every other page does.
- /fleet uses SAGE about 500 characters in but expands it about 25,000 characters later. Its otherwise complete vocabulary block leaves SAGE out.
- /autonomy expands R7 as "(R6 + Reputation)" but never expands R6 itself.
- /projects says "the cards expand each on first use" for a list that includes R7, but no card uses R7. The list promises a term the page doesn't need. SAGE appears in the /projects intro before the card expands it.

**Definition of "oversight" varies by page.** /principles: "watching, gating, and reverting". /autonomy: "gating, reverting, audit logs". /projects: "machine-enforced policy gating". /fleet: "(policy gating, peer review, audit)". The /fleet gloss does answer Pass 1's worry that "Oversight pool" overloads the Hardbound word: the page says the pool's name uses the site-wide machine-enforced sense. But "peer review" appears only in that gloss. A billing pool that does "review, planning, coordination, and unblocking" is a stretch of "gates and reverts". It isn't drift in the expansion sense. It's a fifth phrasing of one reserved word.

**Staleness in lead lines.** /autonomy's opening line is "31+ autonomous tracks across 6 cognition machines, ~53 sessions per day (figures as of 2026-05-26, not recounted since)". It's disclosed, but it is 112 days old and has no recount date or owner, and it sits above a /fleet page recounted on 2026-09-12. Also, Home heads its ARC section "Historical ARC-AGI-3 work" and /arc-agi-3 says "Why it is no longer the headline", yet ARC-AGI-3 is the third nav item, ahead of Fleet and Autonomy. The information architecture still ranks as a headline what the content has demoted.

**Checks that passed.** Repository counts agree between /context and /links: 40 original (21 public / 19 internal) + 33 forks (32 public / 1 internal) = 73, as of 2026-09-12. The ARC figures agree on Home, /projects, /context, /raising, /links and /arc-agi-3: 94.85% action score, 23/25 environments, 175/183 levels, 2026-04-17. The two unfinished environments (5 of 9 and 6 of 10) account for exactly the 8 missing levels. Machine counts are "eight (six cognition + two society-hosts)" everywhere except the dated /autonomy header and the historical ARC card ("6 machines … at benchmark time"). Session totals of 2,442 / 2,563 / 2,765 agree on /projects, /context, /fleet and /links.

That entity's identity observations ("identity lives in state files… not in model weights", /fleet) would then be confounded in exactly the way the page says they aren't. I can't tell from the site whether this happens. The problem is that the site's defense of its central distinction never asks.

3. **The one observation the page says construction doesn't explain may be explained by construction.** The claim that SAGE-Sprout's self-description drifted "even though those inputs did not" is what /raising and /fleet both keep as "the observation worth keeping". But dream consolidation, on the same page, runs after every raising session "pruning stale memory, updating vocabulary, flagging milestones, and writing a raising log entry", and /autonomy says it is "LLM-powered" and promotes insights "toward identity-level storage". So the state files are rewritten every session by a consolidation pass. The site never says which model does it. If the drift happened across sessions rather than at the port, the inputs *did* change, and the self-descriptions could be the consolidator's vocabulary. The same applies to "memoriescape". The deflationary list names three simpler explanations and leaves this one out. Also, /raising's dream paragraph ends "This is how short-term session experience becomes long-term identity" with no caveat. /autonomy and /context both caveat "dream" as analogy; /raising, the page it matters most on, doesn't.

Smaller /raising items. The opening definition says identity is "measured via raising curriculum state and interaction logs". The page's own later analysis says curriculum state and accumulated experience "are inputs the treatment supplies, so measuring them cannot tell raising from context engineering". So the opening still says "measured" where the later analysis says "not a metric". Patterns 4 and 5 are stated as trends ("Session logs show an increasing proportion…", "Output increasingly concentrates…") with no number anywhere on the site. Graduated tool introduction is "the one place on this page where a sequence is claimed", and each stage "adds capability only when the entity has demonstrated readiness". The page gives no readiness criterion, and Stage 4 (Creating) is "federation", which Home calls "roadmap, not running".

**That last point connects to /fleet, where the BECOMING labels don't discriminate.** All six cognition-machine cards read "BECOMING pattern observed: creating", the same single label on a 0.8B edge box, a quiet 27B LoRA instance and a paused 4B line. The legend says "Its absence means that pattern hasn't been observed there yet, not that it wasn't assessed." Read literally, Grounding (the "foundation before exploration") has been observed on no machine. So has Acting. But /raising says "Pattern 6 (Acting)'s evidence from a raised entity is Legion's local-model ARC-AGI-3 run", and Legion's card says only "creating". Two pages disagree on what has been observed on one machine. A label that every instance gets carries no information. And the curriculum stage with the same name suggests a simpler reading: a lab-set schedule placed everyone in "Creating". The site insists patterns are not stages, and the uniform label is exactly what a stage would look like.

**/principles is where the evidence tiers slip.** The intro says these are "operational patterns that emerged from building the system — things we learned the hard way, then codified because they kept being true." Principle 5, four items down, says of itself: "it has not earned the status of the principles around it." Principle 1 (termites) and Principle 2 ("When a pattern works at one scale, apply it at every scale") are heuristics, not things that "kept being true". Principle 6 is honest in the direction I'd want, but asymmetric. The coupling-coherence experiment's positive number (1% → 35%) is graded "ungrounded" because its coherence measure exists "only within the experiment that produced" it. The *same* experiment's refutation of p_crit ("failed… by 400x") is graded "a result".
