# 4-lab Visitor Browse Log — 2026-09-28

## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (Home + 8 nav pages; the nav lists nine, not eight)
- **Understanding achieved**: partial
- **Would return?**: maybe
- **Overall impression**: A serious, self-critical lab site whose quick start is the only place on the internet that tells me how to run its flagship project, and whose home page throws six acronyms at me before any of them is defined.

### Journey

I arrived from a GitHub README, so the first thing I wanted was "what is this, and can I run something." The home page opens with a thesis ("trust should be computed from witnessed evidence, in context, by the party doing the relying") and a four-project list: Web4, Hestia, Hub, SAGE. That list is readable — Hestia is "local governance for humans and AI agents from multiple vendors", Hub is "a Rust society runtime", SAGE is "persistent-agent research ... around frozen model weights". Fine. But then the "Start here" block says "The glossary for LCT, T3/V3, MRH, R6/R7, ATP/ADP and related terms" — six acronyms, none of them expanded anywhere on the home page (I checked the rendered HTML: "Linked Context", "Trust Tensor", "Markov" are absent). I get that the glossary is one click away, but a developer scanning the landing page sees an alphabet soup before seeing a single line of code. There is also no code on the home page at all; the first install pointer is a link to /projects.

/projects is where the site earns its keep for me. Thirteen project cards with status pills ("public, runnable" / "public, research-stage" / "private" / "stalled") — this is exactly the triage I wanted. The Web4 card expands every acronym inline the first time it's used, which is good, but the card is a single ~250-word paragraph with four nested asides; I had to read it three times to find the actual noun ("the shared language everything else speaks"). The Quick start at the bottom is the best thing on the site: one `<pre>` block with a clone → `ollama pull` → `python3 -m sage.instances.init` → `cargo build` → run-daemon sequence for SAGE, `pip install web4-core` for Web4, and honest "NO FIRST-RUN PATH YET" / "STALLED" labels for Hestia and ACT. I checked what I could: `sage/instances/init.py` and `sage-rs/` exist in the public SAGE repo, and `web4-core` 0.3.0 is on PyPI. The commands look real. I did not run them.

The thing that bit me as *this* persona: the quick start says, in its own comment, "The SAGE README has no setup section — these steps are maintained here, not transcribed from it." I confirmed it — the SAGE README lists `install_sage_nano.sh`, `setup_sage_env.sh` and two Dockerfiles by name with no sequence, and points evaluators to a "Five-minute audit" instead. So a developer who found the lab the way I did (via the repo) never sees the install path unless they happen to click through to this site, and this site's nav gives no hint that "Projects" contains it. The Hestia README is the same story: CLI examples (`hestia init`, `hestia delegate grant ...`) but no install, and the README describes it as "Universal Web4 presence for humans and AI" while the site card calls it a "governance daemon". Both descriptions are probably true; a newcomer reading them side by side would not be sure they are the same project.

/context (nav label "Glossary") is enormous — the fetch estimated 15–18k words. The "at a glance" table at the top is genuinely useful and has everything I needed (LCT = Linked Context Token, T3 = Trust Tensor, etc.). But it is not sorted, not searchable, and grouped by relationships I don't yet have. Ctrl-F got me there. Below the table there are 25 more sections; I read the equation (`Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP`, with `/` = "verified by", `*` = "contextualized by", `+` = "augmented with") and the worked example, then stopped.

/arc-agi-3 is clear and short: a spring-2026 94.85% ARC Prize action score, 23 of 25 environments, a scorecard link, and a plain "why it is no longer the headline" section. I believed it more because of that section.

/fleet reads as an ops status board: eight machines, hardware, brain-analog role names ("thalamic router", "cerebellum/habit compiler"), session-record counts per line, and status labels like "publishing stopped by policy" and "instrumentation broken". The counting is careful to the point of distraction — three different totals (2,499 / 2,620 / 2,846) explained in one sentence. As a developer I wanted one number and a date.

/autonomy has the daily timeline I was expecting from the README (03:00 supervisors → 04:00 archivist → 04:30 publisher → 05:30 visitor → 06:30 maintainer → 07:00 outreach → 08:00 explorer → dream consolidation). Its "what they do not guarantee" section admits the tracks "edit their own briefs" and that "the only automated detector is the same daily loop being evaluated". That's the kind of thing I'd normally have to dig out of a postmortem.

/raising is the page furthest above my ceiling. BECOMING is six patterns (Grounding, Sensing, Relating, Questioning, Creating, Acting), "interactive selection, not training", and a long "deflationary alternative" section saying all of it "might be competent context engineering and nothing more" and that the discriminating control "has not been run yet". I respect that but couldn't evaluate it. Numbers like "1,217 records with byte-identical tutor turns" landed as evidence of rigor without my knowing what they meant.

/principles is ten short principles, no headings between them, one link. "R&D, not production" and "Document failures" ("the p_crit derivation failed catastrophically — 400x error") are the ones a developer notices. The license list (AGPL-3.0 for SAGE/web4/hestia/4-hub/4-life, MIT for snarc/membot, Apache-2.0 for ACT, MIT-0 for the ARC harness) is the single most actionable paragraph on the site for me and it's buried on the philosophy page.

/links: a flat list of sites and repos, a contact email, and a pointer back to the /projects quick start. 4-gov.org loads (title "Computable Accountability | Governance for Agentic Entities"). Nothing on this page told me why I'd go to 4-gov rather than /context.

### Unanswered Questions
1. If I run the five SAGE quick-start commands and get a dashboard at localhost:8760, what will I see, and what is the first thing I'd change to make it "mine"? The site says what SAGE studies, not what a fresh instance does in its first hour.
2. Why is the SAGE README silent on setup when the lab clearly knows the steps? Is the site intentionally the canonical install doc?
3. Are Hestia's "governance daemon" and the README's "universal Web4 presence" the same binary or two components of one repo?
4. What does a developer contribute to? "Get involved" on /projects is a quick start, not a contribution guide; I saw no good-first-issue pointers anywhere.
5. Is 4-gov.org part of this lab, a sibling, or a downstream explainer?

### Verdict
This is one of the more honest project sites I've read — statuses are real ("stalled", "no first-run path yet"), caveats are everywhere, and the quick start is concrete and checks out against the repo layout. But the on-ramp is inverted for someone who arrives from GitHub: the install path lives only here, the repo README doesn't point to it, and the landing page leads with undefined acronyms instead of the one runnable thing. I'd come back if I hit the quick start first; I'd bounce if I hit the glossary first.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 (Home + 8 nav pages)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: Terminology is converged — every canonical expansion on every page matches the reference table, all 60 in-site anchor links resolve — and the remaining problems are structural: a home page that names the site's key project without its canonical noun, a 12k-word glossary with no table of contents, and about 45 dated inline corrections with no errata page.

### Journey

I did this pass the way I'd audit any doc set: nav first, then every page top to bottom, then a second pass over the rendered HTML with a script, because a summarizer is a witness, not a source of record (it told me R7 is unexpanded on /projects; the page expands it once, and it attributed the Hestia row's "'Governance' is deliberate here" note on /links to SAGE).

**Navigation.** Nine entries: the wordmark (/) plus Projects, Glossary (→ /context), ARC-AGI-3, Fleet, Autonomy, Raising, Principles, Links. Every nav label matches its destination's h1 except Glossary → "Glossary", which is fine, and Projects → "The Ecosystem", which is a mild mismatch. Every page has exactly one h1. Zero links use a raw URL as their visible text. All 60 internal `#anchor` links across the nine pages resolve to an element id on the target page; /context alone carries 65 ids, one per glossary row. This is the structural layer in good shape.

**Acronym discipline.** I counted whole-word uses and canonical expansions of 15 acronyms per page (table below). Every expansion string matches the reference: LCT is "Linked Context Token" on 7 pages, T3 is "Trust Tensor" with Talent / Training / Temperament as *dimensions* (never as the expansion), V3 likewise, MRH "Markov Relevancy Horizon", ATP/ADP "Allocation Transfer / Discharge Packet", R6 "Six-Element Action Framework: Rules / Role / Request / Reference / Resource → Result" (the arrow form, uniform on all four pages that expand it), R7 "R6 + Reputation". None of the known-drift strings (Lifelong, Lifecycle, Trust-Tracing, Minimum Response, Attention Token, Adaptive Trust, R5, "production ready") appears anywhere. The expansion-slot form that evades greps ("T3 (Talent / …)") is absent.

**First-use distance.** This is where the pages differ. /projects, /fleet, /autonomy, /raising, /principles and /links expand at or near first use. Home never expands eight acronyms it lists ("The glossary for LCT, T3/V3, MRH, R6/R7, ATP/ADP") and never expands TCSEC. /projects has a note saying "the cards expand each on first use" — and that note is itself the page's first use of R6, R7 and SNARC, roughly 2,000 words before their expansions. That is the exact pattern /raising already corrected on 2026-09-23 (its note now reads "Until 2026-09-23 this note said these terms were expanded inline on first use, and the note itself was their first use"). /raising's corrected note lists T3, V3, MRH, LCT as the Web4 terms used on the page, but the page also uses ATP once (in a quoted vocabulary list) without expanding it. /context, the glossary itself, uses SAGE in its intro about 2,800 words before the SAGE row, and its first table row (Web4) uses T3/V3 and MRH before their rows.

**Noun consistency.** In site voice, Web4 is "ontology" on every page that characterises it; where "substrate", "stack" and "infrastructure" appear they are quoted as upstream README wording and attributed (/projects, /context). Hestia is "governance daemon" on Home, /projects, /context, /links with an explicit carve-out explaining why. Hardbound is "hardware-bound oversight suite" on /projects, /context, /fleet, /autonomy, /raising, /links — and on Home it is "the planned proprietary enterprise assurance tier for hardware-bound identity, stronger fail-closed enforcement and audit-ready evidence packaging". The word "oversight" does not occur on Home at all (0 hits in the rendered text). That is not drift — Home doesn't call it governance either — but the landing page is the one place the canonical noun for the project is missing. /fleet's "Oversight pool — Account 2" heading carries a disclaimer that it is a registry label, not the machine-enforced sense.

**The T3/V3 relation.** /context's V3 row says T3 and V3 "together they form a 6-dimensional reputation space at the root level". Its T3/V3 section, further down, quotes canon saying T3 is "NOT: A 6-dimensional tensor (that's T3+V3 combined)" and glosses "not combined" as "not merged into one six-component tensor". A reader who does not already know the difference between a six-dimensional *space* and a six-component *tensor* will read these two sentences as contradicting each other. The "/" = "verified by" reading is labelled "the site's gloss, not canon's" on all six pages that use it (/projects legend, /context, /fleet, /raising, /links, /autonomy by reference); that is consistent.

**Structure.** /context is 11,879 words with 26 h3 headings directly under the h1 (no h2 level), no table of contents, and an "at a glance" table of ~55 rows grouped thematically but not sorted. /fleet also skips h1→h3. Heading elements carry ids on /principles (10/11) and /context (4/27, though the rows do); Home, /arc-agi-3, /fleet, /autonomy and /links have no heading ids, so nothing on them is linkable. All nine pages share one meta description (the same 8-machines / 40-repos sentence). Dated inline corrections — "Until 2026-MM-DD this page/card/note said…" — number 39 across the site (13 on /fleet, 12 on /context, 10 on /raising), plus 8 "Corrected 2026-…" and 4 "withdrawn". They are honest and I'd keep them, but there is no errata page collecting them, so a returning reader has to re-read every page to find what changed.

### Unanswered Questions
1. What does the developmental account predict that context engineering does not? The page says it cannot yet say. Until it can, "developmental descriptions fit better" is a vocabulary preference, and the site should call it that rather than a hypothesis.
2. Who is the intended reader of the 64-day-old unscheduled control? If it is the researcher, the page should say what it is waiting on; if it is the tracks, the page says they cannot schedule it. A disclosure with no addressee is a disclosure to nobody.
3. Why does the site's most safety-relevant sentence, "consequential pushes are not human-gated before they ship", sit under a heading called "Known oversight gap" on a page whose definition of "autonomous" says the tracks are merely "self-scheduled"? Which framing is the lab's considered one?
4. The identity metric separates two lines running the same model and script. Something in their contexts differs. Has anyone diffed the two identity files and asked whether the separation survives swapping them? That is one run, and it is the closest thing to the yoked control that exists today.
5. Is a null on the fixed-script lines evidence about raising at all, given the page's own statement that those lines do not run the method? If not, the honest summary is that raising as defined has zero quantitative tests, not two.

### Verdict
This is the rare lab site whose caveats cost it something: it discloses the LoRA line that breaks its own "always in-context" claim, calls one of its own sentences "the most self-serving on this site", and retracts a p-value that its exclusion rule manufactured. I would cite it as an example of honest reporting under self-review. But the honesty has a direction problem in three places: a null gets summarized as "leaning the other way", human-scheduled tracks get called "self-scheduled", and a metric result that the owner page qualifies gets restated unqualified on /fleet. And the one thing that would move any of this, a control the site has had specified since July, has no date, no owner and no prediction, and the page doesn't say how long that has been true. Write the prediction, date the gap, and this becomes a page I could put in a paper's related-work section without a footnote.
