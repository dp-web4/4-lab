## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (Home plus the 8 nav pages: Projects, Glossary (/context), ARC-AGI-3, Fleet, Autonomy, Raising, Principles, Links). I also opened the SAGE and web4-core artifacts the quick start points to.
- **Understanding achieved**: partial
- **Would return?**: maybe
- **Overall impression**: The Home page and the /projects quick start work well for a developer, and the quick start's paths match the public repo. Every other page is written as an audit trail of its own corrections, so "what is this?" gets answered underneath "what we got wrong last week."

### Method note
I read the pages as served HTML (curl, then tags stripped) and checked every friction item against that text. I did not rely on a model summary. My first WebFetch summary of Home was accurate about structure but reduced the page to a table, so it was only used for orientation. The quick-start checks used public GitHub raw files and the PyPI JSON API, which a developer clicking "Repo →" could also do.

### Journey
**Home.** The headline, "AI agents are becoming actors in the world. Trust and authority need to become first-class," tells me the topic in one line. The thesis sentence is the best on the site: "trust should be computed from witnessed evidence, in context, by the party doing the relying — not declared by a platform or asserted by the agent itself." The four project blurbs (Web4, Hestia, Hub, SAGE) are short and I understood them. Web4 is the vocabulary. Hestia puts several vendors' agents under one law on one machine. Hub is a society runtime. SAGE is agent research around frozen weights. The stats block is where I slowed down. "21 SAGE instances configured … 8 of them carry raising history" uses *raising* before any page has told me what it means. The **Start here** block, which is exactly what I want, sits at the very bottom, below the historical ARC section. Its "Calibration" link leaves the site for a GitHub STATUS.md without saying so.

**/projects.** This page has the answer to "what would I clone first?": SAGE, then the Quick start. I checked it against the public repo. `sage/instances/init.py` exists and accepts `--machine`, `--model` and `--operator-name`. `sage-rs` is a workspace with a `sage-daemon` crate whose default port is 8760 and which reads `SAGE_MACHINE`/`SAGE_MODEL`. `pip install web4-core` resolves to 0.3.0 on PyPI. The "What success looks like" paragraph ("An idle daemon in WAKE with an empty buffer is the correct first result") is the kind of thing that saves a developer an hour. The rest of the page is hard going. The Web4 card is about 330 words, mostly one sentence with nested parentheses and dashes. I finished it knowing the acronyms' expansions but not what Web4 does for me as a developer. The SAGE card spends more words on how its session count was recounted three times than on what the kernel does.

**/fleet.** The page is about 6,300 words, and the first machine card (Thor) starts about **2,070 words in**. Before it come the counting method, a migration clause, four "raising line" states, and an explanation of why subject-keyed commit tests are unsound. It is rigorous, but as a developer I wanted a table of eight boxes. The cards are readable once reached: hardware, model and state are clear, and the WSL2/Jetson/M4 mix is interesting. Each card is also a changelog ("Until 2026-09-18 this card read…"). The **Role:** field on every cognition card opens with "Curriculum phase: creating (by session count, not assessed)". That is not a role. The actual role ("Physics exploration lead", "Data czar…", "Edge demonstrator") comes three or four sentences later.

**/autonomy.** This is the clearest mechanism page on the site. The daily timeline (supervisors → archivist → publisher → visitor → maintainer → outreach → explorer → dream) is concrete, and the one-sentence split between tracks (Claude Code sessions on cron) and SAGE (on-device kernel) is exactly what I needed. The headline figure, "31+ autonomous tracks … ~53 sessions per day", is stamped "as of 2026-05-26, not recounted since", so it is almost four months old. It is honest, but it is the first number on the page.

**/raising.** It took 512 words to reach Pattern 1. The page calls itself "the softest page on the site" and sends me to ARC-AGI-3 if I want to check code. I appreciated that. I skimmed the BECOMING patterns and "The deflationary alternative". I can't evaluate this page, which it seems to expect.

**/principles.** It is short and readable, and the termite-mound line in #1 is memorable. #3 ("R&D, not production … Nothing here is optimized for deployment") sits awkwardly beside Home's **Commercial path** section and /fleet's pub card, which describes "Staging host for the first PUBLIC-facing Web4 hub" with gated go-live. The page may resolve this somewhere, but I didn't find it.

**/context (Glossary).** The nav says "Glossary" and the URL says `/context`. Both work, but it's a small surprise. "Glossary at a glance" promises "one-line definitions, scannable". In fact it is a **58-term table of about 5,270 words**. The median row runs roughly 90 words, the V3 row 272 and Substrate 262, and the hestia row alone is 220. The table is not alphabetical: `hestia`, `Hestia`, `A0–A4`, `Autonomous` and `Emergence` all come before LCT. I used ctrl-F instead of scanning. The page does point developers back to the /projects quick start as "the only copy on the site", and that is true: /links now links to it instead of duplicating it.

**/links.** This page is useful. It gives an honest repo count (40 original, 21 public), per-repo license guidance, a statement that there's no CONTRIBUTING guide ("ask in an issue first"), and a clear "Hands-on: start with SAGE." The "4-gov — Governance explainer site" entry is three words. 4-gov.org's own title is "Computable Accountability | Governance for Agentic Entities" and its meta description reads "Web4 — an open standard … from Metalinxx Inc." Nothing on 4-lab explains how 4-gov relates to Hestia, Hub or this site.

**/arc-agi-3.** This is the cleanest page. Status comes first, then what happened, why it mattered and why it is no longer the headline, then artifacts. The acronyms are defined in the first paragraph, and the affordance caveat is stated once and stated clearly. Other pages could follow this template.

### Unanswered Questions
1. What can I *build* with web4-core 0.3.0 today? None of the pages shows an API call or a five-line example. There is only the install line.
2. How do 4-gov.org (Metalinxx) and Hardbound (Metalinxx) relate to the open projects and to this lab? Is 4-gov an official Web4 explainer?
3. If I run the SAGE quick start, is my instance a "raising line"? What would I do next after "idle daemon in WAKE"?
4. What is the "prompt suggestions mechanism" on /autonomy?
5. Will outside PRs be accepted at all? "Ask in an issue first" is clear, but the eventual answer isn't.

### Verdict
The site passes the developer's two-minute test on Home and /arc-agi-3. It also gives a correct, repo-verified answer to "what would I clone first?": the SAGE quick start on /projects. Canonical terminology is clean on all nine pages. The cost is readability. Every other page puts its correction history ahead of its content: 2,000 words before the first fleet card, a 5,000-word "at a glance" table, and a 330-word single-sentence Web4 card. That density also hides two stale directional pointers on /fleet ("its card below", "see the note above") that point at nothing. I'd come back to run SAGE. I would not come back to read /fleet.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 (Home plus all 8 nav items: Projects, Glossary (/context), ARC-AGI-3, Fleet, Autonomy, Raising, Principles, Links). The pass brief says "all 8 pages", but the nav is the source of record and gives 9, counting Home.
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: Canonical terminology is fully consistent across all nine pages, and every in-site anchor resolves. What's left is structural and lexical, not canonical: nouns for Web4 besides "ontology", one word with three referents (HUB/Hub/hub), a heading hierarchy on /fleet and /context that hides a 2,000-word preamble, and page metadata that still describes the old site.

### Method note
I used WebFetch for the landing page's nav and heading outline. Everything else was checked against served HTML (curl, then tags stripped), because model summaries of these pages have confabulated before. The checks were scripted over all nine pages:
- first use of each acronym vs its first expansion, in words
- tallies of each canonical expansion and dimension-list form
- casing variants of shared proper nouns
- heading levels and ids
- every `href="/page#frag"` checked against the target page's ids
- a drift-pattern grep

Counts below come from those scripts.

### Journey
**Home (via WebFetch, then HTML).** The outline is clean: H1 thesis, then H2s What is being built / Commercial path / How the lab works / Historical ARC-AGI-3 work / Start here. There are no heading skips. The mismatch is in the metadata. The browser tab reads **"4-lab | Eight Machines, One Recursive Learning Loop"**, but the H1 is about trust and authority for AI agents. All nine pages share one meta description, and it opens with fleet and repo counts ("8 machines (6 cognition + 2 society-hosts), 40 original repos…"). So a search result for /raising, /principles or /arc-agi-3 shows the same fleet-inventory snippet as Home. For a returning reader, this is the first text the site shows, and it describes the pre-refocus site.

Two sentences apart in the Home intro, Web4 is "an open trust ontology, not an architecture, infrastructure or stack" and then "For the **protocol** and implementation start with Web4". I followed that noun across the site (see Terminology Audit).

**/projects.** The page promises "Every Web4 term the cards use (LCT, T3/V3, MRH, ATP/ADP, R6/R7, MCP, RDF, SNARC) … the cards expand each on first use." I tested this. The equation block expands all eight equation terms within about 100 words of the equation. In the cards, SNARC is expanded 3 words after first use and R6 2 words after, so the promise holds. The one unexpanded token is **E4B** ("Transfer to Gemma 4 E4B", ARC card). HUB carries an inline gloss.

**/fleet.** The heading outline is what a tech writer notices first. The h1 "The Fleet" is followed **directly by h3s**. Pool names ("Synthesis pool — Account 1", "Oversight pool — Account 2", "Society-host pool") and machine names (Thor, Sprout, Legion…) sit at the **same h3 level**, and the three h2s come *after* the cards. The roughly 2,000 words of counting method before the first card have **no heading at all**, and the page has **zero ids**. So nothing on /fleet can be deep-linked, including the Sprout card that Pass 1 found mis-pointed as "below". "Oversight pool" is a heading-level use of the site's most enforced noun in a non-Hardbound sense. The body text disambiguates it, but a skimmer reading headings doesn't see that.

**/autonomy.** Every canonical term (LCT, T3, V3, MRH, ATP, ADP, R6, R7) is expanded within 2–8 words of first use, and nine terms link to their /context row anchors. All of those anchors resolve. This is the model page for acronym handling.

**/raising.** The intro says "Web4 vocabulary on this page (T3, V3, MRH, LCT, LoRA) is expanded inline on first use." I checked each one. T3, V3, MRH and LCT are expanded within 2–4 words of their first real use. **LoRA is not.** Its first use in running text ("the archived Sprout LoRA line did update weights") comes about 300 words before "LoRA (Low-Rank Adaptation)". Pass 1 separately noted that LoRA isn't Web4 vocabulary.

**/principles.** It has 10 h2s, each with an id (#p1…#p10), a flat outline, and zero skips. It is the best-structured page. The fractal-leverage and oversight notes are phrased as negations ("not unification and not scope inflation"), which is the correct use.

**/context (Glossary).** The h1 is "Glossary", and it is followed **only by h3s**: 27 headings, no h2. So "Glossary at a glance" (a 58-row table of 5,309 words by my extraction), the narrative sections (SAGE, Hardbound, PolicyGate…) and "Evidence & limitations" all sit at one level. Four of the 27 headings have ids. Rows do have ids (#lct, #t3, #r6…), and every cross-page link into /context resolves. The page's own first-use distances look bad on paper: SAGE is first expanded about 2,665 words after its first use and T3 about 1,444. That's an artefact of the glossary opening with prose that uses the terms before the table defines them. In a glossary it's tolerable, but a reader landing on the intro meets T3/V3/LCT/MRH in the "Trust-native" row before any of them is defined. The HUB row is good documentation: "All-caps HUB is always this machine; capitalized Hub is the software it runs." I checked every page against that rule (below).

**/links.** It's short and clear. All nine canonical terms are expanded inline. It is where the Web4 noun changes again: "SAGE is the recommended starting point … **Web4 is the protocol starting point.**"

**/arc-agi-3.** The page's own content is clean. The `<title>` reads "ARC-AGI-3 — Spring 2026 Research Record" and the H1 reads "ARC-AGI-3 - spring 2026 research record": a hyphen instead of an em dash, and different casing. It's cosmetic. ARC is expanded here (about 37 words in) but used unexpanded on Home (5×), /fleet (7×) and /principles (4×).
