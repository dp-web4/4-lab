## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (/, /projects, /fleet, /autonomy, /raising, /principles, /context, /links, /arc-agi-3)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: A research lab site that explains itself unusually honestly — I understood "what is this?" within two minutes, and the one thing I tried to catch it on (machine counts) turned out to be self-consistent.

### Journey

Landed on the home page from a GitHub README. The h1 is "Eight machines. Forty original repos. One recursive learning loop." — concrete numbers, which I like. The pitch resolved fast: AI agents already act autonomously, there's no general way to know if one will behave appropriately, and this lab is building a "trust-native ontology" where trust is computed per relationship from witnessed interaction instead of platform reputation or crypto keys. As a developer I can hold that: it's like a reputation system where identity is non-transferable and history-backed. The vocabulary primer at the bottom of home did a lot of work — LCT, T3/V3, MRH, ATP/ADP, SNARC, MCP, RDF all get one-liners right there, so I never hit a wall of raw acronyms.

Mid-page I thought I'd found a contradiction: headline says eight machines, but a later section talks about "the 6 cognition machines." I went back and checked — the page itself says "Eight machines (6 cognition + 2 society-hosts)," so it reconciles. Points for that; sites usually lose consistency on their own stats.

/projects gave me the map: four runnable projects (SAGE, 4-Life, SNARC, Membot), research-stage specs (Web4, Synchronism, ACT, others), one private (Hardbound). Clone commands exist for SAGE and ACT. The unifying line — "Synchronism discovers the equations. Web4 encodes them as ontology. SAGE runs them as cognition." — is a good elevator pitch, though descriptions lean abstract; I'd need the READMEs for actual setup.

/fleet was the most fun page for a developer: eight named machines (Thor, Sprout, Legion, McNugget, Nomad, CBP, HUB, pub), each running a different local model on different hardware, with per-machine session counts. "The model is weather, the identity is organism" is a genuinely useful metaphor for identity-in-state-files.

/autonomy read like ops documentation: tracks are literally cron jobs with declared scope, and the daily timeline (supervisors 03:00 → visitor 05:30 → maintainer 06:30 → explorer 08:00) is legible. What surprised me was the candor: the page says outright that the maintainer ships to production without pre-approval, that oversight is "detect-and-revert... not prevent," and that the visitor/maintainer tracks share model families with the authors so "their misses are correlated with the authors'." I've never seen a project site enumerate its own blindspots like that.

/raising is the strangest page for someone with my background — developmental language ("phases," "raising not training") applied to frozen-weight LLMs. But it pre-commits to retiring that vocabulary if a specified control experiment (a context-scramble test) shows nothing, and it flat-out says "everything on this page might be competent context engineering and nothing more." Weird, but falsifiable-weird.

/principles is where jargon density peaks — Hill functions, pheromone fields, p_crit, synthons. Principle 5 admits its own circularity (synthon defined via coherence, coherence partly via synthon). T3/V3 appear here without on-page definitions.

/context is the glossary and it's solid — a scannable table plus a worked example tracing one maintainer commit through every primitive. This is the page I'd bookmark. /links gave me the GitHub org, a contact email, and an actual quick-start (SAGE via Rust/Ollama/Python, dashboard on localhost:8760). /arc-agi-3 is the evidence page: 24/25 games, 94.85% official score, a link to the official arcprize.org scorecard, MIT-0 repo — and a caveat that the SAGE-harness-vs-base-model ablation hasn't been run, so how much is SAGE and how much is Claude Opus 4.6 is unquantified. That caveat is the difference between me trusting the page and not.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 (/, /projects, /fleet, /autonomy, /raising, /principles, /context, /links, /arc-agi-3)

### Journey

I audited page by page, checking every acronym expansion against the canonical table, and cross-checking expansions between pages.

The site's terminology infrastructure is unusually strong for a project site. Home carries a "Vocabulary primer" that expands LCT, T3, V3, MRH, ATP/ADP, SNARC, MCP, and RDF in one place. /context is a full glossary with 26 sections, per-term definition lines, a worked example, and — this is rare — an explicit notation key admitting that "/" means two different things in the flagship equation ("verified by" in T3/V3, a declared→discharged pair in ATP/ADP: "same glyph, unrelated semantics"). Most documentation would quietly hope nobody noticed; this site documents its own notational overload.

Two consistency mechanisms I want to call out as good practice. First, /fleet uses "machine sessions" for per-machine counts while /raising uses "raising sessions" — and instead of leaving the reader to wonder, /fleet states outright: "those pages call this same quantity 'raising sessions' where the cards below call it 'machine sessions': one quantity, two nouns." That's a synonym declared at the point of divergence, which is exactly how a style guide says to handle it. Second, the governance→oversight correction is disambiguated in one canonical place (/context) and every page that must still say "Governance" (it's baked into SAGE's expanded name) annotates it: "'Governance' in the name predates the lab's governance→oversight correction." The annotation appears on /, /raising, /links, and /principles — consistent wording each time.

The drift I did find: /fleet's pub machine card says the fleet ran security reviews "against the hub + trust stack." That is the only occurrence of "stack" I found on the entire site, and it's describing the Web4 trust components — the exact context where the canonical table says "stack" is banned (Web4 is an ontology, not a stack). One word, but it's on the page describing the first public-facing deployment, which is where a newcomer is most likely to import the wrong mental model.

Smaller issues: on /autonomy, "V3-validated value creation" appears before V3 is expanded on that page (the expansion sits later, in Safety boundaries). On /principles, T3/V3 first appear in Principle 4 with no nearby expansion or glossary link — Pass 1 hit the same wall from the newcomer side, so this one is confirmed from two directions. And the home page navigation appears to contain both a "Glossary" item and a "Context & Glossary" item; if both point at /context, that's a duplicate label (one concept, two nav names — the inverse of the session-noun problem they handled well). I couldn't fully verify the nav structure through my fetch tool, so I'm flagging it for verification rather than asserting it.

One near-collision worth a style-guide note: ACT expands to "Agentic Context Tool" and ACP to "Agentic Context Protocol." Both are defined where used, but two four-letter-adjacent acronyms sharing "Agentic Context" is a proofreading hazard — a future page will eventually swap them.

### Journey

I went straight to /projects, /fleet, and /context, then swept the rest. Because /context does something unusual for a project site — it names its source of record ("Source of truth: the canonical terms reference in the public web4 repo — CANONICAL_TERMS_v1.md. When this page and that document disagree, the document governs.") — I did what that sentence invites: I pulled CANONICAL_TERMS_v1.md from the repo and diffed the glossary against it.

The headline result: the citations are real. /context glosses T3 as "Three-component trust tensor; each component is an RDF sub-graph root" and attributes the phrase "a root node in an open-ended RDF sub-graph, not a scalar" to canon — and canon does say "Each dimension is a root node in an open-ended RDF sub-graph." The V3 relation "complementary, not combined" is likewise canon's own wording ("Complementary, not combined. T3 measures trust, V3 measures value."). A site that quotes its canon accurately, and marks its extensions ("Society-layer vocabulary; not yet in CANONICAL_TERMS_v1" on Sovereign, HUB, Chapter ledger, Chapter law), is doing the thing I wish more of our own docs did.

The diff also surfaced where the site runs ahead of the document. Three spots: (1) the notation key — canon has no notation section at all, so the site's careful "/" dual-sense disclosure ("verified by" in T3/V3, declared→discharged pair in ATP/ADP) is site-authored, not canon-sourced; (2) LCT non-transferability — /context says "Non-transferable: permanently bound to a single entity," which is correct Web4 doctrine from the broader docs, but CANONICAL_TERMS_v1's LCT entry says only "verifiable digital presence that accumulates witnessed history and reputation over time"; (3) the "not a scalar" tail on the T3 quote, which the canon excerpt I retrieved doesn't include. None of these are drift — every one is doctrinally right — but under the site's own "the document governs" rule, they're claims the named source doesn't yet back. The fix belongs upstream (canon should absorb them), not on the site.

One genuine discovery from reading canon rather than the site: canon defines R7 — "R6 + Reputation, a superset adding reputation back-propagation" — and canon's R6 is explicitly the "transaction without reputation tracking" form. The site presents R6 as "the shape of every auditable action" and never mentions R7 anywhere. Since the site elsewhere describes trust tensors updated from witnessed interaction — which is reputation back-propagation, i.e., the R7 loop — a contributor reads /context and wonders where reputation lives in the action grammar. Not a wrong statement anywhere, but a missing canonical term.

On my other focus checks: /projects is accurate. The Web4 card reads the equation out in prose exactly right — T3 verified by V3, contextualized by MRH, anchored to LCT, resources cycled through ATP/ADP, augmented with MCP transport and RDF representation. Hardbound is "hardware-bound oversight suite" with the machine-enforced disambiguation, TPM 2.0 and FIDO2 expanded. "This isn't unification — it's fractal leverage" is verbatim correct. SAGE's card (12-step loop, 6 components, session counts) matches the project I know, and the "Governance predates the correction" annotation is applied consistently on every page that expands SAGE's name (/, /raising, /links, /arc-agi-3, /context). Synchronism is hedged as "research conjecture, single-trial and not independently replicated" — accurate, and braver than most labs would be.

/fleet is where the one real violation lives: the pub card says the fleet ran three security reviews "against the hub + trust stack." I know exactly what that phrase is reaching for — the hub daemon plus the LCT/T3/V3/ATP components — and "stack" is precisely the word we banned for it, because it imports the infrastructure mental model on the page describing our first public-facing deployment. Pass 2 found this too; from the contributor side I confirm it's not a quote from any canon document I know. /arc-agi-3's SAGE-Web4 relationship line ("Web4 supplies the audit trail — every action shaped as an R6 record") is accurate.

## Pass 4: External Researcher

### Summary
- **Pages visited**: 9 (/, /projects, /fleet, /autonomy, /raising, /principles, /context, /links, /arc-agi-3)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: The most caveat-conscious project site I have evaluated — every consciousness-adjacent claim arrives with its deflationary alternative attached — but the discriminating experiment the whole vocabulary hangs on is not just unrun, it's structurally blocked: the metric it needs pre-registered depends on a term the lab admits has no operational definition.

### Journey

I came in expecting the usual failure mode of agent-lab sites: developmental language doing unacknowledged philosophical work. The home page defused that within one screen — "machines that 'teach', 'raise', and hold 'identities' is functional description of observed system behavior, not a claim about consciousness or experience" — and, more unusually, it stratifies its own evidence: the fleet-observation claims are labeled "internal observation... not externally audited, not blinded, and with no published log samples or coding criteria," with the ARC Prize scorecard identified as the sole externally verifiable result. That's an evidence-tier discipline most preprints don't manage.

/raising is the page I came to stress-test. The "raising not training" distinction is operationally stated — "we shape context — we do not update weights"; training "optimizes for a loss function" — which makes it defensible as far as it goes: it names a real difference in intervention type, not a smuggled claim about inner life. The page then does something I want to explicitly credit: it leads with "everything below might be competent context engineering and nothing more — the control that would discriminate raising from that alternative has not been run yet," attaches a simpler candidate explanation to each observed pattern, and even marks an observer's note ("I notice I want to call it experience") as "observer's interpretive pull — not a system-level claim." The falsification design is real: a scramble control (same corpus, same token volume, permuted order) with a stated success criterion — identity-continuity measures degrade while task competence stays intact.

And then the load-bearing admission: the control is "specified... but not scheduled — no date, no owner, no pre-registered metric yet." Cross-referencing /context turned this from a scheduling gap into a structural one. The glossary concedes that "coherence" is used "in three related senses... with no single operational definition yet," and that the continuity claims have "no metric [that] names what would actually be scored on those logs, and no threshold [that] says what counts as degradation." So the chain is: the developmental vocabulary is licensed pending a control; the control needs a pre-registered metric; the metric needs an operational definition of the very term ("coherence" / "identity continuity") that the vocabulary is built on. The site discloses every link of this chain — but nowhere states the chain itself, that the blocker is definitional rather than logistical.
