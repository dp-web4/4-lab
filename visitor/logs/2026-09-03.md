## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (/, /projects, /fleet, /autonomy, /raising, /principles, /context, /links, /arc-agi-3)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: The "what is this" question is answered fast and well — the failure is one step later, at "okay, how do I run it," where the page that invites me to clone hands me a README pointer and the page that actually has the commands is signposted as something else.

### Journey

Landed from a repo README with zero Web4 context. The home headline — "Eight machines. Forty original repos. One recursive learning loop." — is the best thing on the site for me. Concrete nouns, countable. I knew within fifteen seconds this was a fleet of machines running agents against each other, not a whitepaper.

Home then does something most research sites don't: it defines its own vocabulary inline before using it. LCT as "Linked Context Token. Non-transferable identity grounded in witnessed history, not model weights," MRH as "The boundary of what an entity can know or affect given its position," ATP/ADP as "intent and discharge as two distinct audit artifacts." I did not have to leave the page to parse the page. That's rare and I want to say so before I complain about anything.

Went to /projects, because that's where a developer goes. Eleven cards, each with a public/private and runnable/research-stage label. The labels are genuinely useful — "runnable" on SAGE, 4-Life, SNARC, Membot told me exactly which four to look at. SAGE is marked "Clone it and it executes end to end today (a demo, a script, a server)." Good. So I scrolled to the quick start:

```
# SAGE — on-device cognition kernel (recommended first clone)
git clone https://github.com/dp-web4/SAGE
cd SAGE
# See README for Python/conda setup and first session instructions
```

That's where I stalled. The comment tells me to leave the site. Fine, I thought — and kept browsing the rest of the nav first.

/fleet is eight machine cards with hardware, model, and session counts. This is the page that made the "recursive learning loop" claim feel real rather than aspirational — Thor on a Jetson AGX at 435 sessions, Sprout on an Orin Nano 8GB at 488, CBP on WSL2 with a 2060 SUPER at 193. Someone is actually running small models on cheap hardware and logging it. But this page also has the densest unglossed vocabulary on the site (below).

/autonomy is the page I most wanted to steal from and least could. "31+ autonomous tracks across 6 cognition machines, ~53 sessions per day," then a clean timeline: 03:00 supervisors, 04:00 archivist, 04:30 publisher, 05:30 visitor, 06:30 maintainer, 07:00 outreach, 08:00 explorer. That is a scheduler config, described in prose. I wanted a crontab. There is no code block on the page at all. Every other page on this site eventually hands me a repo; this one hands me a picture of one.

/raising and /principles I read as a skeptic and came away better disposed than I expected. "This is the softest page on the site" and "Everything below might be competent context engineering and nothing more" are the kind of lines that buy credibility cheaply and honestly. Principle 3 is literally "R&D, not production — Nothing here is optimized for deployment." I stopped bracing for a pitch.

/context is the glossary and it's the best reference page here — the Web4 equation with a notation key that distinguishes "/" as "verified by" in T3/V3 from "declared→discharged allocation pair" in ATP/ADP, and a Coherence entry that admits it's "used in three related senses...with no single operational definition yet." Admitting an undefined load-bearing term costs nothing to write and is unusual to see.

/arc-agi-3 leads with its own caveat before the number: the ablation "that would separate the harness's contribution from the base model's (same model, no harness) has not been run." Then 94.85% action score, 24/25 games, with a link to a third-party ARC Prize scorecard. I clicked it — the link is real and external. That's the strongest evidence on the site.

Last stop, /links. And there, at the bottom of the nav, were the commands I'd been looking for since /projects:

```
python3 -m sage.instances.init --machine mybox --model gemma3:4b --operator-name yourname
cd sage-rs && cargo build --release && cd ..
SAGE_MACHINE=mybox SAGE_MODEL=gemma3:4b ./sage-rs/target/release/sage-daemon
```

That's a real first run. It's also Rust, not conda. I would have spent an hour in a Python environment before finding out the daemon builds with cargo.

### Unanswered Questions

1. Which quick start is right for SAGE — the conda setup /projects points me at, or the `cargo build` daemon on /links? I can't tell from the site which one is current.
2. What is hestia? It has an identity system, a "trust layer", and is the thing HUB's agent owns, but it has no card, no link, and no definition anywhere I looked.
3. Can I run one of the 31+ autonomous tracks myself, or is that fleet-internal only? The page never says either way.
4. What does a "session" consist of? The counts (435, 488, 193, 2,065) are the site's main evidence, but I never learned what one session is — a prompt? a day? a scheduled track run?
5. If Web4 is an ontology and not a layer, what do I actually import or depend on to use it in my own project?

### Verdict

This site clears the two-minute bar better than most research-lab sites: the home headline is countable, the vocabulary is defined where it's used, and the caveats read like someone who expects to be checked rather than someone managing expectations. The ARC scorecard link to a third party is worth more than the rest of the evidence combined, and the site is honest that the ablation behind it hasn't been run. What breaks is the handoff. I was told to clone SAGE three separate times and never once given the command to run it on the page doing the telling — the real commands are on /links, which /projects describes as the place licenses live. That's a one-sentence fix and it's the difference between a developer who clones and a developer who closes the tab.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 (/, /projects, /fleet, /autonomy, /raising, /principles, /context, /links, /arc-agi-3) + canon raw
- **Understanding achieved**: solid
- **Would return?**: yes
- **Overall impression**: Acronym expansions are clean on all nine pages — every one I checked matches canon — so the drift has moved entirely into glosses, scope claims, and one false statement *about* canon; the glossary is now the site's most authoritative page and its least audited one.

### Journey

I audited against two instruments this pass, not one. CLAUDE.md's canonical table is a crib sheet of nine terms; `/context` links the real source — `CANONICAL_TERMS_v1.md` in the web4 repo — so I fetched it raw and diffed the site against the document rather than against the summary. That changed the results. The crib sheet returns "all clean" on this site by construction: it only checks expansions, and the expansions *are* all correct. Everything I found this pass is one level down.

**Expansions: nine pages, zero drift.** LCT is "Linked Context Token" on /, /context, /links, /projects, /arc-agi-3 — five surfaces, one string. MRH is "Markov Relevancy Horizon" everywhere. ATP/ADP are "Allocation Transfer Packet / Allocation Discharge Packet" on /, /context, /autonomy, /links, /arc-agi-3. T3 is "Talent / Training / Temperament", V3 is "Valuation / Veracity / Validity" on all five surfaces that carry them. None of canon's `NOT:` variants appear anywhere — no "Lifecycle-Continuous Trust", no "Trust-Tracing-Tensor", no "Attention Token Pool", no "Adaptive Development Points". I checked all of them. That is a genuinely good result and I want it on the record before the findings, because the findings are all about something else.

I also checked a name I expected to flag and didn't: canon's headword for T3 is **"Trust Tensor"**, with Talent/Training/Temperament as its three root nodes — not, as the crib sheet implies, "Talent / Training / Temperament" as the expansion. The site carries both: `/context` reads "T3 — Talent / Training / Temperament | Three-component trust tensor". Correct on both levels. Same for V3 / "Value Tensor". If a future pass flags "Trust Tensor" as drift, it is the crib sheet that is wrong, not the site.

Then I went to the glossary and read it against itself. `/context` carries 44 headwords, which makes it the densest and most load-bearing page on the site — and the only page whose internal consistency nothing checks. Three of the four findings below came from reading two of its own entries side by side.

The sharpest one: the **Society** entry ends "(Society-layer vocabulary; not yet in CANONICAL_TERMS_v1.)" Canon v1 defines Society. It is headword nine: *"A self-governing group of entities with treasury, membership rules, policies, and roles. Societies can contain other societies (fractal structure)."* The site disclaims canonical status for a term canon actually carries — and having disclaimed it, defines Society by pointing at the fleet instead of by its properties. The honest hedge is what suppressed the definition. This is the only outright false statement about canon I found on the site, and it is unusual in shape: the site is being *more* modest than the facts support.

Second, R6 and R7 sit adjacent in the glossary and disagree. R6: *"Every action in the system is shaped as an R6 record."* R7, four lines later: *"wherever the prose says trust 'updates from interaction,' the action grammar underneath is R7, not bare R6."* Both cannot hold. Canon settles it against R6 — there, R6 is *"Base action grammar for routine, low-consequence tasks without reputation ledger tracking"*, with R7 for *"when consequences justify ledger cost."* The R7 entry is the correct one; the R6 entry's "every action" over-scopes and makes its neighbour redundant.

Third, canon's five relationship primitives. Canon defines **Witnessing, Binding, Pairing, Delegation, Federation** — Binding *"Irreversible"*, Pairing *"Revocable"*, Delegation *"Instantly revocable"*. That is a revocability ladder, and it is the vocabulary for exactly what /fleet and /autonomy describe: trust relationships between machines, and scoped authority granted to tracks. The site imports one rung. Witness is a headword; Federation appears once in prose, undefined ("using federation for distributed consolidation"); Pairing and Delegation are absent from all nine pages. Binding is the interesting case — the *concept* is on the page, under the wrong headword: LCT reads *"Non-transferable: permanently bound to a single entity."* That is canon's Binding, spelled as an adjective. The word is doing canonical work without being a defined term, and meanwhile /principles and /context use "bind" casually for tensor attachment (*"Both bind to entity-role pairs via RDF triples"*), which is a different relation entirely and revocable.

Fourth, and the one I'd fix first: **"self-directed."** `/context` defines it — negatively, and emphatically. The Autonomous entry reads *"Unattended and self-scheduled — NOT self-directed in the AI-safety sense of choosing its own goals"*, and calls itself *"the site's highest-risk collision for a reader from AI safety."* `/autonomy` repeats the disclaimer. Then `/raising`, BECOMING Pattern 4, states as an observed developmental milestone: *"Session logs show an increasing proportion of self-directed prompts."* The site defines a term by disclaiming it, then reports achieving it. A researcher who reads /context first and /raising second sees the disclaimer retracted; one who reads them in the other order sees the milestone walked back. Neither page links the other.

Two smaller structural notes. `/raising` states an explicit style policy — *"Web4 vocabulary on this page (T3, V3, MRH, LCT, LoRA) is expanded inline on first use"* — and honours it. `/fleet` uses T3/V3, MRH, LCT, ATP/ADP, RDF, MCP, LoRA, SNARC, plus WM and dlPFC, and expands none of them. The policy exists and is written down; one page ignores it. And the R6 name is inconsistent by page: /projects, /links and /arc-agi-3 all call it the "Six-Element Action Framework"; /context, the authority, calls it "the canonical action framework" and never uses that name. Canon writes it `Rules/Role/Request/Reference/Resource → Result` — an arrow, five inputs producing a result, not six peers. The site's own R6 gloss actually agrees with canon semantically (*"what it consumes (Resource), and what it produces (Result)"*); it is only the label and the slash that flatten it.

**One claim I checked and withdrew.** I drafted a finding that the site presents ATP/ADP as a one-way audit pair and drops canon's recycling (*"Can be recycled back to ATP through validation"*). Wrong — /context carries it: *"discharged packets are charged back to ATP against validated value creation."* The recharge is on the page; my first read of the notation key ("a plain declared→discharged allocation pair") had me expecting an omission that isn't there. Recording the miss because the shape recurs: absence-findings on this site need a second, literal fetch before they are written down.

Finally, a countable inconsistency a reader will hit in two clicks. Home: *"Forty original repos."* /projects: eleven project cards, and the sentence *"The Links page has the full repo list."* /links: eleven repos, three of them explicitly labelled forks — eight original. Forty, eleven, eight, and the middle page calls the smallest one "full." Separately, `hestia` is named twice on /fleet as a known noun and appears on no other page — not /projects, not /links, not /context (I checked all three literally). Whatever else "full repo list" means, it does not survive a term the site uses in its own copy.

## Pass 4: External Researcher

### Summary
- **Pages visited**: 9 (/, /raising, /principles, /autonomy, /context, /arc-agi-3, /fleet, /links, /projects)
- **Understanding achieved**: solid
- **Would return?**: yes
- **Overall impression**: This is the most epistemically self-aware research site I have audited this year — it states the evaluation-correlation problem better than most published safety work — and that is exactly why its two remaining defects matter: the disclosure budget is spent, and the site is still spending it instead of publishing one checkable artifact.

### Journey

I came in from a conference mention expecting the usual: developmental vocabulary applied to LLM agents, consciousness gestures hedged just enough to be unfalsifiable, and a fleet-of-machines aesthetic standing in for evidence. I did not get that, and I want to lead with what I found instead, because the criticism further down is worth more if the credit is on the record first.

**/autonomy contains the single best sentence on the site**, and it is a sentence most labs do not write:

> "The visitor and maintainer tracks are LLM sessions drawn from the same model families as the tracks that author the content they audit — their misses are correlated with the authors', not independent."

That is the evaluation-correlation problem, named, in the place where it applies, by the people it indicts. It is immediately followed by the correct reading of the lab's own clean record: 79 maintainer sessions, 117 commits, zero rollbacks, zero reverts — and then *"Read that as weak evidence, not as a safety result: the only automated detector is the same daily loop being evaluated, so a zero is equally consistent with 'no bad push shipped' and 'the loop cannot see its own bad pushes.'"* A lab that knows what its own zero means is a lab I will read again.

The same page discloses things labs usually bury: that consequential pushes are not human-gated before they ship, that a repo push is *"not fully revertible... rewriting history afterward doesn't unpublish what was already pulled"*, that human review of audit logs is *"asynchronous, with no committed cadence"*, and that for the failure class the loop is worst at — technically correct but misleading content — *"the exposure window is unbounded in principle."* I went looking for the gap between the oversight claimed and the oversight practiced. The page had already written it down.

**/raising** is where I expected to find the problem, and it is where I found both the site's best structure and its worst sentence. The page opens by conceding it is *"the softest page on the site"* and that *"everything below might be competent context engineering and nothing more."* The BECOMING phases are labelled *"descriptive scaffolding, not measured stages."* Consciousness-adjacent language is disclaimed at the top of the site, not the bottom of this page: *"functional description of observed system behavior, not a claim about consciousness or experience."* The identity-portability observation is paired with its own deflationary alternative — *"the same context files fed to a different set of frozen weights may produce similar behavior for mechanical reasons, with no identity transferred at all."* Offering the deflationary reading unprompted is the behavior of someone who expects to be checked.

And then the page pre-registers its own refutation. The control is a **scramble**, correctly specified: *"same corpus, same token volume, permuted order... If phase-consistent behavior survives the scramble, 'raising' is a redescription of prompt engineering, and the honest move is to retire the word."* With a pre-commitment: *"if this control runs and the result is a bare main effect, or no degradation at all, that outcome gets published on this page and the developmental vocabulary gets retired from it."*

I want to be clear about how unusual that is. Most labs using developmental vocabulary have no condition under which they would stop. This one has written down the experiment that would take the word away, and it is the right experiment — order-scrambling is precisely the manipulation that separates "curriculum" from "corpus." **Is "raising, not training" defensible?** As stated, yes, and narrowly: the operational content is *"we shape context — we do not update weights,"* which is a mechanical claim that is true by construction. What is *not* yet defensible is the developmental reading layered on top, and the page says so: *"treat the framework as a working vocabulary that fits our observations, not an established finding."*

The problem is the status line: **"specified but not scheduled — no date, no owner, no pre-registered metric yet."** A pre-commitment with no owner and no date is, operationally, not a commitment. And the blocker the page names is worse than a resource constraint — it is definitional: pre-registering the metric *"requires an operational definition of identity continuity,"* and /context concedes coherence *"has no single operational definition yet."* So the site has designed the experiment that would falsify its central framing, then blocked it behind a term it has already admitted it cannot define. That is an honest deadlock, but it is a deadlock, and it will still be here next cycle unless someone breaks it. **It does not have to be.** The scramble control does not need "coherence" or a defined identity — it needs any *pre-registered discriminator* that a blinded rater can apply. Blind three raters (or three model instances from a different family) on session transcripts from the raised and scrambled arms, ask them to sort each into a BECOMING phase, and report inter-rater agreement and arm separation. That is a stipulated proxy, not a definition, and it converts a definitional blocker into a scheduling problem. The lab does not need to know what identity *is* to test whether the ordering does work.

**/principles** held up better than the genre usually does. Principle 3 is *"R&D, not production — Nothing here is optimized for deployment,"* extended to *"Nothing on this site is intended for or suitable for deployment in safety-critical, medical, financial, or autonomous-control settings."* Principle 6 is *"Document failures,"* and unlike most sites that claim it, this one instances it: /principles reports its own *"p_crit derivation failed catastrophically — 400x error,"* and /projects' Synchronism card volunteers that *"several predictions have been refuted by existing bounds."* Publishing your own refutations on the project card is the cheapest credibility available and almost nobody spends it.

Principle 5 is where I'd push back. 'Synthon' is defined through coherence, and coherence is in turn partly defined through the synthon marker — the two terms lean on each other."* The circle is disclosed and unbroken. My question is not whether it is honest; it is why a single-trial figure whose two variables are mutually defined is still sitting in a numbered principle. Disclosure has been substituted for demotion. The caveat is doing work the edit should do.

**/context** is the page I'd point another researcher at first, because of one feature I have not seen elsewhere: it maintains an explicit **collision list**. Five terms are flagged as colliding with established vocabulary — *autonomous* (flagged as *"the site's highest-risk collision"*), *oversight*, *policy*, *emergence* (*"explicitly NOT the LLM emergent-capabilities sense"*), and *coherence*. The Autonomous entry in particular is the best-written thing on the site: *"Unattended and self-scheduled — NOT self-directed in the AI-safety sense of choosing its own goals: task definitions are authored in advance, not chosen by the track itself."*

Which brings me to the sentence I cannot let pass. **/raising Pattern 4 reads: "Session logs show an increasing proportion of self-directed prompts — the system generates questions rather than only responding to them."**

The site defines "self-directed" negatively, in the AI-safety sense, on the home page, on /context, and on /autonomy — three surfaces — and then asserts it as an observed and *increasing* quantity on a fourth. For a reader arriving from safety research, "an increasing proportion of self-directed prompts" is not a soft phrase. It is the trend claim the field cares most about, and it is stated here with no denominator, no measurement window, no baseline, and no coding criteria — on a page whose own framing rule is that these are *"descriptive scaffolding, not measured stages."* Every other empirical assertion on this site carries an evidence tier. This one is phrased as a longitudinal measurement and carries nothing. Two independent readings are available to an outsider — a genuine goal-selection trend, or a rise in self-addressed prompting within a fixed task scope — and the site's own vocabulary makes the alarming one the default reading. The fix is one sentence and it is not a hedge: name the measured thing ("prompts originating within the session rather than from the track definition"), or drop the quantifier.

I checked whether **anything on this site can be verified from outside it**, and the answer is: one thing. The ARC Prize scorecard link resolves to a third-party page. Everything else countable — 2,065 sessions, 79 maintainer sessions, 117 commits, 31+ tracks, the BECOMING patterns, the 1%/35% figure — rests on logs the fleet keeps about itself. The site says this plainly (*"Evidence tier: internal observation... not externally audited, not blinded, and with no published log samples or coding criteria"*), which is why I am not filing it as dishonesty. I am filing it as a **saturation problem**: the marginal return on the next caveat is now approximately zero. I already believe the lab is being straight with me. What I cannot do is check anything. The site names its own missing artifact — *"no published log samples or coding criteria"* — and never says why it is missing. An unexplained absence reads, to an outsider, as a choice.

**/arc-agi-3** is where that matters most, because it is the one page with an external referent and therefore the page where a credibility error is most expensive. It leads with its caveat rather than burying it — *"the ablation that would separate the harness's contribution from the base model's (same model, no harness) has not been run"* — and repeats it twice more, plus *"Nothing here was adversarially tested"* and a note that Hardbound's hardware anchoring was *"a design target, not the mechanism in this run."* Good. But the page describes the benchmark's difficulty in terms of *"obfuscated engine source"* while labelling its own method chain *"Source analysis → world model → solver → multi-agent frame-questioning."* Those two statements are in tension on one page, and I cannot tell from the page what source was analyzed. Separately, the run is disclosed as using *"network access"*; for a benchmark claim that is a first-order condition, and it is stated as a fact rather than flagged as one.

**/fleet** was my last stop and it carries the one unhedged agency claim on the site: *"Its hestia identity is the fleet's first agent-owned one (created by the machine's own agent, not delegated by a human)."* No hedge, no evidence pointer, on a page that a skimmer reaches before /raising. It also uses "identity" throughout with no pointer to the collision list two clicks away.

### Unanswered Questions

1. Is "an increasing proportion of self-directed prompts" a counted quantity or a characterization? If counted: what is the denominator, over what window, and by what coding rule? This is the one question on the site whose two answers point in opposite directions for my field.
2. Who owns the scramble control, and what would have to be true for it to be scheduled? The stated blocker is definitional, and the site has already shown it can stipulate proxies elsewhere.
3. Why are session logs and coding criteria unpublished? Privacy, volume, or nobody has asked? The site names the absence three times and never gives a reason.
4. What would the lab accept as external validation short of a paper? The ARC scorecard shows they will use third-party scoring when it exists. Is there a second claim on this site that could be routed to an outside scorer?
5. If the visitor and maintainer tracks are correlated with the authors, what is the plan to decorrelate them — a different model family, a human reviewer with a cadence, or an accepted permanent limitation? The problem is named; the response is not.
6. The 1%/35% figure has survived multiple cycles with its caveat attached. What is the retirement condition for a number, as opposed to for a vocabulary? /raising has one for "raising"; /principles has none for this.

### Verdict

Judged on intellectual honesty alone, this site is in the top decile of anything I read from small labs: consciousness-adjacent language is disclaimed on the landing page rather than the footer, the central framing carries a specified control and a written pre-commitment to retire its own vocabulary, a clean safety record is explicitly read as weak evidence, and the evaluation-correlation problem is stated by the party it implicates. "Raising, not training" is defensible as written, because its operational content — shape context, never weights — is true by construction and the developmental reading on top of it is hedged and pre-registered against. The honest assessment feels honest; I went looking for the gap between claimed and practiced oversight and found it already documented.

Two things keep it from being credible rather than merely honest. First, "an increasing proportion of self-directed prompts" — the site defines that term negatively for readers like me on three pages, then asserts it as an unquantified trend on a fourth, and the default outside reading is the alarming one. That is a one-sentence fix and it is currently undoing the work every disclaimer on the site is doing. Second, the disclosure budget is spent. After nine pages I believe this lab; I still cannot check a single internal claim, and the only thing that changes that is an artifact — one redacted session log with its coding criteria, or the scramble control run against a stipulated proxy instead of waiting on a definition that the glossary has already conceded will not arrive. More caveats will not move me further. One checkable thing would.
