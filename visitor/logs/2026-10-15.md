That's a deliberate choice, and from a documentation point of view it's the right one: a front page with no acronyms can't have acronym drift. Hardbound is "hardware-bound oversight" on `/projects`, which is correct. Web4 is "an open standard … a shared vocabulary, or ontology" on Home, "The open standard, written as an ontology" on `/projects`, and just "the open standard" on `/links`.

Then I went through the notebook page by page, counting every use of each canonical acronym and finding where it is first expanded (I fetched the rendered HTML and confirmed every count against the page text).

- **Expansions:** every expansion on all nine notebook pages matches the canonical table. LCT is always Linked Context Token. T3 and V3 always appear as "Trust Tensor — Talent / Training / Temperament" and "Value Tensor — Valuation / Veracity / Validity". The dimensions are never given as the expansion. MRH, ATP and ADP are canonical everywhere. R6's element list appears 5 times on 4 pages, always identical, arrow included. R7 = R6 + Reputation. SNARC's expansion (Surprise / Novelty / Arousal / Reward / Conflict) is the same on `/notebook/projects` and the glossary.
- **Drift words:** "production ready" appears nowhere. "Unification" and "scope inflation" appear only inside "not unification, and not scope inflation" disclaimers. "Architecture" and "infrastructure" appear for Web4 only in "Web4 is not …" sentences, or where the site attributes them to the upstream README.
- **Pointers:** I ran an anchor check on every `href="/…#…"` and `href="#…"` across all 16 pages, and **all of them resolve**. Bare route labels in the notebook's prose that point at a front page (e.g. "see /fleet" where the notebook page was meant) are down to **3**, from roughly 86 on 10-10. All 3 are on `/notebook/projects` and deliberately name the front (e.g. "its link on the front /projects and /links pages returns 404"). The other 59 bare labels are `/context`, `/autonomy` and `/arc-agi-3`, which redirect correctly.

That left SAGE's expansion. "Situation-Aware Governance Engine" is given on all nine notebook pages, but in two different ways. `/notebook/autonomy` says "SAGE (Situation-Aware Governance Engine — **a legacy name; see the Glossary**)". `/notebook/fleet` says "(Situation-Aware Governance Engine — **legacy name, see the note above**)". I followed both pointers. The glossary's SAGE row gives the expansion with no "legacy" label. Its governance→oversight section says the opposite: "Names minted before the correction are **retained** … 'Governance' in SAGE's name … **No rename is planned**." The "note above" on `/notebook/fleet` says that "cognition kernel" is SAGE's 2025 *framing*, which is about the framing, not the name. `/notebook/projects` has a third version: the word "Governance" is "a legacy label … retained upstream". As a technical writer I can't tell from the site whether "Situation-Aware Governance Engine" is the current expansion or a superseded one. Both pointers claim to explain it, and neither destination says "legacy".

Next, the status labels. The front `/projects` defines **Running / Building / Research**. The notebook's `/notebook/projects` defines **runnable / research-stage**, plus a separate **public / private** axis. Neither page maps one set onto the other. The front's "Building" (Hardbound) has no notebook counterpart, and "Running" (in daily use here) is a different claim from "runnable" (clone it and it executes). A reader who follows "Every repository, with its maturity … is in the notebook" arrives at a different scale with no key between the two.

### Journey
I went straight to `/projects` and read each card against the repo I know. Web4, Hub and Hardbound match upstream closely. Hardbound is "hardware-bound oversight, private, built by Metalinxx", which is web4 README l.204 with the right noun. Hub's "eight base roles" matches the web4 README (l.111) and the notebook's seven→eight note. The Running/Building/Research labels line up with the README's stack table (Hestia "Running daily", Hub "Running Rust reference implementation", Hardbound "Private/proprietary; building", SAGE "active research").

Two cards don't hold up:

- **Synchronism**: "It supplies the equations that Web4's trust model builds on." web4 `AGENTS.md` l.107 says: "`Synchronism` | Blue-sky conceptual lineage; **not an engineering dependency**." The site's own `/notebook/projects` quotes that line and adds "no Web4 primitive (LCT, T3/V3, MRH, ATP/ADP, R6/R7 …) is defined from a Synchronism equation." The front states the opposite of both the notebook and upstream.
- **Hestia**: "Every action is checked first and recorded where the agent cannot change it." Home says "with a record the agent cannot edit". The hestia README states its assurance ceiling in bold: "profile **A1**: a cooperative gate running as the same UID as the operator. Tamper-**evident**, not tamper-proof", and it says "two environment variables suffice today" to bypass the gate (issue #49, `GATE_BYPASS_CATALOG.md`). The notebook glossary also says "Running today at assurance profile A1". "Cannot change" is the A2+ claim, and the README says A2+ "is not available now". Hestia's real A1 property, that bypass is *attributable*, is a fine thing to put on the front, but it isn't what the card says.

Both are front items, so they go to dp. As far as I know, both were first reported on 2026-10-04 and are still live 11 days later.

I then went into the glossary (`/notebook/context`) as the authority. Canon has not changed since 2026-04-28, and the glossary rows for LCT, T3, V3, MRH, ATP, ADP, R6 and R7 quote or paraphrase it faithfully. The R7 row correctly says "superset" and "both modes are canonical", and it logs the R6-tensor-update conflict between canon and spec as upstream's to settle. Two sections drift on mechanism instead:

- **"R6 and R7: the action framework"** says: "R6 is the canonical action framework used throughout the SAGE loop … **Every action in the system is shaped as an R6 record** … R6 records are the artifacts that make every action **signed**." I read the SAGE gateway. `sage/gateway/being_gate_client.py` (2,787 lines) has zero R6 references, and its shape is `intent -> gate.evaluate (+ society safety) -> dispatch -> result`. Its `pr_open` note says the being's commits are "authored by the seat's git identity and ATTRIBUTED to the being in trailers — §6 says **signatures come at M3**". SAGE's R6 module (`sage-core/src/r6.rs`) describes itself as "R6 Framework Implementation for SAGE **Training** … for context-aware training evaluation", and a code search finds no `sage_core::r6` callers. So in today's SAGE, R6 is a training-evaluation schema, not the record every action produces, and the being's actions are attributed, not signed.
- **"ACP: Agentic Context Protocol"** is all present tense: ACP "ensur[es] that every tool invocation carries a verifiable identity anchor", and ACT "is the Cosmos SDK implementation of ACP — the human interface to Web4". It has no status. `/notebook/links` on the same site calls ACT "Stalled, and reserved", and the ACT repo's own description (last push 2026-09-04) is now "candidate ledger backend for Web4 anchoring. **Early prototype.**" Neither the web4 README nor `AGENTS.md` mentions ACT or ACP at all, and today Hestia and Hub are the human/agent interface. The glossary is the most-cited page and also the most out of date here.
