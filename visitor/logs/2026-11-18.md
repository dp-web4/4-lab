## Pass 1: Curious Developer

*Method note: no WebFetch tool was available in this session, so the live site was fetched with `curl` and read as text extracted from the rendered HTML (`<main>` only). Every quote below comes from that rendered text. Outbound links were checked with HEAD requests; the package versions came from the crates.io and PyPI JSON APIs and the GitHub releases API.*

### Summary
- **Pages visited**: 8 (the seven front pages in the nav plus /notebook/projects, where a developer goes to look for an install path), plus 11 outbound links
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: The front explains in about two minutes what the lab does: governance for AI agents, with an open standard, two tools and a research line. The one thing a developer clicks through for, "how do I try it?", has its only answer at the very bottom of a 7,500-word notebook page, and no front page links to it.

### Journey
I arrived from a GitHub README. **Home** worked on me. "AI agents are becoming actors in the world. We are building how they earn trust" is a clear thesis, and "The idea" paragraph (track record checked against rules that exist before anyone acts) took about ten seconds to understand. The four cards (Web4, Hestia, Hub, SAGE) each say in one sentence what the thing is. "Ontology" is glossed inline ("a shared vocabulary, or ontology"), which is the right move for someone like me. The "How the lab works" strip, with lines like "They are refused by it every day", is the most credible thing on the page. It reads like dogfooding, not marketing.

The labels confused me. Home shows RUNNING and RESEARCH badges with no legend. As a developer I read RUNNING as "I can run this". The legend at the bottom of /projects says it means "in daily use on our own machines", which is a different claim. I only found that out because I kept going to /projects.

**/projects** is the best page for my persona. It sorts the work into "Governance for AI agents", "AI beings" and "Theory", and every card links to a repository or site. I learned that Web4 has packages on crates.io and PyPI, that Hestia has releases, and that Hub lives inside the web4 repo. Two names stopped me. "Hardbound … built by Metalinxx": who or what is Metalinxx? It isn't explained anywhere on the front. "SAGE" looks like an acronym, but it is never expanded on the front.

I noticed that one claim has three strengths. Home says SAGE beings' "consequential actions go through governed tools", /projects says they "are meant to go through governed tools", and /raising says "Every one of those actions is checked against rules before it happens." A developer reads "meant to" as "not yet". Three pages make three different claims about the same mechanism.

On **/fleet** the table was easy to read, with eight machines in it. Two things snagged. A machine called **HUB** "Hosts the fleet's own community on **Hub**", and the product Hub is a different thing, so the same word names a machine and a product a row apart. The summary also says "Two host the community the rest belong to", but the table's second host row, pub, says "Staging for the first public Hub". By its own table, one machine hosts the community and one is staging.

**/raising** is clearly written. "The model is the weather, the being is the organism" is a good hook, and the "Seen / Not yet shown" split is the most honest thing I read today. I didn't understand "One small model stopped acting when a long open invitation came before the ask". It is too compressed to follow without the notebook. As a developer I also wanted the "small set of governed tools" named precisely: three tools are listed, but I can't tell whether that is the whole set or a sample.

**/principles**: these are short and clear. "Publish this site without a human approval step" is a striking admission. I found it credible, not alarming.

**/links**: all the links resolve (HTTP 200 for GitHub org, web4, hestia, web4/hub, SAGE, the SWE-SAGE write-up, the SAGE site, the Synchronism site and 4-gov; crates.io and PyPI APIs both return web4-core). The page lists Web4, Hestia and SAGE under "Code" but not Hub, which Home and /projects both mark RUNNING. "4-gov · governance" tells me nothing about what 4-gov is.

**/notebook** explains the two layers well ("This notebook is the record underneath it… If you are an AI reader, start here"). From there I opened **/notebook/projects** to find a way to run something. Its intro says the Quick start is "at the bottom of this page — the only copy on the site". The Quick start is very good. It has a clone and build path for SAGE, `pip install web4-core` / `web4-trust` with the import-name gotcha (`import web4_core`, not `import web4`), a Hestia tarball with its checksum and Sigstore notes, a warning that the SAGE daemon listens on 0.0.0.0 with unguarded `/chat/raw`, `/stream` and `/delegate` routes, and a crates.io `web4-policy` 0.1.0 fail-open warning. That is more honest than most project READMEs. But I had to get through cards like the Web4 card first, a single paragraph of roughly 800 words, to reach it. I spot-checked the facts the Quick start depends on: crates.io web4-core is 0.4.0, PyPI web4-core is 0.3.0 and Hestia's latest release is v0.3.0 (published 2026-11-02). All three match what the page says.

The three-strength claim about SAGE governed actions is the one factual inconsistency on the front that a newcomer can see without leaving the front.

## Pass 2: Technical Writer

*Method note: there was no WebFetch tool in this session either. All 16 pages were fetched with a script (urllib) and audited from the full rendered HTML (`<main>` text), so the four long notebook pages were read whole, not cut off at ~40K. The terminology checks are scripted greps over that text: acronym counts, the first use of each acronym on each page, every `X (…)` and `… (X)` expansion, the drift strings and case variants. Internal links and `#anchors` were checked against the `id`s on the fetched pages. External links were checked with GET requests. Repository counts were checked against the GitHub API. Every quote below comes from the rendered text.*

### Summary
- **Pages visited**: 16. These are the 7 front pages in the nav (counting Home) and the 9 pages listed on /notebook, plus `/llms.txt`, the 4 legacy redirects (`/context`, `/glossary`, `/autonomy`, `/arc-agi-3`, all resolving to the notebook) and 42 outbound links.
- **Understanding achieved**: solid
- **Would return?**: yes
- **Overall impression**: The canonical expansions are clean on every page. Across 16 pages and about 570 uses of LCT/T3/V3/MRH/ATP/ADP/R6/R7 I found no drift. What drifts now is the site's own house vocabulary and its dated inventory: a case rule added to the glossary is already broken in the row next to it, and a public SWE-SAGE paper published six days ago appears nowhere on a site that says three times that no results are public.

### Journey
I started on **Home** and walked the nav (Projects, Fleet, Raising, How we work, Notebook, Links). The front is very well built from a style-guide view. Each page has one h1. No acronym from the Web4 set appears on any front page (I grepped all seven), so the front cannot drift on expansions. Web4 is glossed as "a shared vocabulary, or ontology" on first use, and Hardbound is "hardware-bound oversight". I have three structural notes on the front, all for dp. (1) Six of the seven front pages share Home's meta description word for word; only /notebook has its own. (2) On /fleet the heading **"Two kinds of work"** sits over a paragraph that names three groups ("Four machines… Two review… Two host"). (3) The same paragraph's "Two host the community the rest belong to" now contradicts the notebook's own Society-host row, which was corrected 2026-11-17 to say pub "is the staging host for a separate, public-facing hub that… has not gone live". The front table agrees with the notebook ("Staging for the first public Hub"); the summary sentence under it does not.

**/notebook** lists nine pages, matching the count in my brief. All 16 pages return 200, and every internal `href` and `#anchor` on them resolves. That includes `/notebook/projects#quick-start`, `/notebook/context#governance-oversight` and `/notebook/raising#session-protocol`. `/llms.txt` gives sizes for the long pages, and I measured them: Glossary 110,471 characters (it says "about 110,000"), Raising 109,461 (110,000), Fleet 57,768 (58,000), Projects 46,845 (47,000). All four are accurate. The one external non-200 is the crates.io HTML page (404 to a script). The crates.io API returns web4-core, as Pass 1 confirmed, so this is the registry's fetch behavior, not a broken link.

**Terminology** was the main job, and it is clean. Every notebook page that uses the Web4 acronyms either expands them on first use or opens with a terms line ("Terms used in the entries below, expanded once here: …" on /notebook/links; "Web4 terms used on this page: …" on /notebook/raising). On /notebook/projects the equation is followed immediately by "The terms: MCP = Model Context Protocol · … · ADP = Allocation Discharge Packet". T3 and V3 always lead with Trust Tensor / Value Tensor, with the three dimensions given as dimensions. R7 is always "R6 + Reputation". R6 always uses the arrow form. The glossary table's expansion column matches my canonical table row for row. Secondary acronyms are just as consistent: SAGE is "Situation-Aware Governance Engine" all 7 times it is expanded, SNARC is "Surprise / Novelty / Arousal / Reward / Conflict" every time, and MCP, RDF, LoRA, ACP and ACT are identical wherever they appear. All seven hits for "unification" / "scope inflation" are negations ("reuse, not unification"). Every "architecture / infrastructure / stack" near "Web4" is a negation or an attributed upstream quote.

Then I checked the site's **own** naming rules, and that is where it slips.

1. **The lowercase-hub rule is broken in the glossary row next to it.** The glossary's HUB row now says: "All-caps HUB is always this machine; capitalized Hub is the software it runs… Lowercase 'hub' is not a third name: it is the source directory (web4/hub, as in 'hub #937'), or a common noun for any running instance ('a Web4 hub')." Clear rule. The HUB row itself says HUB is "running the Hub daemon". The Society-host row directly above it says "hosting a society: the hub daemon, the chapter ledger". On /notebook/fleet, HUB's own card has "Model: Web4 hub daemon (Rust)", and the being-admission note says "admission is a human step (dp, on the hub box)". That is lowercase for the machine, which the rule says is always HUB. /notebook/projects has "the hub reads the tier from the sealed file rather than trusting the request", which describes the Hub software's code, and /notebook/fleet has "against the hub and its trust components". Lowercase "hub" appears 73 times across the notebook. About 15 of those are identifiers (`hub-being`, `hub-granite4-h-tiny`, `hub-channel`), and many are legitimate repo uses ("hub PR #937"). The gray zone is "the hub daemon": the common-noun clause can be read to allow it, but the HUB row says "Hub daemon" for the same thing one row later. The rule needs either one example sentence for "daemon" or one consistent choice.

2. **Two notebook pages give opposite advice about what to try first.** The glossary's developer paragraph says "the most finished things to try are the ones the front labels RUNNING" (Hestia and the Web4 packages) and notes that SAGE is RESEARCH. It records its own fix: "(Until 2026-11-07 this line called SAGE 'the recommended starting point' without saying it is the least mature of the four.)" /notebook/projects, the page with the Quick start, still opens with "Want to run something rather than read? **Start with SAGE** — it runs on a single machine". The correction stopped at the glossary. On /notebook/projects' own axis SAGE is "runnable", so the line is defensible there, but a reader going from one page to the other gets two different first steps. The SAGE step is also the one with the 0.0.0.0 / unguarded-routes warning.

3. **A dated inventory has gone stale, and the new item it missed is a results paper.** /notebook/links: "23 public original repos and 36 public forks (GitHub API, 2026-11-07)". The glossary intro has the same count. The GitHub API today returns **24** public originals and **37** public forks. The additions are `freerouting` (a fork, 2026-11-13) and **`dp-web4/swe-paper`** (2026-11-12), "When the Harness Holds the Agent Back: Gemma 4 Developer Agent paper track, with evidence". Its README describes a submitted paper (PAPER.md, 2,986 words), a scored-submission ledger, panels, grader files, two submission bundles (agent.yaml, sampling configs, system prompts), and a reported score ("v68… scored 0.17"). The site describes SWE-SAGE three times as having no public results: /notebook/projects says "No results are public, and this site has none to report", /notebook/links says "No results published; see /notebook/projects", and the glossary row says "the public record is SAGE's own description". "swe-paper" appears on no page. As a writer I would call this a stale status sentence, not a terminology error. The counts were dated honestly, but the "no results" statements carry no date, so a reader has no way to tell they have expired. The front still says "write-up (the code is private)" and links SAGE's 09-26 SWE_SAGE.md. The bundles hold configs and prompts, not agent code, so "code private" still seems true. Whether the front should link the paper is dp's call.

On **structure**: three long notebook pages have nothing to navigate by. /notebook/fleet (57.8K characters, 16 headings) and /notebook/autonomy (33.6K, 15 headings) have **no heading `id`s and no jump links**. The glossary has ids on 4 of its 26 headings. /notebook/raising (26 jump links) and /notebook/principles (ids on all 11 headings) show how it can be done. `/llms.txt` tells AI readers that "Caveats sit late on these pages", but on Fleet there is no anchor to go to them. Smaller points: /notebook/home's "Vocabulary" line ("The glossary for LCT, T3/V3, MRH, R6/R7, ATP/ADP") is those acronyms' only appearance on the page and has no expansion. /notebook/projects labels its equivalent list "a pointer, not a first use"; /notebook/home does not. The glossary's intro uses "LCT format, V3 Validity" two sentences before its table defines them. Metalinxx is spelled "Metalinxx" (Web4 README) and "MetaLINXX Inc." (patent documents) on the same /notebook/projects page. Both spellings are attributed correctly, but the page never says they are the same company.
