## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (/, /projects, /fleet, /autonomy, /raising, /principles, /context, /links, /arc-agi-3)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: I understood *what the lab is* in about two minutes and *what I could run* in about fifteen — the gap between those two numbers is the whole friction story.

### Journey

Landed on `/` from a repo README. The headline — "Eight machines. Forty original repos. One recursive learning loop." — plus the "New here? This site is acronym-dense. Start with the /context glossary" line immediately told me two useful things: this is a fleet-of-machines lab, and the site knows it's jargon-heavy. That second admission bought a lot of goodwill. Most sites like this let you drown.

The home page's vocabulary primer is the reason this pass went well. LCT, T3, V3, MRH, ATP/ADP, SNARC, MCP, RDF, and "synthon" are all expanded *on the landing page*, before I have to click anything. As a dev who normally bounces off ontology-flavored sites, I got through the whole home page without opening a second tab.

Went to `/projects` next, because that's where a developer goes. The **runnable / research-stage / private** status labels are the single most useful design decision on this site. I could immediately sort eleven projects into "I can clone this today" (SAGE, 4-Life, SNARC, Membot) and "this is a spec I'd have to read" (Web4, Synchronism, ACT, Oversight Plugins, AI DNA Discovery). Nobody makes me guess. The cards also honestly say what's *not* there — "Specification and schemas without runnable demo" for Web4, "hardware-anchored enforcement remains design target" for Hardbound. That's the kind of thing most projects hide.

Then `/links` for the quick start, and this is where I stalled. The quick start is:

```
git clone https://github.com/dp-web4/SAGE
cd SAGE
# See README for Python/conda setup and first session instructions
```

I came here *from* a GitHub README. The quick start sends me back to a GitHub README. That's a closed loop with no new information in it. I wanted one concrete command — the thing I actually type to see the 12-step loop do something, plus one sentence about what I'd see when it works.

`/fleet` was the most interesting page and the most opaque. Eight machines with real hardware (Jetson AGX with 122GB unified memory, Jetson Orin Nano 8GB, RTX 4090 Mobile, Mac Mini M4, RTX 2060 SUPER, Radeon Pro W5500) — that's a fleet I believe exists, because nobody invents a Radeon Pro W5500. But the role strings stopped me: "Thalamic router dispatcher", "Habit compiler; motor skills tier", "Reward prediction error signal; data czar", "Metacognition detector; crystallization evaluator". The page does say vocabulary in the cards is defined in `/context#glossary`, and it lists which terms it covers (T3/V3, MRH, SNARC, LoRA, MCP, crystallization, chapter ledger, chapter law) — but the brain-analogy *role names* aren't in that list, and they're the part I actually wanted decoded. The line "Identity lives in state files and prompt construction, not in model weights. The model is weather. The identity is organism" is the best sentence on the site and it's stranded at the bottom of a page most devs won't reach.

`/autonomy` sold me. A timeline of 31+ scheduled tracks with a stated safety posture ("detect-and-revert... not prevent") and a named worst-case ("the maintainer loop... the only track that ships changes to the public site without a human gate") reads like something built by people who've had it break. I trusted the rest of the site more after this page.

`/raising` and `/principles` are the philosophy pages. I skim theory, so I skimmed — but the deflationary caveat ("everything on this page might be competent context engineering and nothing more") caught my eye precisely *because* I was skimming. Same with `/arc-agi-3`: the metric tile itself carries "Claude Opus 4.6, network access", so I never got to form the wrong impression that a Jetson scored 94.85%. The missing ablation is stated plainly.

`/context` is enormous — a ~40-term glossary plus a dozen explainer sections. It's the reference the rest of the site promises, and it delivers. It's also where I finally reconciled the session numbers that had been bugging me since the home page (see below).

### Unanswered Questions

1. **What do I actually run first, and what do I see?** The quick start clones a repo and points at a README. One command with expected output would close this.
2. **Which loop is "one recursive learning loop"?** Three candidates on the site, no disambiguation at the headline.
3. **Where does the 12-step loop live in the code?** No file, module, or directory pointer anywhere on the site.
4. **Can I run SAGE on hardware I own?** Every machine listed is a Jetson, an M4 Mac, or a discrete GPU box. Is there a CPU-only or small-GPU floor? "On-device" implies constraints nobody states.
5. **What's the actual interface between the projects?** I understand SAGE runs a loop and Web4 is an ontology. I do not understand what a SAGE instance *calls* to use Web4 — is it MCP tool calls, a library import, an RDF store it writes to? The equation tells me the composition; it doesn't tell me the integration.
6. **Do the eleven projects need each other, or can I take one?** If I only want SNARC (salience-gated memory sounds immediately useful to me), do I inherit the whole ontology?
7. **What is a "track," concretely?** /autonomy calls them "scheduled autonomous jobs with declared scopes." Is that a cron entry running Claude Code with a prompt file? A daemon? The registry is named as SQLite, which suggests something inspectable — but never shown.

### Verdict

This is the rare research site that respects a developer's time: it tells you upfront that it's acronym-dense, defines its vocabulary on the landing page instead of behind a link, labels every project runnable-vs-spec so you know what you can actually clone, and states its own limitations (the ungated maintainer push, the missing ARC ablation, the unrun deflationary control) without being asked. I came in expecting ontology fog and got a fleet inventory with hardware model numbers.

What it doesn't do is close the last mile. Every path that should end in "and here's what you type" ends in "see the README" or "see /context" instead. Two additions would move this from *legible* to *actionable* for my persona: one real first command with expected output, and one code-location pointer per runnable project. The site has clearly been optimized for comprehension; it hasn't yet been optimized for the moment right after comprehension, when a developer decides whether to clone.

Would I return? Yes — for SNARC and Membot specifically. Those two solve problems I have, and they're both labeled runnable.

**(2) is nearly clean, with one weak page.** The home page carries a full vocabulary primer (LCT, T3, V3, ATP, ADP, MRH, SAGE, SNARC, MCP, RDF all expanded before the reader clicks anything) plus a signposted pointer: *"New to this vocabulary? **(3) is where the real findings are.** Three number-continuity problems, described below. None of them is a wrong number — every figure I checked is internally defensible and the arithmetic reconciles. The problem is that the reconciliations aren't printed where the numbers are.

Two things I want to record as *improvements*, because they're the kind of fix that gets made and then forgotten:

- **The equation notation key is on the home page, not just the glossary.** It even distinguishes the two senses of `/`: *"`/` means two things here: 'verified by' in `T3/V3`, but a plain declared→discharged allocation pair in `ATP/ADP`."* Most sites would print the equation and let the reader infer one operator. This out-specifies the equation as usually written, which is the right direction for a page whose job is teaching.
- **The `/fleet` brain labels now carry their own on-page disclaimer**: *"The 'Brain:' labels below are role mnemonics the lab assigned, not measured functional homologies."* A caveat one page away is a caveat that doesn't travel; this one is adjacent to the thing it qualifies.
