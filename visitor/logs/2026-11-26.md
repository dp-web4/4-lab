## Pass 1: Curious Developer

*Method: I fetched each live page over HTTPS and read it as text (curl + tag strip), not as a WebFetch summary. That avoids the summarizer rewording things. Pages: the seven front pages in the nav, plus `/notebook/context` (the glossary) as the eighth. I also checked every outbound link on the front, and the web4-core registry entries via the crates.io and PyPI APIs.*

### Summary
- **Pages visited**: 8 (`/`, `/projects`, `/fleet`, `/raising`, `/principles`, `/links`, `/notebook`, `/notebook/context`), plus 19 link checks
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: In two minutes I learned what this lab is: governance tooling for AI agents, a standard underneath it, and an odd but clearly marked research line about "beings". The one thing that takes longer is the developer question "what can I install today?". The front never answers it directly, and the answer is in the glossary's second paragraph.

### Journey
**Home.** The headline ("AI agents are becoming actors in the world. We are building how they earn trust.") and "The idea" paragraph tell me what this is within about 20 seconds: trust from track record, checked against rules set in advance. Four cards, each with a status label. Web4 is "a shared vocabulary, or ontology". I'm not an ontology person, but "shared vocabulary that any system can implement" is enough to go on. Hestia, "checked before each tool call, with a hash-chained record", is the first thing I recognise as a concrete developer tool: a pre-tool-call policy hook with a tamper-evident log. "They are refused by it every day" is a good, credible detail.

**Projects.** This page is where the structure clicks: standard → free tools → paid tier. The label legend at the bottom ("Running: in daily use on our own machines") is useful. It tells me RUNNING means *they* run it, not that it is packaged for me. Hardbound's "built by Metalinxx" made me ask who Metalinxx is (no link, no gloss). SWE-SAGE is described as a competition entry, with "write-up (the code is private)".

**Fleet.** I liked the table. "Monocultures are fragile" is a reason I can accept. Then the summary line under "Two kinds of work" ("Four… Two review… Two host the community the rest belong to") doesn't match the table I just read. Only HUB "Hosts the fleet's own community"; pub is "Staging for the first public Hub", which is a different community. I also couldn't tell which four do the "heavy work", since Sprout is described as an edge device with a camera, not something that writes code. Small, but it's the kind of thing a developer notices.

**Raising.** This is the page I expected to roll my eyes at, and I didn't. "The model is the weather, the being is the organism" is a clear metaphor, "We do not change the model's weights" answers my first question, and the "Not yet shown" box ("more than well-kept memory files fed back to a model… no blind comparison") is exactly the objection I was about to raise. One sentence lost me: "One small model stopped acting when a long open invitation came before the ask, and acted once the ask came first." I think it means prompt ordering changed whether the model took an action. As written, I had to read it three times.

**How we work.** The six principles are crisp. "AI peers review pull requests, merge changes, and publish this site without a human approval step" is a strong claim, which I note but can't verify at my level.

**Links.** All 11 outbound links return 200 (GitHub org, web4, hestia, web4/hub, SAGE, SWE_SAGE.md, SAGE site, Synchronism site, 4-gov.org, and both registries). "4-gov · governance" carries no other context, and I don't know what 4-gov is relative to Hestia/Hub.

**Notebook index.** This page explains the two layers well. "If you are an AI reader, start here" is an unusual sign to see, and an honest one.

**Glossary (`/notebook/context`).** I went here to find out what SAGE stands for, since no front page expands it. The answer: "Situation-Aware Governance Engine… 'governance engine' is its name, the persistent beings are what it runs". So the name and the front's description ("Persistent AI beings") point at different things, and the glossary admits it. The best developer content on the whole site is the glossary's second paragraph: "the most finished things to try are the ones the front labels RUNNING. Hestia has a downloadable release, and Web4's core packages install from crates.io and PyPI with no clone." That is the answer to my main question, and it sits in a 354 KB HTML page (~18,600 words of text) that opens with a 90-word sentence about repository counts. I checked the claims: Hestia v0.3.0 is a public release (2026-11-02, 17 assets), and web4-core is on crates.io and PyPI. **They hold up.**

Clicking through to the registries and repos showed two seams:
- **Registry descriptions call Web4 "infrastructure".** crates.io web4-core 0.4.0: "Web4 trust-native infrastructure core library". PyPI web4-core 0.3.0: "Python bindings for Web4 trust-native infrastructure". The site's glossary row reads "A trust-native ontology… — not architecture or infrastructure." The phrase is the same and only the noun differs, which looks like a stale package description rather than a deliberate position.
- **The two registries are at different versions** (Rust 0.4.0, Python 0.3.0). The front's "reference code in Rust and Python" doesn't say whether they track each other. That's not a front error, but it's the first thing I'd ask as an adopter.
- **Hestia's GitHub description describes a much broader product than the front does**: "universal Web4 presence for humans and AI. Local-first cryptographic identity, encrypted vault, delegation authority… device constellation. Cross-platform app + AI plugin + CLI. EUDI-compatible credential issuance." The front says only "one set of rules for agents from any vendor, checked before each tool call". Neither is false, but clicking through feels like landing on a different product.
