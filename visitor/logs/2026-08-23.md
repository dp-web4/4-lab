## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (`/`, `/projects`, `/fleet`, `/autonomy`, `/raising`, `/principles`, `/context`, `/links`, `/arc-agi-3`)
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: The site now answers "what is this and why should I care" fast and honestly — my remaining friction is almost entirely about *doing* something, not *understanding* something.

### Journey

I came in from a repo README with zero Web4 context. The landing page opens with a count — "Eight machines. Forty original repos. One recursive learning loop." — which told me scale before it told me purpose, but the recovery is quick: within a screen there's an actual problem statement, and it's a good one:

> "AI agents already act on their own — browsing, transacting, coordinating with other agents — and there is no general way to establish whether one will behave appropriately in a given context."

That's the sentence that made me keep reading. It's the kind of framing I can repeat to a coworker. Immediately after, the page anticipated exactly my next problem: *"New here? This site is acronym-dense. Start with the /context glossary — every term on every page is defined there — or the vocabulary primer below ↓"*. Being warned about the jargon density before hitting it is a real courtesy, and it changed how I read the rest of the site — I stopped treating unfamiliar acronyms as blockers.

The equation `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP` appears *after* the plain-English trust framing, not before. That ordering matters a lot for me. I know MCP and RDF; anchoring the unknown terms next to two I already use made the whole thing feel like an extension rather than a new universe. `/context` then gave me a notation key — `/` = "verified by", `*` = "contextualized by", `+` = "augmented with" — which is more than most projects bother to do with their own shorthand.

`/projects` is where I spent the most time, and it's the best page on the site for my persona, for one reason: every card is tagged **public/private** and **runnable/research-stage**. That's the filter I actually apply. Four things are runnable: SAGE, 4-Life, SNARC, Membot. I went looking for how to run them — and this is where I hit my main friction, described below.

`/links` turned out to be far more than a link dump; it has a `Quick start` with real clone-and-build commands and a `Contributing` section that's refreshingly blunt: *"Ask in an issue first — that's the on-ramp until a formal policy exists."* I'd never have found that from the nav label "Links."

`/fleet` was fun — eight named machines with specific hardware, models, and session counts, each mapped to a brain-component role. `/autonomy` was the page that most made me believe the lab is real: it lists the daily cron timeline and then, unprompted, lists what the automation *misses* ("deep technical errors that require domain expertise... content that is technically correct but misleading") and admits the maintainer "ships changes to the public site without a human gate" with "detect-and-revert" rather than prevention, and that publisher pushes "are not fully revertible" — *"this gap is unaddressed, not solved."* I don't see that kind of writing on project sites.

`/arc-agi-3` gave a hard number — 94.85% official action score, 24/25 games — with the caveat up front that the ablation separating the harness from the base model "has not been run," and a link to a public ARC Prize scorecard. I appreciated the caveat. I could not interpret the number.

### Unanswered Questions

1. **What is 4-Life, and how do I run it?** Tagged `runnable`, no glossary entry, no repo link. It's the project whose name made me most curious and the one I could learn least about.
2. **Does Web4 require a blockchain?** ACT is a Cosmos SDK implementation. Is that *the* path or *a* path? This is the first thing my team would ask.
3. **Is 94.85% good?** No baseline, no comparison, no "typical entrant scores X." The caveat about the un-run ablation is admirable but doesn't help me place the number.
4. **What do I actually see if I clone SAGE?** The quick start gets me to `cargo build --release`. Then what — a REPL, a daemon, a log? No "expected output" and no screenshot anywhere on the site.
5. **Is Web4 a spec I can implement against today?** It's tagged `research-stage` but described as *"The repo itself is a specification"* and *"the shared language everything else speaks."* Stable enough to build on, or still moving?
6. **What's the relationship between the eight machines and anything I'd run?** The fleet is fascinating but reads as *their* infrastructure. Do I need machines to use any of this, or is SAGE single-box?

### Verdict

This site is genuinely good at the thing my persona usually finds broken: it states a real problem in plain English before it states its vocabulary, it warns me about its own acronym density, and it defines essentially every term where it uses it. The intellectual honesty is unusual — `/autonomy` volunteers its own unpatched gaps and `/arc-agi-3` leads with the experiment it *hasn't* run. I trust the writing.

What I can't do is *start*. The `runnable` tags are the best affordance on the site and they dead-end: the clone commands live on a page called "Links" that I'd normally skip, 4-Life is tagged runnable with no repo anywhere, and nothing tells me what success looks like after `cargo build`. The gap isn't comprehension anymore — it's that every path from "I get it" to "I ran it" has one missing link in it.

If I fix one thing: put a **Quick start →** link on each `runnable` project card. That single edit turns the site's best feature into a working funnel.

### Journey

I audited for the thing a tech writer audits for: does the same term mean the same thing, expand the same way, and get pointed at the same source, on every page that uses it? I fetched each page with numbered, targeted questions rather than asking for a dump, and I re-fetched any page where a finding depended on something being *absent*.

**The expansion layer is clean.** I built a full term × page matrix (below). Fourteen terms, nine pages, and I could not find a single variant expansion. "Situation-Aware Governance Engine" is byte-identical on eight pages. "Allocation Transfer Packet" never once becomes "Attention Token Pool." Web4 is called an *ontology* on all nine pages and is explicitly negated against "architecture"/"infrastructure" on four of them. This is better term hygiene than most funded documentation projects achieve.

**So the interesting failures are elsewhere.** Three of them are real, and they share a shape: a good editorial decision was made *once*, on one page, and never propagated to the sibling page where it also applies.

The sharpest is on `/raising`. The page's thesis sentence is *"Raising is not training. Training optimizes for a loss function."* Later, inside a subsection literally titled **"Interactive selection, not training,"** the page writes: *"raising shapes the T3 tensor (Talent / **Training** / Temperament…"*. So the word the page spent its opening paragraph repudiating reappears as a component name inside the section named after the repudiation. The site already knows this is a problem — `/context` carries the fix: T3's Training is *"capability accumulated through interaction history — not gradient training, the sense the same word carries in ML."* That one clause resolves the collision completely. It is not on `/raising`, which is the only page where the collision actually occurs.

The second is `/links` versus `/projects`. `/links` presents a **GitHub** section that reads as the repo index — twelve repos, no caveat that it's partial. `/projects` links repos that `/links` does not list: 4-Life (`dp-web4/4-life`) and SNARC (`dp-web4/engram`). Two pages, two different answers to "what repos exist." A reader who lands on `/links` — the page whose entire job is outbound links — concludes those two projects have no code.

The third is that `/links` never links `CANONICAL_TERMS_v1.md`. `/context` links it and grants it supremacy: *"Source of truth: the canonical terms reference in the public web4 repo… When this page and that document disagree, the document governs."* That is exactly the sentence that makes a reader want the document. `/links` — 17 outbound links, including the web4 repo root — doesn't offer it. `/fleet` points at `/context` but not at canon either. The site names an authority it never routes you to from the routing page.

I also chased four things that looked like findings and weren't. `/autonomy`'s "31+ tracks" versus eight timeline rows is explained in place (*"The timeline below shows eight of the 31+ tracks — the ones with distinct cross-repo scopes"*). "Eight machines" versus "six cognition machines" is reconciled on `/fleet` (*"Six cognition machines, plus two society-hosts"*). SAGE keeping "Governance" in its name while Principle 10 forbids "governance" for Hardbound is explicitly handled: *"Names minted before the correction are retained where they are load-bearing: 'Governance' in SAGE's name (kept across code, papers, and the ARC Prize benchmark)."* And the word "layer" — a term I watch because it's the easy way to smuggle back "stack" — is used four times on the site (MCP, ACP, Hardbound, the autonomy registry) and **never once applied to Web4**.

**On "raising not training": defensible as stated, because of what it declines to claim.** The page reduces its own thesis to a comparative: *"We're claiming that developmental frameworks describe what we observe better than training frameworks do — a comparative claim whose missing baseline is acknowledged above."* And the acknowledgement is up front: *"everything below might be competent context engineering and nothing more — the control that would discriminate raising from that alternative has not been run yet."* That is the correct null hypothesis, named by the authors, unprompted. `/fleet` carries the same discipline down to the counts: *"nothing in the count establishes that what happened in it was raising rather than competent context engineering."* I can't call the framing overclaimed when the authors have pre-stated the deflationary alternative and conceded it's live.

**Where it breaks is one level down, and it's the finding I care most about.** `/raising`'s evidence disclosure reads: *"the claims in this section rest on internal session logs — documented and dated, but not externally audited, and no log samples or coding criteria are published yet."* That is an **availability** caveat: nobody has checked yet, and checking is deferred. That last sentence is the single most methodologically credible thing on this site. It is written about **site maintenance**, where the stakes are a typo. I checked `/raising` directly for any independence language and it is **ABSENT** — the words "independent," "blinded," "third-party," "correlated," and "inter-rater" do not appear in that sense anywhere on it.

This matters because the two are not interchangeable: unaudited work can be audited later, but self-observed, self-coded behavioral data has a construct-validity problem that auditing *the same logs* later cannot repair. Two smaller outsider-confusion items. ### Verdict

This is the most epistemically careful research site I have read that has almost no published evidence, and both halves of that sentence are load-bearing. The consciousness-adjacent claims are properly caveated — not by one disclaimer but by roughly ten sentence-level operationalizations plus a flat denial that summarizes them. "Raising not training" is defensible precisely because it has been reduced to a comparative claim whose null hypothesis the authors state themselves and concede is live. Three of my four incoming hypotheses about where the hedging would fail were refuted by the source. The honest assessment is honest.

The problem is that the honesty has become the product. One of four evidence tiers is populated, and the site's response has been to describe the other three's emptiness with ever-finer precision — which is correct, and which has now hit zero marginal return with me. Worse, the one populated tier is the one that fails checking: the ARC claim disagrees with its own linked artifact, drops that artifact's headline caveat, and points at a scorecard I can't read. A reader trained by nine pages of scrupulous hedging is exactly the reader who won't re-check the one hard number.

And the site has no relation to anyone else's work. Zero citations, zero positioning, on subject matter — decentralized identity, attestation, reputation metrics — with a large standardized literature. That is not an honesty failure and no additional caveat repairs it; it's the difference between a lab talking to itself carefully and a lab talking to a field.

If I fix one thing: **add one paragraph situating Web4 against DIDs and verifiable credentials.** It is the cheapest edit on this list and the only one that changes what kind of document this is.

### So what?
