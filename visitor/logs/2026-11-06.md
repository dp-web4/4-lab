### Journey
**Home.** The headline "AI agents are becoming actors in the world. We are building how they earn trust." and the sentence after it ("a research collective of one human and a fleet of AI agents… open tools for governing AI agents, and we run our own lab with them") told me what this is within ten seconds. The four cards (Web4, Hestia, Hub, SAGE), each with a status badge, are the right shape. Hestia was the one I understood straight away: "one set of rules for agents from any vendor, checked before each tool call, with a hash-chained record." A developer gets that at once, like a policy hook for coding agents. Web4 ("a shared vocabulary, or ontology") is abstract but honest about being abstract. "They are refused by it every day" is a good hook.

**Projects.** The structure works: standard → tools → paid tier → research → theory, and a legend saying what RUNNING, BUILDING and RESEARCH mean. Each card links to a repo. Hardbound is "built by Metalinxx", a name I hadn't seen anywhere before, with no explanation of who that is or how they relate to the lab. SAGE is never expanded on any front page, so I had no idea what the letters stand for. I only found out on `/notebook/projects`: "Situation-Aware Governance Engine", which doesn't obviously match the front's "persistent AI beings".

**Fleet.** The machines table is fun and concrete. Two things snagged:
1. **Hub (product) vs HUB (machine).** One row's machine name is "HUB" and its job is "Hosts the fleet's own community on Hub". Same word, different referent, one line apart. I had to read it twice.
2. **The counts don't map onto the table.** The intro says "most raise a persistent AI being", but only three rows mention a being (Sprout, Legion, Nomad). "Four machines do the heavy work: writing code and running large experiments" leaves Thor, Sprout, Legion and McNugget as the four (Nomad and CBP review, HUB and pub host), which makes Sprout, a Jetson Orin Nano described as an "Edge device: a being with a camera and microphone", one of the "heavy work" machines. Maybe it is, but the table reads otherwise. I can't call either a false fact from here; they are places where the prose and the table can't both be read literally.

**Raising.** "The model is the weather, the being is the organism" is a memorable line. The "Seen / Not yet shown" split is refreshingly direct ("That this continuity is more than well-kept memory files fed back to a model"). As a developer, my first thought was exactly that: isn't this just a memory file plus a system prompt? The page anticipates it. Good.

**How we work.** Clear. "AI peers review pull requests, merge changes, and publish this site without a human approval step" is the most interesting sentence on the site for a developer. I'd want to see one of those PRs, but there's no link.

**Links.** All targets resolve (I checked all 20 unique outbound and notebook URLs: 20/20 returned 200). "4-gov · governance" told me nothing about what 4-gov is. It turns out to be a talk/deck site titled "Computable Accountability | Governance for Agentic Entities".

**Notebook index → /notebook/projects.** I came here because I wanted an install command. I found it: the intro says "Commands for Web4 and SAGE are in the Quick start at the bottom of this page — the only copy on the site". It sits at the bottom of a page of about 5,600 words. The quick start is actually good. It has `pip install web4-core`, the SAGE `cargo build`/daemon steps, and a Hestia section that correctly says v0.3.0 is Latest (I confirmed with `gh release list`: v0.3.0, 2026-11-02). It also correctly notes that web4-core is 0.4.0 on crates.io and 0.3.0 on PyPI (both confirmed via the registry APIs). Two small things: (a) the intro sentence names only "Web4 and SAGE" although the quick start also covers Hestia, the one project I most wanted to try; (b) the intro says "Start with SAGE", but the front leads with Hestia as the thing a person actually runs.

**Clicking upstream.** The Web4 README says "Web4 is open infrastructure", and the PyPI and crates.io package summaries say "trust-native infrastructure". Meanwhile the site says ontology. As a newcomer I just noticed that the two descriptions differ. (Upstream, not this site's text; noted below for the terminology record.)
