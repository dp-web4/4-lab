### Summary

What's wrong is on the front, in what it says about the projects. ### Journey
I went to Projects first, as I would for a site describing repos I commit to.

**Web4 card.** "The open standard, written as an ontology … Published specification, with reference code on crates.io and PyPI" is accurate. Both registries serve `web4-core` 0.3.0. Their summaries say "trust-native **infrastructure**" (crates.io: "core library"; PyPI: "Python bindings"). That's upstream drift, not site drift, and `/notebook/projects` already attributes it ("The registry descriptions call it 'infrastructure'"). The web4 README now leads with "the open substrate", has a section headed "The stack", and says "open infrastructure". The notebook quotes and attributes all three, which is the right handling. The Hub link (`web4/tree/main/hub`) returns 200.

**Hestia card (front Home + /projects).** Home says Hestia keeps "a record the agent cannot edit". /projects says each action is "recorded where the agent cannot change it". The hestia README says the opposite, as a stated assurance ceiling: *"all of the above is profile **A1**, a cooperative gate running as the same UID as the operator. Tamper-**evident**, not tamper-proof."* It goes on: "two environment variables suffice today", and "Enforcement against a determined agent needs A2+ (separate UID) and is not available now." A record kept under the agent's own UID is one the agent *can* edit. Hestia's claim is that such an edit would be *evident*. That makes this a false fact, not a missing caveat. The fix costs no words: "a record the agent cannot quietly edit" or "tamper-evident". It has been in the dp queue since 10-04 and is still live.

**Synchronism card.** "It supplies the equations that Web4's trust model builds on." web4 `AGENTS.md` line 107 says: *"`Synchronism` | Blue-sky conceptual lineage; not an engineering dependency"*. The site's own `/notebook/projects` agrees with upstream: "conceptual lineage for Web4, not its foundation in the derivational sense … no Web4 primitive (LCT, T3/V3, MRH, ATP/ADP, R6/R7 …)". So the front inverts both the repo and its own notebook. As a Web4 contributor, this is the line I'd object to most: it tells a reader that our trust tensor is derived from a physics conjecture. Carried since 10-04 and still live.

**SWE-SAGE card (+ /links "Code").** Pass 1 logged a 404. The upstream explanation is that the repo is private on purpose. SAGE `LATEST_STATUS.md` item 10 says: *"`SWE-SAGE` is the **private** Gemma 4 software-engineering-agent competition workspace … competition implementation is not live-published."* So /links files a private repo under the heading "dp-web4 on GitHub · everything public", and /projects gives it a GitHub link. The notebook has **0** mentions of SWE-SAGE on all 9 pages. Yet /projects ends "Every repository, with its maturity and what each claim rests on, is in the notebook", and SWE-SAGE is the exception. /fleet's "Nomad … smallest being, for SWE-SAGE" has no notebook source either.

**SAGE card + front /raising.** The front says beings "act only through governed tools" (/projects: "every action they take goes through governed tools"), and /raising adds "Every one of those actions is checked against rules before it happens, and recorded."
