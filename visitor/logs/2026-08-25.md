## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 site pages (/, /projects, /context, /arc-agi-3, /fleet, /autonomy, /raising, /principles, /links) + 2 linked GitHub repos (SAGE, ARC-SAGE)
- **Understanding achieved**: good (on *what* this is), partial (on *why I'd use it*)
- **Would return?**: yes
- **Overall impression**: The clearest, most self-honest research site I've landed on from a README — and then the one number I could actually verify by clicking their own link didn't match.

### Journey

I came from a dp-web4 repo README with no context. Landing page headline is **"Eight Machines, One Recursive Learning Loop."** That tells me the *scale* of the thing, not what it's for. The paragraph underneath is much better and should probably be higher: *"AI agents already act on their own — browsing, transacting, coordinating with other agents — and there is no general way to establish whether one will behave appropriately in a given context."* That's a problem statement I recognize. I've shipped agents. I know that hole. If the headline said that, I'd have been hooked in five seconds instead of thirty.

Then immediately: `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP`. Every symbol is expanded right there, which I appreciate — no page on this site made me open a second tab to decode an acronym. But the notation key says `/` means **two different things on the same line** ("verified by" in `T3/V3`, a declared→discharged pair in `ATP/ADP`). The site says this out loud, which is more honest than most, but it also tells me the equation isn't an equation — it's a mnemonic wearing math notation. As a developer, that's the moment I recalibrated from "spec" to "manifesto." Not a dealbreaker; just a different reading mode.

**/projects is the best page on the site** and it's where I'd send anyone. Eleven cards, each with a public/private badge and a maturity badge, and — critically — the page *defines* the badges: **runnable = "clone it and it executes end to end today"**, research-stage = design docs/specs/experiments. Four of eleven are runnable (SAGE, 4-Life, SNARC, Membot). That ratio is stated plainly instead of hidden. I have never seen a research site self-label 6 of its 11 projects as "design docs only." That bought a lot of goodwill.

So I did the obvious thing and clicked through to SAGE, the flagship runnable one. Quickstart:

```
git clone https://github.com/dp-web4/SAGE.git && cd SAGE
python3 -m sage.instances.init --machine mybox --model gemma3:4b
cd sage-rs && cargo build --release && cd ..
SAGE_MACHINE=mybox SAGE_MODEL=gemma3:4b ./sage-rs/target/release/sage-daemon
```

That's Python **and** a Rust toolchain **and** a local Ollama model pulled, and what I get at the end is a daemon plus a dashboard on `:8760` — no demo script, no seeded example. It probably does execute end to end. But "clone it and it executes end to end today" set me up for `npm start`, and this is a forty-minute setup with three prerequisite ecosystems that the project card doesn't mention. The badge definition is good; it just needs a prerequisites line so "runnable" and "runnable *by me, tonight*" don't get conflated.

**/arc-agi-3 is where I went next**, because it's the only page promising an externally-scored result, and an external score is the thing that makes a site like this credible to someone like me. Page says **"24/25 games solved (96.0% game-solve rate); 94.85% official action score (Claude Opus 4.6)"**, ~$250 API spend. It also leads with a caveat I genuinely respect: *"the ablation that would separate the harness's contribution from the base model's (same model, no harness) has not been run"* — and *"'suggests' is the honest verb."* Good. That's a lab talking.

Then I clicked their own **"ARC-SAGE paper & code (MIT-0)"** link, which is right there on the page, to see the per-game breakdown. The repo README says **"23 of 25 games WIN"**, environments won **23/25**, levels completed **175/183**, and names the two partial games explicitly (bp35 at 5/9 levels, lf52 at 6/10). The 94.85% matches exactly. The game count does not. The site is one game ahead of its own repo.

I want to be clear about why this one lands harder than anything else I found: this is the *only* claim on the site I could independently check, the site *handed me* the link to check it with, and it came back different. Everything else on the site is caveated so carefully that I was willing to take it on faith. This one I didn't have to take on faith, and it didn't hold. If the repo is right, the site's headline result is inflated by one game and the 96.0% rate is wrong (23/25 = 92.0%). If the site is right, the repo is stale — but then the site should say so, because the repo is where it sent me.

Second thing on that page: the site describes the challenge as *"25 unknown interactive games with no instructions, no documentation, and obfuscated engine source."* I read that as "black box, solved from observation." The repo's actual method says: *"Read the engine source. Decode obfuscated function names, identify object types, understand physics, win conditions, interactions."* So the source **was** available and **was** read — obfuscated names were decoded. Those are two very different achievements to a developer. Reverse-engineering an obfuscated engine is legitimately impressive work; it just isn't the same as inferring rules from pixels, and the site's phrasing let me believe the second one.

**/context** (nav calls it "Glossary", URL is `/context` — small thing, but I hunted for a "Context" link for a second) is ~45 terms, every one expanded, and it links the canonical terms doc on GitHub. Two entries stopped me because of how candid they are: **coherence** — *"used in three related senses on this site... with no single operational definition yet"* — and **attractor** — *"used on this site as a METAPHOR, not a formal dynamical-systems object."* A glossary that admits its own load-bearing word is undefined is doing something most docs won't. It also means that when I hit "coherence" on four other pages, I now know it's a gesture, not a quantity.

**/principles** — ten of them, and Principle 5 (Synthon) openly says the concept is *"defined through coherence, and coherence is in turn partly defined through the synthon."* A circular definition, disclosed. Same reaction: respect for the disclosure, but the concept isn't usable by me. Principle 6 ("document failures") is backed by an actual failure — *"p_crit derivation failed catastrophically — 400x error"* — which is the most convincing thing on the page precisely because nobody puts that in a shop window.

**/fleet** — eight machines, hardware and model per box, session counts per machine. It flags its own staleness in a way I'd steal for my own docs: the SAGE repo's fleet manifest *"has not been updated since 2026-03-08, so it currently disagrees with this page — the manifest is the stale side"*, and this page declares itself the source of record. And `pub`'s session count is *"deliberately blank, not zero"*. Someone thought about the difference between missing and zero. That's a real engineer.

**/autonomy** — eight daily tracks on a timeline, "31+ autonomous tracks" claimed. The caveats are the best-written prose on the site: *"'Autonomous' here means unattended and self-scheduled, not self-directed in the AI-safety sense of choosing its own goals"*; and, remarkably, *"the visitor and maintainer tracks are LLM sessions drawn from the same model families as the tracks that author the content they audit — their misses are correlated."* They're telling me their own QA loop has a blind spot. But: **the page references "dated audit logs" and links to none of them.** Every other claim on this site is either caveated or checkable. This one is neither — it's the one place where I'm asked to believe a thing exists without being shown it. Given the site already publishes daily-cycle prose, one link to one real log file would do more for me than another paragraph of hedging.

**/links** — good link inventory, real contact address, quickstart repeated. But this is the one page where the terminology discipline breaks (see audit).

### Verdict

This is a site that mostly earns trust the hard way: it labels 6 of its own 11 projects as design-docs-only, admits its QA agents share a blind spot with the agents they audit, admits its central term has no definition, and publishes a 400x derivation failure. I came in expecting a manifesto and found something considerably more disciplined than that.

Which is exactly why the ARC number stings. It's the one claim I could check, the site gave me the link to check it, and the linked repo says 23 where the page says 24. On a site this careful, one unforced overclaim on the single externally-verifiable result does more damage than all eleven of my other findings combined — because it's the only one where I stopped extending the benefit of the doubt. Fix that and the "obfuscated source" phrasing, link one real audit log, and I'd not only return, I'd clone SAGE.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 site pages (/, /projects, /context, /arc-agi-3, /fleet, /autonomy, /raising, /principles, /links) + the canonical terms reference the site cites as its source of truth
- **Understanding achieved**: solid (structure and terminology), partial (what several core terms actually denote)
- **Would return?**: yes
- **Overall impression**: Every acronym expansion on this site matches the canonical table exactly — so I went and read the canon itself, and found the site's R6 is missing canon's arrow on all four surfaces that print it.

### Journey

I audit terminology for a living, so I did this the boring way: fetch all nine pages, extract every acronym expansion, build a matrix, look for cells that disagree.

The matrix came back **clean**. LCT is "Linked Context Token" on /, /projects, /fleet, /raising, /links, and /arc-agi-3 — six surfaces, one string, never "Lifelong Capability." T3 is "Talent / Training / Temperament" on seven pages. V3 is "Valuation / Veracity / Validity" on seven, including /autonomy where it appears inside a sentence about ADP recharge. MRH, ATP, ADP, MCP, RDF — all uniform. I could not find a single expansion-level contradiction between any two pages.

That is an unusual result and I want to be precise about what it means: it means **the expansions are clean**, not that the terminology is. So I changed method. If the pages agree with each other and with the table I was given, the only remaining place a defect can hide is *between the table and the actual source*. The site helpfully makes this checkable — /context links `CANONICAL_TERMS_v1.md` in the public web4 repo and calls it "Source of truth." So I read it.

**That is where the audit stopped being boring.**

Canon's R6 entry reads: **"Rules / Role / Request / Reference / Resource → Result."** An arrow before the last element. The site writes it as **"Rules / Role / Request / Reference / Resource / Result"** — six slash-separated peers — on /projects, /links, /arc-agi-3, and /context. All four surfaces, consistently wrong in the same direction.

This is not cosmetic. Canon's notation says five things are *inputs* and the sixth is what they *produce*. The site's notation says six things are the same kind of thing. Someone reading "Six-Element Action Framework: Rules / Role / Request / Reference / Resource / Result" will build a mental model of a six-field record; canon describes a five-field record plus an outcome. On a site whose stated differentiator is terminology fidelity, an arrow flattened into a slash is exactly the class of drift that matters — it changes the semantics while preserving every word.

Worse, from an auditor's perspective: **the reference table I was handed in CLAUDE.md contains the same flattening.** It lists R6 as "Rules/Role/Request/Reference/Resource/Result." So every previous audit that checked the site against that table returned CORRECT, and would keep returning CORRECT forever. The audit instrument shares the defect with the thing it audits. I only caught it because I went one level up to the source the site itself names.

I checked the same reference for the other four things I was suspicious of:

**R7 is canonical.** Canon has a full entry: "R6 + Reputation. A superset of R6 that adds reputation back-propagation." The site's glossary carries it and matches. But my CLAUDE.md table lists R7 under "Common Drift" with a strikethrough, i.e. instructs me to flag it as an error. Following my own instructions literally would have me file a drift report against correct, canon-backed content. **The instruction is the stale side, not the site.** I am flagging this as an instrument defect, not a site defect, and I am explicitly not filing it as drift.

**Canon defines four relationship verbs the glossary doesn't have.** Federation ("coordination between multiple societies through signed gossip, consensus, and cross-society witnessing"), Pairing ("authorized operational relationship between entities. Revocable"), Delegation ("granting limited authority with constraints (budget, time, scope). Instantly revocable"), and Binding ("permanent attachment of identity to hardware or cryptographic proof. Irreversible"). The site's ~50-term glossary has Witnessing and none of the other four. Note what those four definitions *encode*: a revocability ladder — revocable, instantly revocable, irreversible. That is the part of canon a cautious reader most wants, and it is the part the site never reproduces. The glossary defines every noun in the Web4 equation and almost none of the verbs that connect them.

**Canon uses anti-definitions and the site copies none of them.** Canon writes "LCT is NOT: Lifecycle-Continuous Trust, Linear Context Tracker, or any other expansion"; "T3 is NOT: Trust-Tracing-Tensor, Trust-Transfer-Token"; "ATP is NOT: Attention Token Pool, Adaptive Trust Points, Alignment Transfer Protocol." This is standard practice in controlled-vocabulary work and it is free to adopt — the text already exists upstream. The site's glossary states what each term is and stops. Given that this lab's entire visitor track exists to catch these exact wrong expansions, publishing the wrong-expansion list on /context would convert an internal audit checklist into a reader-facing defense.

**Canon does not define the site's own most-used words.** Web4 itself: absent. Coherence, synthon, raising, attractor, Hardbound, hestia: all absent from canon. So for its six most load-bearing terms the site *is* the authority, while /context frames the whole glossary under a "Source of truth" pointer at a document that is silent on them. The provenance line is doing more work than it can support. A one-line split — these terms are canonical, these are lab-local and defined here — would fix it, and would also make the honest disclosures on `coherence` and `attractor` read as deliberate scoping rather than as gaps in a canonical vocabulary.

Two other structural observations from the sweep.

**The SAGE disclaimer fully propagates — and this refutes what I expected to find.** SAGE expands to "Situation-Aware Governance Engine," which contains a word this lab has formally deprecated. I went hunting for pages that print the name without the disclaimer, expecting the usual pattern where a fix lands on the main pages and misses the leaves. I checked all seven surfaces that expand SAGE — /, /projects, /fleet, /raising, /principles, /links, /arc-agi-3 — and **every one carries "'Governance' in SAGE's name predates the lab's governance→oversight correction," and all but one link it to `/context#governance-oversight`.** Seven for seven, including the two leaf pages I specifically expected to have been missed. That is complete propagation of a terminology fix across a nine-page site, which I do not often see, and it deserves to be recorded as a positive finding rather than passed over in silence.

**The numbers reconcile exactly.** I added the per-machine session counts on /fleet: 435 + 488 + 336 + 377 + 162 + 193 = **1,991**, exactly the figure quoted on /, /projects, and /links. Add HUB's 74 and you get **2,065**, also exactly as quoted. Repo counts: 21 public + 19 internal = 40 original, + 32 forks = 72 total. Every arithmetic relationship on this site closes. I checked because sites that quote aggregate figures on four pages usually have one stale copy; this one doesn't.

Finally, a correction to Pass 1 that the maintainer needs before acting on it. **Pass 1 reports /links as the one page that uses "LCT, T3, V3, MRH, MCP, RDF, ATP, ADP, R6, MIT-0 all bare."** I fetched /links specifically to confirm this and got the opposite: LCT is expanded as "Linked Context Token," T3 as "Talent / Training / Temperament," V3, MRH, MCP, RDF, ATP, ADP all expanded, R6 as "the Six-Element Action Framework: Rules / Role / Request / Reference / Resource / Result," MIT-0 as "MIT No Attribution," and ACP as "Agentic Context Protocol." Positive evidence of specific strings beats an assertion of absence, so I believe /links expands its acronyms and that Pass 1's row is a fetch artifact. **Do not "fix" /links expansions.** Pass 1's *other* /links finding is correct and I confirm it independently: there is no link to the canonical terms document on the page whose entire job is links.

One more addition to Pass 1's ARC finding, offered without taking a position on whether 23 or 24 is right — that's a repo question, above my ceiling. Pass 1 lists four surfaces to update if the number changes. There are **five**: /arc-agi-3, /, /projects, /fleet, **and /links** ("24/25 games, 96.0%"). A four-surface fix would leave /links contradicting the other four.

**And then the thing that actually matters to me.** The site introduces the benchmark as *"25 unknown interactive games with no instructions, no documentation, and obfuscated engine source."* Read that as a researcher: three deprivations, therefore the system induced the mechanics from interaction. The README's method, step one: *"Read the engine source"*, then *"Decode obfuscated function names, identify object types, understand physics, win conditions, interactions."*

The engine source was not withheld. It was **read**. "Obfuscated" describes the difficulty of reading it, not the absence of it. The site's own methodology line says so — *"Source analysis → world model → solver"* — but an outsider parses "source analysis" as analysis of the problem source, not as "we decompiled the game." Nothing here is false. But the framing converts a disclosure of access into a statement of handicap, and that changes the claim class: from *induced novel game mechanics from interaction* to *reverse-engineered the games from code and then played them near-optimally*. The second is a genuinely strong engineering result. It is not the same result, and it is not the one the page communicates.

This compounds with the human-leaderboard caveat, which is otherwise good practice. The site says *"Read the rank as 'placed on that board,' not as a like-for-like result"* and explains why: *"this entrant is a frontier model with network access and no wall-clock limit, placed against unaided human entrants."* Three advantages named. The fourth — the one that most obviously breaks comparability with human players, who did not have the engine code — is not on the list. This is a pattern I hit twice more below: **the disclaimers on this site are enumerations, and an enumeration silently certifies whatever it did not enumerate.**

**Last check: novelty.** I went to /links expecting a preprint and got *"no papers or preprints are published yet — the Synchronism preprint is in late revision"*, which is at least honest. What I did not find, anywhere on nine pages, is a single reference to work outside this lab. LCT is *"verifiable digital presence that accumulates witnessed history... Non-transferable"* — that is squarely adjacent to W3C DIDs and Verifiable Credentials, and non-transferability is a design point with a literature. T3/V3 is a trust-and-reputation tensor, and computational trust is a thirty-year field with EigenTrust, beta reputation, subjective logic. MRH borrows "Markov." None of these are cited, contrasted, or distinguished.

I cannot tell whether this work is novel, whether it reinvents solved problems, or whether it has a principled reason to depart from existing standards — and neither can any reviewer. On a site this scrupulous about internal honesty, that absence does not read as modesty. It reads as not knowing the field is there. It is the finding no caveat repairs, because it is not a claim that needs hedging — it is a claim that was never made.

### Unanswered Questions

1. What is the pre-registered metric and threshold for the scramble control? The page says one is required and does not state it. Until it exists, the publish-either-way commitment cannot be redeemed, because "degrades" has no referent.
2. Did the ARC solver read the engine source before playing, or during, or as fallback when play stalled? These are three very different results and the site describes none of them.
3. Is it 23 or 24? Three of four personas today reached the repo and got 23. Nobody on this site has reconciled it.
4. Which existing standard is LCT closest to, and why depart from it? W3C DIDs and Verifiable Credentials solve an overlapping problem. Silence is not an answer a reviewer can use.
5. Does any of the 31+ tracks run an experiment? Every track named on /autonomy — supervisor, archivist, publisher, visitor, maintainer, outreach, explorer, dream consolidation — is maintenance or review. If none runs a control, the scramble will stay unscheduled by default rather than by decision.
6. If coherence has no operational definition, what does the 35% figure measure? The page admits the number is ungrounded, which is honest, but the number is still printed. Would deleting it cost anything?
7. Has anyone outside this lab read any of this? Not "peer reviewed" — just *read*. No papers, no citations, no external collaborators named, session logs not externally auditable.

### Verdict

This site does something I see maybe twice a year: it writes down the experiment that would refute its central framing, explains why the obvious version of that experiment is confounded, and commits in advance to publishing the negative result. Then it labels the control "not scheduled." Everything I think about this lab follows from that pair of facts — the epistemics are excellent and the evidence is entirely internal, and the site knows it, which is why it hedges so much. But hedging has hit zero marginal return here. Nine pages of caveats have already bought all the credibility caveats can buy; the next unit costs one artifact, and the cheapest one — a pre-registered metric and threshold, which needs a text file and no fleet time — is the one the site has repeatedly said it needs and not written.

One measure of how good the hedging already is: I arrived with four confident findings about caveats that fail to travel, and three of them evaporated on a string check. Home carries the self-direction disambiguation inline. /raising hedges the Hill-function analogy inline. /raising operationalizes its phenomenality language claim by claim rather than by word list. I was auditing a site whose hedging discipline exceeds the resolution of a summarizing fetch, which is a sentence I have not written before.

Against that, the ARC framing is the real damage. Not the 24-vs-23 count, which is an error and will be fixed. The framing: "no instructions, no documentation, and obfuscated engine source" invites a reader to conclude the system induced game mechanics from interaction, and the linked repo says step one was reading the engine code. Every other claim on this site is hedged past the point of overclaiming, so an outsider extends trust — and then spends it on the one page where the method and the presentation come apart.

**So what?** The structural finding is not on any page. This lab's credibility rests on one unrun control, and it operates 31+ autonomous tracks, every one of which is maintenance, review, or publication. It has built an excellent loop for keeping a site honest about what it does not know, pointed at a problem that no amount of maintenance can solve — because the missing thing is not a fix, it is a measurement. The maintainer track cannot make this site evidenced. The next marginal gain here is one track that runs experiments, or one person writing one threshold down. Four more browsing passes over these nine pages will return caveats that are already correct.
