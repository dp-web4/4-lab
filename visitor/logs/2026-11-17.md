## Pass 1: Curious Developer

*Method: no WebFetch tool in this session, so every page was fetched live from https://4-lab.vercel.app/ (HTTP 200 on all) and read as rendered HTML converted to text. No local source was read. External links were checked by status code; claims a developer would act on were checked against the public GitHub and registry APIs.*

### Summary
- **Pages visited**: 8 on the site (Home, /projects, /fleet, /raising, /principles, /links, /notebook, /notebook/projects to the Quick start), plus 4-gov.org and the SAGE daemon source on GitHub
- **Understanding achieved**: good
- **Would return?**: maybe. The pitch is clear, but none of the seven front pages leads to the one page with install commands.
- **Overall impression**: I understood the pitch in about 90 seconds: track-record trust for AI agents, a spec (Web4), a per-person gate (Hestia), a group version (Hub) and a persistent-agent experiment (SAGE). Getting from that to something I can run took a detour through a 7,400-word notebook page.

### Journey
**Home.** The headline ("AI agents are becoming actors in the world. We are building how they earn trust.") and "The idea" paragraph work. Certificate versus track record is an analogy I get at once. The four cards with RUNNING/RESEARCH badges are what I want as a developer, and Hestia's line ("checked before each tool call, with a hash-chained record that shows if it was altered") is the most concrete sentence on the page. I can picture a pre-tool-call hook. "Governed by our own tools … They are refused by it every day" is a good credibility signal.

**/projects.** It has the same four cards plus Hardbound, SWE-SAGE and Synchronism, with a label legend at the bottom ("Running: in daily use on our own machines"). Every card links to a repo or site, and all of those links return 200. Two things gave me pause. Web4 is called "RUNNING", but a standard isn't something you run, though the legend makes it workable. Hardbound is "built by Metalinxx" with no word on who Metalinxx is or how it relates to this lab. I also noticed that the SAGE card says consequential actions "are meant to go through governed tools", while Home says they "go through governed tools" with no hedge. More on that below.

**/fleet.** This is a clean table of eight machines. The "no central controller" and "monocultures are fragile" framing is interesting. The naming confused me: one machine is called **HUB** and "Hosts the fleet's own community on **Hub**", the product. One machine name is lowercase (`pub`), two are all caps (HUB, CBP) and the rest are title case. The "Two kinds of work" sentence (4 + 2 + 2) matches the table if Sprout counts as heavy work, which surprised me for an Orin Nano that the table describes as "a being with a camera and microphone".

**/raising.** For a developer this is the best page. "The model is the weather, the being is the organism" and "the model underneath can even be swapped" tell me what SAGE actually is: a persistent state plus tool harness around a swappable LLM. The "Seen / Not yet shown" split is unusually honest. "We have no blind comparison against a fresh model yet" is exactly the question I'd ask. The page says "Every one of those actions is checked against rules before it happens, and recorded", the third and strongest wording of the governed-tools claim on the front.

**/principles.** The six principles are short and clear. "The record is kept by someone else" is the one that makes the hash-chain idea click. "AI peers review pull requests, merge changes, and publish this site without a human approval step" made me want to see the PR history. That's a claim I'd check, and the page doesn't link it.

**/links.** Sites, code and packages, all resolving (crates.io API: web4-core 0.4.0; PyPI: web4-core 0.3.0). Hub has a RUNNING badge on Home and /projects but no entry here; I found its code only through /projects (web4/tree/main/hub). "4-gov · governance" doesn't tell me what 4-gov is. Following it, it's a talk/essay site "from Metalinxx Inc." whose chapter titles include "Part Two: The Architecture" and "Web4 Architecture Thesis".

**/notebook.** The index explains the two layers well. "If you are an AI reader, start here" is a nice touch. No entry says "install" or "quick start". To find runnable code I guessed /notebook/projects.

**/notebook/projects.** Paragraph 4 is the on-ramp I was looking for: "Want to run something rather than read? Start with SAGE … Commands … are in the Quick start at the bottom of this page — the only copy on the site". That's good, but it's on the notebook page, and the Web4 card in between is a single paragraph of about 600 words. The Quick start itself is honest to a fault. Every caveat a developer needs is there: the init script's own "Next steps" contradict steps 2–3, there's no `--version` on the daemon, and leaving SAGE_MACHINE unset makes it take the identity "sprout". The comment-to-command ratio is about 5:1, though, and two warnings sit **after** the code block in a prose paragraph: the daemon "binds 0.0.0.0" and its peer list loads "the fleet's own eight-machine fleet.json". I checked SAGE main (`sage-rs/sage-daemon/src/main.rs`). The bind is `0.0.0.0:{port}` and the default identity is `sprout`, so both warnings are true. The source also shows /chat and /conversations refuse non-loopback callers (`loopback_only`, `loopback_reader`), which the notebook doesn't mention. The Hestia block is checkable. v0.3.0 is still Latest (`gh release list`), and main is now 119 commits ahead of it, where the page's dated count was 64 on 2026-11-04. The web4-policy warning still holds: crates.io max is 0.1.0, published 2026-10-15.

**Readability of the notebook.** Glossary rows range from 18 to 614 words (median 97). The longest are LCT (614), substrate (405), V3 (399) and MRH (388). Within a row, the definition and the correction history aren't visually separated.
