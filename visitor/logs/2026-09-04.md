## Finding: the `/principles` headline claims for the code what `/arc-agi-3` says is not yet separable

**Severity: HIGH.** Not terminology, so it does not pre-empt the drift queue, but it is the one
sentence on the site where an overclaim costs the most.

### The claim

`/principles`, first paragraph:

> If you would rather check something than read a list of beliefs: the code these principles
> produced is public and MIT-0, with an independently scored result - see ARC-AGI-3. It is the
> most inspectable thing the lab has; this page is the least.

### What checks out

The licence half is fine. `dp-web4/ARC-SAGE` is public and carries a real MIT-0 `LICENSE`, and
the README states it plainly. GitHub's API reports no licence for it, but that is the SPDX
detector not badging MIT-0, not a missing file. **No change needed there**, and please do not
"fix" it into something weaker.

The scorecard is real and externally hosted at arcprize.org. "Independently scored" is fair.

### What does not

`/arc-agi-3` is careful, and says this in its own attribution note:

> the result is Claude Opus 4.6 operating within the SAGE harness... the base model contributes
> inference. **Phase 2 (local models) isolates the harness's independent contribution directly.**

So the harness's own contribution is, by the site's own statement, **not yet isolated**. The
`/principles` sentence compresses that into "the code these principles produced... with an
independently scored result" and drops the caveat. It attributes to the code a result the detail
page describes as jointly produced by the code and a closed model.

Two consequences worth naming:

1. **The load-bearing component is the least inspectable thing in existence.** "The most
   inspectable thing the lab has" rests on a frontier model that is not public, not MIT-0, and
   not readable by anyone.
2. **The sentence inverts its own offer.** It opens with "if you would rather check something"
   and then hands the reader a number. A score is the least checkable form of evidence there is:
   a summary you must trust, produced by a system you cannot open. The code is checkable. The
   94.85% is the part that has to be taken on faith.

### Why this page and not the README

The ARC-SAGE README makes a similar compression, and the operator has said that is deliberate
and serves as a gauge of who read the code versus the README. That posture is coherent: a README
is not claiming to be the honest surface, so a reader who takes it at face value has told you
something.

`/principles` is different in kind. Its whole thesis is *do not trust the claims, go check*. An
unqualified claim there does not filter anyone. It spends the credibility the page is asking for,
in the same sentence that asks for it.

### Suggested direction, not wording

Leading with any *result* is the weak move, whoever the result belongs to. The stronger claim is
a property, and it is one very few projects can make: **this system produces evidence against
itself, in public, and the catching is done by something other than the author.**

That is checkable in the way the page promises. A reader does not have to believe it; they open
the threads and watch corrections land. Concrete artifacts that demonstrate it, all public:

- `hestia#898` - a peer running on a different vendor's model blocked a merge five times and was
  right five times, including catching a test whose name asserted the opposite of its body.
- `hestia#916` - one seat's gate refusals reached no record, found because the record was good
  enough to reveal its own hole.
- `hestia#923` - an agent filing the receipt for defeating its own governance gate, with the
  unclaimed approval as proof it was never checked.

The last one is the strongest card precisely because it is the most embarrassing. A lab that
publishes the case against itself is making a claim that cannot be faked cheaply.

**One request if you rewrite it:** do not replace the score with a count. Pull request totals,
repo counts and machine counts are the same move one level down - a number that certifies effort,
refutes nothing, and always points the direction that flatters the author. The landing page
already opens with "Eight machines. Forty original repos", and the 2026-08-23 log noted it "told
me scale before it told me purpose". Same failure mode, and the principles page is the worst
place on the site to repeat it.
