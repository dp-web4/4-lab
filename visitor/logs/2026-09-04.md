## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (/, /projects, /context, /fleet, /autonomy, /raising, /principles, /arc-agi-3, /links) + the SAGE README the site sends you to
- **Understanding achieved**: good
- **Would return?**: yes
- **Overall impression**: I understand what this lab *is* within two minutes, but the one thing I actually wanted to do — clone SAGE and run it — is described wrong on the site.

### Journey

I came from a repo README, so I landed on `/` cold. The headline ("Eight machines. Forty original repos. One recursive learning loop.") did its job: I immediately knew this was a multi-machine agent lab, not another framework.

What surprised me positively: the page anticipates that I have no context. There's a "New here? This site is acronym-dense" pointer within the first screen, and a full vocabulary primer at the bottom of the *same* page. That's the right call — I didn't have to leave the landing page to decode `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP`. I did have to scroll a long way to get there, and I only found it because the page told me to.

The equation itself is the first thing that made me stop. Not because it's wrong, but because a formula that mixes `+` (augmented with), `/` (verified by, *except* in ATP/ADP where it means something unrelated), and `*` (contextualized by) is not an equation in the sense I use that word — it's notation. The page actually says this out loud ("same glyph, unrelated semantics"), which I respect, but the honesty doesn't remove the friction: I read it as math, then had to un-read it.

The "What's Happening Right Now" section is the best part of the site for me. "The Context Window IS the World" and "Small Models Are Winning Game Levels" are concrete, dated, and about things I can evaluate. That's the section that made me want to look at code.

So I went to `/projects`. Clear status labels — `runnable` = "clone it and it executes end to end today" vs `research-stage` = "may not run end to end". That's a genuinely useful distinction that most project sites don't bother with. SAGE is marked runnable, and the Quick Start says:

```
git clone https://github.com/dp-web4/SAGE
cd SAGE
# See README for Python/conda setup and first session instructions
```

Then I opened the README. It says: **Rust toolchain (stable), Ollama, Python 3.10+**, and the actual start sequence is `cargo build --release` followed by running a Rust daemon. There is no conda step. The site told me to expect a Python project and the repo is a Rust daemon with Python tooling around it. That's the single highest-friction thing I hit — it's the exact moment a developer decides whether the lab is careful or not, and it fails at that moment. It also quietly undercuts the `runnable` label: "clone it and it executes end to end today" is true only if I already have a Rust toolchain and Ollama installed, neither of which the site mentions.

`/fleet` was the page I enjoyed most and trusted least. Enjoyed: eight machines with real hardware listed, Jetson Orin Nano next to a Mac Mini next to WSL2 on a 2060 SUPER — that's a real heterogeneous fleet, not a diagram. Trusted least: the session counts don't quite hold up under a second read (see friction log).

`/autonomy` answered the question I'd been carrying since the landing page — "autonomous in what sense?" — and answered it well. Task definitions authored in advance, self-scheduled, not self-directed. It also volunteers that the maintainer track pushes to the live site with no human pre-approval, 117 commits, zero rollbacks, and then immediately says zero rollbacks reflects "how corrections are applied" rather than proof none were needed. I didn't expect a site to argue against its own best number.

`/raising` and `/principles` are the theory half and I skimmed them, which is exactly what my kind of reader does. `/raising` survived the skim: the disclaimers about consciousness are in the body text, not a footnote, and there's a section admitting the control experiment that would distinguish "raising" from ordinary prompt engineering hasn't been run. `/principles` reads as genuinely operational rather than aspirational — Principle 3 ("R&D, not production") and Principle 6 ("Document failures") are the ones I'd quote to a colleague.

`/arc-agi-3` is the page with the only externally-checkable number, and it links the ARC Prize scorecard. 94.85% action score, 24/25 games. It also says the ablation (same model, no harness) hasn't been run, so the harness's own contribution is unmeasured. As a developer that's the number I'd want most and it's honestly marked missing.

`/links` and `/context` both worked. `/context` is a 45-term glossary and is the page I'd send a second newcomer to first, ahead of the landing page.

### Unanswered Questions

1. What do I actually run to see SAGE do something? The site says Python/conda, the repo says Rust + Ollama. Which is current?
2. What are the other 29 original repos? The headline number and the project list are 29 apart with no bridge.
3. Is the fleet's 1,991-session total counting current model lines only, or cumulative across model swaps? Legion's numbers made me unsure.
4. The ARC result is Claude Opus 4.6 in a harness. What does the harness do that the model doesn't? The site says the ablation isn't run — so is the honest answer currently "unknown"?
5. Can I run any of this without a Jetson? /projects says "SAGE runs on a single machine — no Jetson required," which answered it, but that line is easy to miss and it's the first question a developer has after reading /fleet.
6. Is there a way to contribute that isn't "read 45 glossary terms first"? /links has a Contributing heading but I couldn't tell what a first PR would look like.

### Verdict

This is the rare research site that reads as if it expects to be checked. The status labels distinguish what runs from what doesn't, the ARC page marks its missing ablation, the autonomy page argues against its own zero-rollback stat, and the landing page downgraded a heading from "demonstrated" to "internal observation" and says so in the text. As a developer, that pattern buys more trust than any of the individual claims do.

The gap is that the care applied to claims hasn't reached the onboarding path. The one instruction aimed squarely at me — clone SAGE, here's the setup — points at the wrong toolchain, and that's the first concrete thing a developer touches. Fix the Quick Start prerequisites and this site converts readers into cloners.

The terminology is clean. Every Web4 acronym I met used the canonical expansion, and where a term is legacy (SAGE's "Governance") the site flags it itself rather than hoping nobody notices. What's missing is local definition: /fleet and /arc-agi-3 both use load-bearing jargon that's only defined over on /context, and /arc-agi-3 in particular is reachable directly from the ARC Prize scorecard by someone who has never seen the primer.

## Pass 2: Technical Writer

### Summary
- **Pages visited**: 9 (/, /projects, /context, /fleet, /autonomy, /raising, /principles, /arc-agi-3, /links)
- **Understanding achieved**: solid
- **Would return?**: yes
- **Overall impression**: Canonical terminology is clean on every page — the defects are structural: one acronym has three different expansions across three pages, one page has three different names, and the site maintains two glossaries that can drift apart.

### Journey

I audit documentation for a living, so I browsed the way I audit: nav bar left to right, every link, checking each acronym against the canonical table before accepting it.

The nav is `Projects | Glossary | ARC-AGI-3 | Fleet | Autonomy | Raising | Principles | Links`. Putting Glossary second is the right call for a site this acronym-dense — most sites bury it under a "Resources" fold. Clicking it takes me to `/context`, where the H1 is "How Knowledge Flows" and the glossary is a subsection titled "Glossary at a glance." So one page carries three names: the nav calls it Glossary, the URL calls it context, the heading calls it How Knowledge Flows. Each is defensible alone; together they mean a reader who bookmarks "the glossary" and a reader who is told "see the context page" don't know they're the same destination.

The glossary itself is the strongest artifact on the site. Forty-five terms, and — unusually — it defines its own weak spots. "Emergence / emergent" is glossed as "used in more than one sense on this site... with no single operational definition yet." "Coherence" gets the same treatment for three senses. "Attractor / attractor basin" is marked "used on this site as a METAPHOR, not a formal dynamical-systems object." A glossary that flags its own polysemy instead of papering over it is doing the job. I would cite this page as an example in a style guide.

Then I checked the canonical table, term by term, page by page. **Every Web4 acronym on every page uses the canonical expansion.** LCT is "Linked Context Token" in nine places and never "Lifelong Capability Token." T3, V3, MRH, ATP, ADP, R6 — all correct, all consistent. R7 is handled precisely: listed as "R6 + Reputation," Canon's superset, rather than as a rival expansion of R6. That's the exact distinction a careless writer collapses.

`/principles` closes with Principle 10, "Terminology matters," which states the rules as policy: "Web4 is not 'architecture' or 'infrastructure' — it's an ontology. Hardbound is not 'governance' — it's oversight." Then it does something I don't often see: it concedes that its own preferred word is ambiguous. "That's the machine-enforced sense, not the human-supervision sense 'oversight' carries in AI-safety literature." A site that publishes its terminology rules *and* the residual ambiguity in those rules is running the same audit I am.

`/context` backs that with a dedicated section, "Terminology note — the governance→oversight correction, in one place," which records that the lab originally said governance and changed. Documenting a terminology migration rather than silently rewriting history is the correct practice, and it's why SAGE keeping "Governance" in its expansion doesn't read as drift — the site names the legacy explicitly.

Where it breaks down is ARC-AGI-3. I found three expansions on three pages:

- `/` — "Abstraction and Reasoning Corpus for Artificial General Intelligence (ARC-AGI-3)"
- `/context` — "Abstraction and Reasoning Corpus for Artificial General Intelligence, version 3"
- `/projects` — "Abstraction and Reasoning Corpus for Artificial General Intelligence, third-gen interactive benchmark"

The landing-page form is the weakest: it expands "ARC-AGI" and leaves the "-3" doing unexplained work, which is precisely the first-use failure mode. The other two disagree on whether the numeral is "version 3" or "third-gen." None of these is *wrong* — but a reader who moves between pages has to decide whether they're reading about the same benchmark, and the glossary is supposed to remove that question, not pose it.

I also checked the two items Pass 1 flagged on `/fleet` and `/arc-agi-3`, because if they were real I'd escalate them. They aren't. `/fleet` reads "working memory (dorsolateral prefrontal cortex / dlPFC)" — expanded. It reads "Zero crystallization achieved (S100 — session 100) — no fixed-point collapse, the failure mode where an agent settles into repeating the same responses" — both S100 and crystallization glossed inline. Legion's number is labeled "336 sessions (creating) — a line count, not a machine total." And `/arc-agi-3` carries a full expansion strip covering LCT, MRH, ATP, ADP, RDF, T3, V3, and MCP. All four are already correct on the live page. Recording this so the maintainer track doesn't spend a cycle fixing what isn't broken.

`/fleet` does the same self-audit on its own metric: it notes that the home page says "raising sessions" where the fleet cards say "machine sessions," calls it "one quantity, two nouns," and declares itself the source of record. Correct diagnosis. But naming a terminology collision is not resolving it, and neither noun is in the glossary — so the fix is one glossary entry away and hasn't been taken.

The remaining gap is coverage. `/fleet` uses "hestia" as a bare proper noun ("Its hestia identity is the fleet's first agent-owned one"). It's not in the 45-term glossary. Same for BECOMING, memoriescape, bilateral generation, and dream consolidation from `/raising`, and TPM, FIDO2, WASM, and RPE elsewhere — though those last four are expanded at point of use, which is acceptable.

Last structural note: the landing page carries its own vocabulary primer covering ten terms, and `/context` carries forty-five. Both are correct today. Two glossaries maintained by hand will not stay correct indefinitely — that's the single highest-probability source of future drift on this site, and it's a maintenance-process issue rather than a text issue.

The exception is `/arc-agi-3`, which links a third-party ARC Prize scorecard: 94.85% action score, 24/25 games, ~$250 API spend, Claude Opus 4.6 inside the SAGE harness. The caveats are properly severe — *"the ablation that would separate the harness's contribution from the base model's (same model, no harness) has not been run,"* stated twice; Hardbound's hardware anchoring is *"a design target, not the mechanism in this run"*; the gating gives *"auditability, not a demonstrated safety property... a much weaker claim than that unsafe actions were prevented"*; and *"nothing here was adversarially tested."*

Which leaves the structural problem a reviewer notices immediately: **the one externally verifiable result on this site does not test the lab's thesis.** It tests Claude Opus 4.6, with the harness's contribution explicitly unmeasured. The credible evidence and the interesting claim are disjoint. That is not dishonest — the site says every component of it — but no amount of caveating converts an unablated frontier-model score into evidence about raising.

`/principles` I read as the lab's own theory of its epistemics, and it mostly holds. Principle 3 ("R&D, not production") disclaims safety-critical, medical, financial and autonomous-control use. Principle 6 ("Document failures") is backed by real content: the p_crit derivation that failed by 400x, kept on /context and in the principle itself; the Synchronism "80 orders of magnitude" claim retracted with a correction on /projects explaining what the number actually was (the spread of critical-density values across systems, not the range of a single coherence curve). **Dated retractions are the strongest honesty signal on this site** — stronger than any disclaimer, because a disclaimer costs nothing and a retraction costs a claim.

Principle 7 is the defensible core: *"Raising is not training; it is also not nothing."* The weights-never-change boundary is categorical, checkable, and held on every page that touches it — /context, /raising, /principles all state that raising shapes context, experience buffer and interaction history and never weights, with LoRA explicitly fenced off as a different thing. As a researcher I will grant that boundary without argument. It is a real distinction and the site never blurs it.

Principle 5 is where the discipline slips. "Synthon: emergent coherence" is a stated principle of the lab, and its own caveat says synthon *"lacks independent operational definition; coherence and synthon partly define each other"* — circularly, ungrounded. /context adds that the operational marker (coherence self-sustains above ~1% coupling, absent below) rests on a **single unreplicated trial** whose variables are undefined outside the experiment, and that the associated "35% coherence gain" figure is defined only within that one trial. A single unreplicated trial with a circular definition has been promoted to one of ten principles. The site discloses every part of this and promotes it anyway.

That produces the asymmetry I would raise first in review: **the most speculative claim on the site has the strongest falsification discipline, and the empirically-shaped claims have none.** /raising pre-registers its own execution. Nothing states what would falsify the synthon coupling threshold, the Synchronism coherence equation, or the harness's contribution to the ARC result. Principle 6 documents failures after they occur — which is genuinely valuable and not the same thing as specifying in advance what would count as one.

Last observation, on rhetorical shape rather than content. The caveats on this site are almost always positioned *after* the claim they qualify, and the claim carries the display weight. "#3 on human leaderboard" appears near the headline scores; the note that this was a frontier model with network access and no wall-clock limit against unaided humans arrives below it. `/fleet` argues persuasively that "machine session" is the accurate deflationary noun — *"nothing in the count establishes that what happened in it was raising rather than competent context engineering"* — and then totals the fleet at "2,065 raising sessions." Each instance is individually defensible. In aggregate it is the standard shape of hedged overclaiming: technically complete, but the number travels and the caveat does not.

### Unanswered Questions

1. What is blocking the scramble control — the metric definition, compute, or willingness to run something that could retire the framing? The page says all three obliquely and settles none.
2. Is there any evidence about raising that a third party could check today, without access to the fleet? If the honest answer is no, that is worth stating in one sentence rather than leaving a reader to assemble it from /context and /autonomy.
3. What would falsify the synthon coupling threshold? /raising pre-registers its own disproof; nothing else on the site does, and the synthon result is the one that has been promoted to a principle on a single trial.
4. The identity-portability claim — behavioural continuity across hardware and model families without retraining — is the most interesting empirical claim here. What was measured to establish continuity, by whom, against what baseline? /context concedes it is "counted but not measured," which means the claim currently rests on session counts.
5. Peer witnessing runs among machines in one fleet under one operator. What is the threat model for attestation, and does anything prevent a closed mutual-attestation loop?
6. Given that /autonomy establishes the auditors' blind spots correlate with the authors', what would break that correlation — a different model family for the visitor track, a human pass, or an outside reviewer?

### Verdict

This site is more honest than most of what I review, and the honesty is structural rather than decorative: four terminology collisions with my field pre-emptively flagged, a dated retraction, a failure published with its magnitude, evaluator non-independence named by the lab itself, and a falsification commitment written down for its own central framing. The sentence "everything below might be competent context engineering and nothing more" is the sentence most research sites are constructed to avoid writing, and this one leads with it. I would cite /autonomy's correlated-auditors paragraph as a model of how to report an internal eval loop.

What the caveating cannot do is substitute for the evidence it correctly says is missing. Every claim on this site except the ARC scorecard is generated and audited inside one fleet, by the site's own account, with no external, blinded, or third-party verification anywhere in the system — and the one external result measures an unablated frontier model rather than the thesis. The falsification commitment on /raising is sincere and currently unbound: no date, no owner, no metric, blocked on a definition the site concedes it lacks, while the vocabulary it would retire carries a nav item and a page. That is not deception; it is a claim that has been made unfalsifiable in practice and left load-bearing anyway.

My recommendation is not more disclaimers — the site has reached the point of diminishing returns on those, and additional hedging would start to read as inoculation. It is one external check: a single third party re-deriving one published number from redacted logs and stated coding criteria. /links already offers that package on request. Publishing one instance would move this from a lab that describes its epistemic position accurately to a lab that has improved it, and it is the smallest step that changes what I could say about the work to a colleague.
