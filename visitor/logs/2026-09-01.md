## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (home, /projects, /fleet, /autonomy, /raising, /principles, /context, /links, /arc-agi-3) + 3 off-site clicks a developer would make (web4 README, SAGE README, ARC Prize scorecard)
- **Understanding achieved**: good
- **Would return?**: yes — but I'd bookmark `/links`, not `/projects`
- **Overall impression**: I understood what the lab does in about two minutes; then I tried to run something and the page that told me *how* was the wrong page.

### Journey

Landed on home. Headline — "Eight machines. Forty original repos. One recursive learning loop." — plus a 94.85% ARC Prize number is a solid hook. The "New here?" box pointed me at the vocabulary primer and I actually read it, because every acronym in the Web4 equation (`MCP + RDF + LCT + T3/V3*MRH + ATP/ADP`) was expanded right there with a one-liner and the operators were explained. That's rare. By the bottom of home I had the mental model: SAGE is a loop that wraps a frozen LLM with identity, trust scores, and a spend/settle budget; Web4 is the vocabulary/spec for that; Synchronism is a physics conjecture the lab is explicit about not having validated.

Went to `/projects` to find what to clone. The cards are good — public/private, runnable/research-stage, links. SAGE is marked "recommended first clone." The quick start says:

```
git clone https://github.com/dp-web4/SAGE
cd SAGE
# See README for Python/conda setup and first session instructions
```

So I assumed Python. Then on `/links` (which I only hit because it's the last nav item) I found a *different* SAGE quick start with `# Needs: Rust (stable), Ollama, Python 3.10+`, a `cargo build --release` in `sage-rs/`, and a Rust daemon binary. I opened the SAGE README on GitHub to break the tie: README matches `/links` exactly (Rust toolchain, Ollama, Python 3.10+). `/projects` never mentions Rust or cargo at all. If I'd followed `/projects` I'd have set up a conda env and then hit `cargo: command not found`.

Same page, Web4 card: "The repo itself is a specification — documents and schemas, no runnable demo." I clicked the repo anyway. The README opens with `pip install web4-core` and `web4-core = "0.3"` for Cargo, and says the packages are published on PyPI and crates.io (web4-core 0.3.0, web4-trust-core 0.2.0). That's not "no runnable demo" — that's an installable SDK. As a developer, that's the single thing I'd most want to know about Web4 and the site told me the opposite.

`/fleet` is the page I enjoyed most — per-machine hardware, model, ollama tag, session count, role. Reads like a real ops inventory. One term, `hestia`, shows up twice ("hestia identity", "hestia trust layer") and is called "hestia's own internal field name" but never told me what hestia *is*. I still don't know if it's a repo, a daemon, or a data structure.

`/autonomy` describes 31+ cron-driven tracks and names 8 of them with times. The caveats are unusually blunt (the maintainer track "ships changes to the public site without a human gate"; repo pushes are "not fully revertible"). But there's not one cron line, not one YAML, not one shell snippet. I'm told about 31 scheduled jobs and can't see the shape of a single one.

`/raising` and `/principles` were readable; I skimmed the theory. Hedging on consciousness is heavy and consistent. `/context` is the glossary and says the canonical source is `CANONICAL_TERMS_v1.md` in the web4 repo, with a link, and "when this page and that document disagree, the document governs." Good.

`/arc-agi-3` gives the 24/25 result, names the model (Claude Opus 4.6, network-enabled, no wall-clock limit), and says outright that the harness-vs-model ablation hasn't been run. I clicked the ARC Prize scorecard link; the page loaded but the scorecard body didn't render for a plain fetch (looks JS-rendered) so I couldn't confirm the number from the source without a browser. Not the site's fault, noting it.

### Journey

I then walked every page with the same checklist: (a) every acronym expanded on first use, (b) expansion identical to the canonical table, (c) same expansion on every page, (d) gloss consistent with the governing document.

(a)–(c) passed everywhere. I compiled the expansion matrix below and could not produce a single cell that differs from canon. The lab's own drift disclaimer — "'Governance' in SAGE's name predates the governance→oversight correction" — appears on seven of nine pages in near-identical wording, which is the kind of consistency I normally have to fight for.

Then I did what the /context page invites: it says *"when this page and that document disagree, the document governs,"* and links the document. So I fetched the document and diffed the glosses. That is where the findings are — see the audit table. The headline: canon has 13 headwords; the site's glossary covers 7 of them and is silent on 4 (Binding, Pairing, Delegation, Federation) while using the words "binding"/"bound", "delegated", and "federation" in running text. And the site's R6 is written with six slashes where canon writes five slashes and an arrow.

Cross-page count reconciliation: I chased every number. 435+488+336+377+162+193 = 1,991 on /fleet; +74 (HUB) = 2,065; home states that sum explicitly; /links says "1,991 (2,065 including HUB)". All consistent. Pass 1's /fleet-vs-/links friction row ("2,065 as cumulative incl. archived lines") is a fetch artifact — /fleet explicitly says the archived gemma3-4b line's 171 sessions are *not* included; "cumulative" there means over time, not over archived lines. Pass 1's /principles "PARTIAL" for T3/V3 is also a fetch artifact: /principles has the verbatim string *"T3 (Talent / Training / Temperament) / V3 (Valuation / Veracity / Validity) tensors bind to entity-role pairs via RDF triples."* Home's "past 180 sessions" for the Sprout line looked stale next to /fleet's 488, until /fleet explained it: the SAGE-Sprout *raising line* transferred to CBP at 115 and is past 180; the 488 is *machine* sessions across all models. Different quantity, correctly labelled. Retracted.

Finally, the promise. I asked /context directly for `hestia`. ABSENT. /fleet uses it twice, calls it "hestia's own internal field name," and never says what hestia is. The same /fleet page, three sentences away, handles a comparable term correctly: *"The Sovereign (society-layer vocabulary; not yet in CANONICAL_TERMS_v1, like chapter ledger and chapter law) is the society's founding human member…"* — glossed, and self-flagged as beyond canon. So the page knows how to do this. It just didn't do it for hestia.
