## Pass 1: Curious Developer

### Summary
- **Pages visited**: 9 (`/`, `/projects`, `/context`, `/links`, `/fleet`, `/autonomy`, `/raising`, `/principles`, `/arc-agi-3`)
- **Understanding achieved**: good

### Journey

Landed from a repo README. The headline — "Eight Machines, One Recursive Learning Loop" — plus the problem statement did the job immediately:

> "AI agents already act on their own — browsing, transacting, coordinating with other agents — and there is no general way to establish whether one will behave appropriately in a given context."

That's a real problem I recognize, stated without hype. Good. The landing page then defines its own jargon inline (LCT, T3/V3, ATP/ADP, MRH, SNARC, MCP, RDF) which is more than most sites do, and offers me two things to actually do: "start with the /context glossary" or clone SAGE.

I did what a developer does: went to **Projects** to find the clone. The card grid is legible — Web4 (spec, no runnable demo — I appreciate being told that up front), SAGE, Synchronism, Hardbound (private), ACT, oversight plugin forks, AI DNA Discovery, 4-Life, SNARC, Membot, ARC-AGI-3. Then the quick start block:

```
# SAGE — on-device cognition kernel (recommended first clone)
git clone https://github.com/dp-web4/SAGE
cd SAGE
# See README for Python/conda setup and first session instructions
```

So I cloned and opened the README. **There is no conda setup.** SAGE's "Getting Started" needs a Rust toolchain — `cd sage-rs && cargo build --release` — plus Ollama and Python 3.10+. If I'd taken the site at its word I'd have built a conda env, then discovered halfway in that the daemon is Rust. That's the single most expensive minute on this site, and it's on the page the landing CTA points me at.

The frustrating part: the site *has* the right instructions. On **/links**, under a "Contributing" heading, there's a complete, correct, README-matching block — `# Needs: Rust (stable), Ollama, Python 3.10+`, the instance-init command, the cargo build, the dashboard at `localhost:8760`. It's excellent. It's also filed under Contributing, which is the last place a first-time developer looks. Two quick starts on one site, one right and hidden, one wrong and prominent.

Same shape with **ACT**. /projects calls it "the human interface to Web4" and lists it as a clone target. GitHub's own description for that repo reads "candidate ledger backend for Web4 anchoring. Early prototype," last pushed four months ago. "Human interface" made me expect a UI; I'd have cloned a Cosmos chain skeleton.

**/context** is the best page here — the equation with a notation key (`/` = verified by, `*` = contextualized by, `+` = augmented with), a real glossary, and an evidence ladder that grades the lab's own claims into externally validated / internal observations / unreplicated / unlicensed vocabulary. It also links the canonical terms doc on GitHub. That ladder is the most credible thing on the site and nothing else links to it.

**/fleet** gave me eight named machines with actual hardware and session counts (Thor 435, Sprout 488, Legion 336, McNugget 377, Nomad 162, CBP 193, HUB 74, pub blank). Concrete, checkable, good. But it introduces a whole second vocabulary — "chapter ledger," "chapter law," "society," "hestia trust layer." Chapter law is defined inline, chapter ledger links to the glossary; **hestia is used three times and never expanded anywhere on the page.** I still don't know if it's a service, a repo, or a concept.

**/autonomy** describes 31+ tracks at ~53 sessions/day and calls each one "a cron entry with a declared scope" — then shows me zero cron entries. This is the page I most wanted to copy something from and there's nothing copyable on it. It does contain the sharpest self-criticism on the site: that the visitor and maintainer tracks are drawn from the same model families as the tracks that author what they audit, so "their misses are correlated with the authors', not independent of them." I don't think most labs would publish that.

**/raising** and **/principles** are the theory pages. "Raising is not training. Training optimizes for a loss function. Raising creates conditions for development — then watches what happens." I can follow that. The consciousness caveat is explicit and I believe it. /principles loses me at Principle 5 ("Synthon: emergent coherence") — synthon, coupling density, attractors, and `p_crit` all appear with no gloss, and the site itself admits elsewhere that "coherence" has no single operational definition.

**/arc-agi-3**: 24/25 games, 94.85% action score, Claude Opus 4.6, scorecard linked, code at ARC-SAGE under MIT-0. The page names one gap honestly — the "same model, no harness" ablation hasn't been run. But when I opened the ARC-SAGE README, it says something the site doesn't: the harness "analyzed the games' (public) engine source and built per-game solver cartridges." That's a much bigger asterisk than the missing ablation, and the repo states it more plainly than the site does.

### Journey

I audit for three things: are terms expanded on first use, do expansions match the canonical source, and does the same fact say the same thing on every page. This site passes the first two better than almost anything I audit. It fails the third in a specific, structural way.

**Method note.** I did not audit against the crib sheet in CLAUDE.md — I fetched `CANONICAL_TERMS_v1.md` raw from the web4 repo and audited against that. The two are not the same instrument. Canon defines **14 headwords** (LCT, T3, V3, MRH, ATP, ADP, R6, R7, Society, Federation, Witnessing, Binding, Pairing, Delegation); the crib sheet carries 9 and none of the relationship verbs. An audit run off the crib sheet returns clean on terms canon actually specifies.

**Nav and IA.** Header nav: Projects, Glossary, ARC-AGI-3, Fleet, Autonomy, Raising, Principles, Links, GitHub. Every link resolved. But the item labelled **"Glossary" is `/context`, a 26-section page** — knowledge flow, the CLAUDE.md pattern, per-project explainers, a worked example through the equation, an evidence ladder. "Glossary at a glance" is section 2 of 26. The nav label advertises the smallest thing on the page, and it's the page the landing CTA sends every newcomer to.

**The promise I could test.** The landing CTA reads: *"Start with /context — canonical definitions for every term."* That is a falsifiable claim and it is false. Of canon's 14 headwords, `/context` glossaries Society and Witness/witnessed but has **no entry for Federation, Binding, Pairing, or Delegation** — 4 of 14 absent. Site-invented load-bearing terms fare worse: **hestia** (3 uses on `/fleet`, incl. "the hestia trust layer") has no entry; `p_crit` and "coupling density" are used in Principle 5 and appear nowhere in the glossary.

What makes this fixable rather than just wrong: `/projects` already says it correctly — *"Every Web4 term the cards use (LCT, T3/V3, MRH, ATP/ADP, R6, MCP, RDF, SNARC) is defined in the /context glossary."* Enumerated, scoped, true. The landing page makes the unbounded version of the same claim. Copy the `/projects` scoping up.

**Two quick starts, one command, incompatible instructions.** Verbatim, same site:

`/projects`:
```
# SAGE — on-device cognition kernel (recommended first clone)
git clone https://github.com/dp-web4/SAGE
cd SAGE
# See README for Python/conda setup and first session instructions
```

`/links`:
```
# SAGE — on-device cognition kernel
# Needs: Rust (stable), Ollama, Python 3.10+
git clone https://github.com/dp-web4/SAGE
cd SAGE
# 1. Create your own instance — this is the first real command.
python3 -m sage.instances.init --machine mybox --model gemma3:4b --operator-name yourname
# 2. Build the daemon that runs the 12-step loop.
cd sage-rs && cargo build --release && cd ..
# 3. Start it. Dashboard comes up at http://localhost:8760/
```

This is not a wording inconsistency, it's a duplicated source of truth that drifted. The `/links` block matches the README; the `/projects` block does not. The documentation fix is not "update both" — it's **delete one**. `/projects` should link to `/links#quick-start`, because the copy that gets read less is the copy that goes stale, and the evidence that it already has is right there.

**The number that doesn't reconcile.** Everything countable on this site checks out except one thing. Session totals: `/fleet`'s per-machine counts (435 + 488 + 336 + 377 + 162 + 193) sum to **1,991**, exactly the site-wide figure, and +74 for HUB gives **2,065** — also exact. Repos: `/links` says *"40 original repos — 21 public, 19 internal — plus 32 forks … 72 repositories in all"*; 21+19=40, 40+32=72, and the landing headline's "Forty original repos" agrees. Machines: the landing page, `/principles`, and `/fleet` all say eight; `/projects`'s "Six machines, 0.8B (Sprout) to 27B (Thor)" carries the qualifier **"at benchmark time"** and `/fleet` distinguishes "six cognition machines, plus two society-hosts" — so that one reconciles too, and I'd have filed it wrong without reading the full sentence.

The exception: **the ARC-AGI-3 game count.** `/arc-agi-3` says *"The game-solve rate is 96.0% (24/25 games)"* and `/links` repeats *"24/25 games, 96.0%"*. The ARC-SAGE README the site links says **"23 of 25 games WIN"** with "175 / 183" levels. Same 94.85% action score on both, so the headline result is stable — but the solve count isn't, and the site's number is the more favourable one. `/raising` adds a third figure ("Legion swept all 25 end-to-end locally"), which may be a different local run, but three counts across three pages with no stated relationship is exactly how a reader loses the thread.

While I was in that README: it states, unprompted, that the harness *"analyzed the games' (public) engine source and built per-game solver cartridges"* and that the result reflects capability *"given engine-level context and tooling."* `/arc-agi-3` says "obfuscated engine source" once, in passing, and foregrounds a different gap — the unrun "same model, no harness" ablation. The repo's caveat is the bigger one and the site's is the smaller one. The linked artifact is more careful than the page linking it.

**Cross-page gloss divergence.** R6 gets two different expansions depending on which page you're on: `/context` says *"the base action grammar"* (which is canon's exact phrase), while `/projects` and `/arc-agi-3` say *"Six-Element Action Framework."* Canon never uses that phrase — it's the visitor crib sheet's coinage, now appearing on the public site. Not wrong, but a second name for a term whose whole job is being one name.

And on all site pages I could check, R6 renders as `Rules / Role / Request / Reference / Resource / Result` — six slashes. Canon writes `Rules / Role / Request / Reference / Resource → Result`. The arrow is not decoration: it separates the five inputs from the one output. Flattening it to a slash makes R6 read as a list of six peers.

**Homograph.** `/fleet` uses "binds" in the neuroscience sense — *"hippocampal episodic index — binds what+where+when for pattern-completion retrieval."* Canon's **Binding** is *"Permanent attachment of identity to hardware or cryptographic proof. Irreversible."* Because canon's sense is absent from the site entirely, there's nothing for a reader to collide with — but the moment Binding gets its glossary entry, `/fleet` needs a different verb.

### Verdict

On the thing I came to check — canonical term fidelity — this site is in better shape than the repos it describes: every expansion matches canon across nine pages, it expands ADP correctly where the SAGE README does not, and it documents its two naming exceptions (SAGE's "Governance", hestia's internal field) out loud instead of quietly. The representation problems are larger than the terminology ones, and they all point the same direction — **the site is not diffed against the artifacts it links.** `/fleet` calls itself the source of record while disagreeing with the SAGE README on every machine; `/projects` prints a 12-step loop the README says the fleet doesn't literally run; and most tellingly, the Web4 card says the repo ships no runnable code while that repo publishes a v0.27.0 SDK to PyPI and a crate to crates.io. A site this careful about hedging its claims should not be underselling the one claim a reader could verify in thirty seconds — and the audit that would have caught all of it stops at the edge of the HTML.

### Journey

I evaluate three things: are consciousness-adjacent claims caveated, is the central framing defensible, and can I check anything without taking the lab's word for it. The first two go well. The third is where this cycle's findings are.

**Caveating: genuinely excellent, and I want to say so before criticising.** `/raising` opens by naming its own deflationary hypothesis — *"everything below might be competent context engineering and nothing more"* — and calls itself *"the softest page on the site."* It states *"We're not claiming these entities are conscious, sentient, or experiencing qualia"* and marks the BECOMING phases *"descriptive scaffolding, not measured stages."* An observer note reading *"I notice I want to call it experience"* is annotated *"This records the observer's interpretive pull — not a system-level claim about the entity's experience."* I have not seen a lab annotate its own author's pull before.

`/principles` #5 goes further than anything I expected: it demotes itself. *"'Synthon' is defined through coherence, and coherence is in turn partly defined through the synthon marker — the two terms lean on each other, and neither has an operational definition yet… It earns its place here as a research direction; it has not earned the status of the principles around it, and it should be read at that weight until something breaks the circle."* A lab that publishes a circular definition and labels it circular in the same paragraph is doing something most peer review can't extract. `/principles` also carries the deployment disclaimer a safety reader looks for: *"Nothing here is optimized for deployment. Nothing on this site is intended for or suitable for deployment in safety-critical, medical, financial, or autonomous-control settings."*

And `/arc-agi-3` volunteers the comparability caveat unprompted: *"This ranks against human competitors on ARC Prize's public leaderboard, not other AI submissions… The conditions are not comparable: this entrant is a frontier model with network access and no wall-clock limit, placed against unaided human entrants."* That is the caveat most benchmark pages omit.

So: the disclosure is real and it is thorough. Which is exactly why the remaining defects matter — they are not disclosure failures, they are the things disclosure cannot fix.

**The evidence ladder's top rung carries a passenger.** `/context` sorts the lab's claims into four tiers, and the top one reads: *"**Externally validated:** the ARC-AGI-3 result (94.85% official action score) has a public ARC Prize scorecard — the one claim an outside party can verify independently."* Precisely scoped: the *action score* is what the scorecard carries.

But that number never travels alone. `/links`: *"94.85% official ARC Prize action score (Claude Opus 4.6, public set, network-enabled; **24/25 games, 96.0%**)."* The landing page, `/raising`, and `/arc-agi-3` pair them identically. Only the first half of that parenthesis is externally validated. The second half is the lab's own count — and the lab's own repo, which I fetched raw, says `**23 of 25 games WIN**`. So a figure that fails the lab's *internal* check is riding inside the parenthesis of the lab's *only* external one, on four pages.

This isn't the arithmetic complaint (Passes 2 and 3 have that, from the same source). It's a failure of the instrument itself: the evidence ladder exists to keep kinds of evidence from contaminating each other, and its top tier contains a composite claim that is half external and half internally contradicted. A ladder that mis-sorts the site's own headline is not a working ladder.

**Verifiability, tested.** I tried to check the scorecard. `arcprize.org/scorecards/c7dfb4f1-…` returns *"Loading…"* to a non-browser fetch; so does the leaderboard. That is almost certainly client-side rendering rather than a dead link, and I am not filing it as one. But it makes a point the site can act on: the entire external-validation tier rests on one opaque UUID behind a JS app, and **the site never transcribes what the scorecard reports.** One line on `/arc-agi-3` — "the scorecard reports an action score of 94.85%; game-solve counts below are ours" — would make the claim checkable, would survive the page not rendering, and would automatically fix the passenger problem above.

**The promised ablation is the wrong control.** `/arc-agi-3` names *"the ablation that would separate the harness's contribution from the base model's (same model, no harness)"* three times, and says *"Phase 2 (local models) isolates the harness's independent contribution directly."*

That control does not isolate what the benchmark measures. The site describes the task as *"25 unknown interactive games with no instructions, no documentation, and obfuscated engine source"* — three deprivations. The ARC-SAGE README describes step one of the harness as *"Decode obfuscated function names, identify object types, understand physics, win conditions, interactions,"* and states the result was earned *"outside strict from-observation play,"* demonstrating capability *"given engine-level context and tooling."* The engine source was an input, not an obstacle.

So the harness bundles two things: a cognition loop, and engine-level access plus per-game tooling. "Same model, no harness" removes both at once and returns a number that confounds them. The discriminating control is **same harness, no engine access** — cartridges built from observation only. ### Verdict

On the question I came to answer — are the consciousness-adjacent claims caveated — this site clears the bar by a wide margin and then keeps going: four separate denials attached to their specific claims, a principle that formally demotes itself for circular definition, an observer note annotated to separate interpretive pull from system claim, and a deployment disclaimer most labs don't write. It is not training; it is also not nothing"*), and the T3 "Training" collision is resolved better here than in the canon the site defers to. It is not defensible as a finding, and the site says so itself.

That is the whole problem now. This lab has spent everything disclosure can buy and the balance is empty: it has named the missing ablation, the missing replication, the missing external audit, the missing operational definition, and the missing licence on its own vocabulary — and every one of those admissions is still exactly as unresolved as when it was first written down. Neither is a caveat failure. Both are cases where the honest sentence already exists in the lab's own MIT-0 repo and hasn't crossed to the site.
