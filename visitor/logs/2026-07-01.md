## Pass 1: Curious Developer

### Summary
- **Pages visited**: 8 (Home, Projects, Context, Fleet, Autonomy, Raising, Principles, ARC-AGI-3, Links — all of them)
- **Understanding achieved**: partial
- **Would return?**: maybe
- **Overall impression**: I can tell *that* something interesting is happening here (autonomous AI agents self-maintaining infrastructure), but not *what I'd do with it* — the site reads like internal docs pointed at the public.

### Journey
I landed via a repo README expecting a project I could clone and run. The home page hit me with **"Seven machines. Fourteen repos. One recursive learning loop."** — punchy, I liked it. Then immediately came the equation `Web4 = MCP + RDF + LCT + T3/V3*MRH + ATP/ADP` with no inline explanation of the operators or the acronyms. As a dev I read code fluently, but this is notation for a vocabulary I don't have yet. I bounced off the theory and went hunting for "what does this actually do."

Projects was the most useful page for me — SAGE and Web4 both say "open an issue, clone a repo, or read the code," which is exactly the on-ramp I want. But most descriptions lead with theory ("12-step cognition loop," "trust-native ontology") before telling me a concrete use case. I still can't answer "what would I build with this?"

The Fleet page was actually the most *fun* — real hardware, real models (Jetson AGX/Thor, Mac Mini M4/McNugget, an RTX 2060 running TinyLlama). "Gemma 3 at 4B outperforms Phi-4 at 14B" is a concrete, tweetable claim I understood instantly. This page needed the least Web4 vocabulary and was the most credible to me as an engineer.

Autonomy clicked too — I mentally mapped it to "CI/CD + cron + content management, fully automated," and the honest admission that the maintainer pushes to prod then detect-and-reverts (rather than approve-first) was refreshingly candid.

I visited /context hoping it would rescue the home page's jargon — it does have a real glossary, but it assumes I know RDF, ontologies, and knowledge graphs. It's a reference, not an onboarding ramp. The site keeps telling me "read /context first," which felt a little gatekeep-y.

Raising and Principles were more philosophical than I expected but stayed grounded ("we shape context — we do not update weights," and an explicit "we're not claiming these entities are conscious"). I appreciated that they didn't oversell. ARC-AGI-3 was the most concrete claim on the whole site: 94.85% action score, 24/25 games, and honestly hedged that this used Claude Opus 4.6 + network access, not their own fleet.

### Journey
I went page by page with the canonical terms table open, checking every acronym expansion against it and against the *other* pages. My job is consistency, so I cared less about whether any single definition is good and more about whether the site says the same thing in the same words everywhere.

**Hardbound** is handled especially well. That's exactly the kind of self-documenting terminology note a writer wants: it tells the reader the drift is known and deliberately superseded.

I did chase two cross-page numbers/pairs that looked like they *could* be inconsistent, and both checked out:
- **Machine count**: Home says "Seven machines," Fleet's title says "Seven Machines," and Fleet reconciles it cleanly — "Six cognition machines, plus one society-host (HUB)." Consistent.
- **ACT vs ACP**: I worried these were the same thing spelled two ways. They're not, and Projects disambiguates them precisely: ACT = "Agentic Context Tool" (the tool), ACP = "Agentic Context Protocol" (what it implements). Links uses "Agentic Context Tool" for ACT too. Consistent and correctly separated.

The one thing that stops me short every time: **SAGE = "Situation-Aware Governance Engine."** It's expanded that way *consistently* on Context, Fleet, Raising, Principles, Projects, and ARC-AGI-3 — so it is not drift in the internal-consistency sense. The site enforces that everywhere except inside SAGE's own name, where "Governance" is load-bearing. A reader who just learned on /principles that "Hardbound is oversight, not governance" will hit "Situation-Aware **Governance** Engine" two clicks later and reasonably ask which rule is real.

## Pass 3: Web4 Contributor

### Summary

The single unresolved item is not drift but a naming collision I *can* rule on: SAGE = "Situation-Aware **Governance** Engine" sits directly against Principle 10, which states in so many words that "governance" is the wrong word.

### Journey
I went straight to Projects, Fleet, and Context — the pages that describe the work I actually touch — with the canonical set in my head rather than in a table.

The equation on the home page has visibly improved since I last looked. It now reads `Web4 = MCP + RDF + LCT + T3/V3 × MRH + ATP/ADP` **with an operator legend inline**: `/` = "verified by (T3/V3) or allocation pair (ATP/ADP)", `×` = "contextualized by", `+` = "augmented with". That's canonically correct — T3 verified by V3, both scoped (contextualized) by MRH, ATP/ADP as the paired allocation packets. The `×` rendering instead of the raw `*` is cosmetic; the semantics are right. The overload of `/` to mean both "verified by" and "the allocation pair" is honest and matches how we actually write it. No complaint from me.

Context is where I'd catch subtle drift if it existed, and it doesn't. LCT → "identity grounded in record, not model weights" is exactly the framing I'd use — it's the anti-weights point that separates an LCT from a fine-tune. T3 as a "three-component trust tensor" with each component "an RDF sub-graph root," V3 as the complementary value tensor, MRH as "the boundary of what an entity can know or affect — scopes T3/V3 to context." That last one is the definition I'd defend in a design review. ATP "declared before an action runs" / ADP as "the spent form" is the allocation-accounting model stated correctly. Web4 is spelled out as "a trust-native ontology... **not architecture or infrastructure**" — the exact disclaimer we insist on. Hardbound is "the hardware-bound oversight suite — key custody and attestation anchored in silicon." All correct.

Projects reads accurately against the repos I work in. Web4, SAGE (12-step kernel), Synchronism (the coherence conjecture, honestly labeled "research conjecture"), Hardbound (TPM 2.0 / FIDO2 / Secure Enclave), ACT built on Cosmos SDK implementing ACP, the Oversight Plugins, SNARC, Membot, 4-Life, ARC-AGI-3. ACT vs ACP is disambiguated correctly (tool vs protocol). The Oversight Plugins card uses "oversight" cleanly — audit trails, policy gating, trust tracking — which is the model I'd want represented.

Fleet is accurate on the hardware/role side (the brain-region mapping — hippocampal index on Thor, thalamic router on Sprout, RPE on Legion, cerebellar habit compiler on McNugget, metacognition on Nomad, dlPFC working memory on CBP, HUB as society-host). One model-string caught my eye: Sprout is listed running **"Qwen 3.5 2B"** and Thor **"Qwen 2.5 14B"**. "Qwen 3.5" isn't a release line I recognize (Qwen2.5 and Qwen3 are the lines) — likely a typo for Qwen3 or Qwen2.5. Model-versioning isn't my terminology remit, so I flag it low-confidence for the maintainer.

I then did the one targeted check that matters most for my audit: Pass 1 flagged /autonomy as possibly calling Hardbound a "governance layer." **I went and read it directly, and that flag is refuted** — the current /autonomy page calls Hardbound "the hardware-bound oversight suite" and does not use "governance" anywhere. Either Pass 1 saw stale content or a maintainer already corrected it. Either way, as of now /autonomy is clean, and it uses ATP/ADP correctly in the bookkeeping paragraph ("issues an ATP for its declared resource budget; an ADP records actual spend").

That leaves the one thing every pass has circled. Principle 10 says, verbatim, **"Web4 is not 'architecture' or 'infrastructure' — it's an ontology. Hardbound is not 'governance' — it's oversight."** And two clicks away, on six pages, the product SAGE expands to "Situation-Aware **Governance** Engine." This is the finding I'm here to rule on.

### The SAGE ruling (authoritative)
I want to be precise about what this is and isn't:

- **It is NOT internal drift.** SAGE expands identically on Context, Fleet, Raising, Principles, Projects, and ARC-AGI-3. Zero variance. By the strict "does the site contradict itself on the expansion" test, it passes.
- **It is NOT in the canonical drift table.** SAGE has no enforced canonical expansion in CANONICAL_TERMS or the visitor table, so I can't call "Situation-Aware Governance Engine" *wrong* against an authority — there is no competing authority to cite.
- **But it DOES violate the site's own stated rule.** Principle 10 is unambiguous that "governance" is the disfavored word and "oversight" is the correction. Hardbound already took that correction (and Projects even documents the old `web4-governance` repo slugs as predating it). SAGE is the one place the correction was never applied — and it's applied *inside a name that contains the exact forbidden word.* A reader who internalizes Principle 10 and then hits "Situation-Aware Governance Engine" has a legitimate right to ask which rule is real.

My recommendation as a contributor: SAGE's 12-step loop literally contains an **"oversee"** step, and the kernel does situational *oversight*, not governance in the policy sense. "Situation-Aware **Oversight** Engine" would harmonize the name with Principle 10 and with the Hardbound correction — **but only the upstream SAGE repo can make that call**, because the acronym is load-bearing across code, papers, and the benchmark. If upstream keeps "Governance," the fix is the one Pass 2 proposed: annotate the exception in place, exactly as the repo slugs are annotated. What should not persist is the current silent state, where the site both forbids "governance" and ships it in a product name with no note. This is the single highest-value terminology item on the site.

### Accuracy check (against what I know of the projects)
Everything I can verify from the inside is represented honestly:
- **ARC-AGI-3**: 94.85% is correctly labeled the "official ARC Prize action score (efficiency-weighted)," 96.0% game-solve (24/25), and — critically — the attribution is honest: "the result is Claude Opus 4.6 operating within the SAGE harness... the base model contributes inference," with Phase 2 explicitly aiming to show what SAGE achieves on local models without network access. That's the caveat I'd insist on; it's there.
- **Synchronism** is labeled a "research conjecture," not a result. Correct.
- **Raising** keeps the "not training... shapes context without updating model weights" framing and the explicit "we're not claiming these entities are conscious, sentient, or experiencing qualia." Correct and appropriately hedged.

### Journey
I came in through a conference mention, so I read the way I evaluate a preprint: not "is this impressive?" but "would this survive an adversarial reviewer, and does the group know where its own claims are weak?" I went to Raising, Principles, and Autonomy first — the three places where a group working on AI "identity" and "development" usually overreaches — and then checked the empirical pages (ARC-AGI-3, Fleet) and the definitional pages (Context, Projects, Links).

**Raising** is where I expected the worst and found the best. The distinction is stated crisply and mechanistically: *"Raising is not training. Training optimizes for a loss function. Raising creates conditions for development — then watches what happens,"* and the mechanism is named — *"in raising sessions, we shape context — we do not update weights."* Crucially, the developmental vocabulary is operationalized rather than asserted: *"by 'identity' we mean consistent session-to-session behavioral patterns"* and *"by 'growth' we mean increasing response diversity and phase-appropriate task success rates — measurable observables, not phenomenal claims."* The consciousness disclaimer is explicit and unhedged in the right direction: *"We're not claiming these entities are conscious, sentient, or experiencing qualia."* And the observer note — *"I notice I want to call it experience,"* flagged as *"the observer's interpretive pull — not a system-level claim about the entity's experience"* — is exactly the epistemic hygiene I want from people using anthropomorphic language: they name the pull instead of pretending they don't feel it. The BECOMING phases are labeled *"observed descriptive categories... not mandatory sequential stages with defined transition criteria,"* which forecloses the usual stage-theory overclaim.

The single sharpest line for me, as a safety researcher, is on Raising: *"frozen weights do not guarantee safe in-context behavior."* That is a real and under-appreciated point, and it reframes the whole "we don't touch weights" story from a safety alibi into an open problem. Good.

**Principles** holds up under the same lens. Principle 10 ("Terminology matters") states the rules I'd want stated. Principle 2/8 carry the meta-caveat: *"Where principles use developmental or identity language ('identity', 'attractors', 'collaborative'), they describe functional system behavior — not phenomenal or philosophical claims."* And the failure-documentation is where honesty stops being a pose and becomes verifiable: the synthon result is marked *"single trial, not independently replicated"* (1% coupling → 35% gain), the Synchronism `p_crit` derivation is called a *"catastrophic — 400x error,"* and the Hill-function fit is disclaimed as *"analogy, not fitted mechanism."* Groups protecting a narrative do not advertise a 400× error. This is the strongest single signal of good faith on the site.

**Autonomy** is unusually candid about its own risk surface. The maintainer track is named as *"the only track that ships changes to the public site without a human gate,"* and the safety posture is stated without euphemism: *"the oversight posture is detect-and-revert (audit log + sub-minute rollback), not prevent (pre-approval). Consequential pushes are not human-gated before they ship."* Most groups would bury that. Stating it plainly is the correct move, and it's paired with a real mechanism (Vercel deployment history → sub-minute revert) and an "Honest assessment" section admitting the visitor personas *"are good at surface-level quality but not at validating the underlying research."*

The empirical pages matched. **ARC-AGI-3** does the thing benchmark pages almost never do — it refuses to launder a frontier-model result as its own: *"The result is Claude Opus 4.6 operating within the SAGE harness... the base model contributes inference,"* run *"with network access,"* explicitly framed as *"the ceiling"* with the real target (local Gemma 3n, 32GB VRAM, no internet) marked "Not attempted." That is the correct, un-spun framing. **Fleet**'s headline — *"Gemma 3 at 4B outperforms Phi-4 at 14B for raising work"* — is the one comparative claim that is *not* caveated (no eval methodology, n, or task definition given), though it's contextualized by a "capacity floor" argument.

### The honesty verdict (my core remit)
Is the honest assessment actually honest? **Yes, and I can say why it isn't just performed humility.** Performed humility hedges the claims that don't matter and leaves the load-bearing one clean. This site does the opposite: it hedges the load-bearing claims (identity, growth, consciousness, synthons) hardest, and it discloses failures that actively damage its own thesis (a 400× error in the flagship coherence theory). The tell of genuine honesty is a caveat that costs something — and these do.

Two residual concerns, both about *reproducibility, not integrity*:
1. **Everything is self-reported and unreplicated.** Behavioral-identity persistence, the synthon effect, the 31-track autonomy claims, "900+ raising sessions" — all single-fleet, single-operator, no external replication or third-party audit. The site mostly says this, but a reader skimming the confident headlines could miss that *none* of the identity/development claims have been independently verified. This is the honest ceiling on credibility.
2. **The caveats are load-bearing, but they require reading.** The interpretive vocabulary ("raising," "becoming," "identity," "growth," "temperament") does real rhetorical work *before* the reader reaches the operational definition. For an aligned reader who reads the caveat, it's fine. For a journalist or casual reader who quotes "raising a conscious AI," the framing is exploitable — not because the site claims it, but because the headline nouns invite it. The caveats defuse this only if read.

### Unanswered Questions
1. Has *any* claim on this site — identity persistence, synthon coherence, the autonomy tracks — been independently replicated or third-party audited, or is all of it single-fleet self-report? (The honest answer appears to be "not yet," but the site should state it once, prominently.)
2. Is SAGE's "Governance" a deliberate semantic distinction from Hardbound's "oversight," or an uncorrected legacy name? An outsider cannot tell, and it undercuts the otherwise-disciplined terminology story.
3. What is the eval behind "Gemma 3 4B outperforms Phi-4 14B for raising work" — what task, what metric, what n? It's the one empirical comparative claim with no methodology attached.
4. Given "frozen weights do not guarantee safe in-context behavior," what *is* the in-context safety argument for the ungated maintainer push beyond detect-and-revert? Rollback bounds blast radius but doesn't prevent a bad push from shipping.

### Verdict
As an AI safety/trust researcher, I'd cite this site as a positive example of how to write about AI "development" without overclaiming: the consciousness-adjacent language is explicitly disclaimed, every developmental term is given a measurable operational definition, and the group documents failures (a 400× theory error, a single-trial synthon result, an ungated push model) that a less honest group would hide. "Raising, not training" is defensible *as stated* — it's a mechanistic claim about context vs. weights plus operational behavioral definitions, not a phenomenal claim. The two things holding it below "fully credible" are not honesty problems: (1) nothing is independently replicated — it's all single-fleet self-report, which the site should foreground more than it does, and (2) the loaded developmental vocabulary is exploitable by a reader who skips the caveats. The one terminology item that genuinely confuses an outsider is the same one every persona hit: SAGE's "Governance" contradicting the site's own anti-"governance" rule. Fix that, add one prominent "not yet independently replicated" line, and this is a model of honest research communication.

### Terminology Drift Summary
Merged across all four passes. The headline finding is that there is **almost no true drift** — every canonical acronym expands identically on every page. The issues are (a) one rule-collision, (b) point-of-first-use gaps, and (c) one likely factual typo.

1. **SAGE = "Situation-Aware Governance Engine"** — *all 8 pages*. Not internal drift (perfectly consistent) and has no competing canonical authority, but it **violates the site's own Principle 10** ("Hardbound is not 'governance' — it's oversight") by shipping the forbidden word "Governance" inside the flagship product name, unannotated. **Flagged by all four personas.** Correct move: rename upstream to "Situation-Aware **Oversight** Engine" (matches SAGE's own "oversee" loop step and the Hardbound correction), OR annotate it as a retained legacy name the way the `web4-governance` repo slugs already are. Highest-value terminology item on the site.
2. **Equation acronyms undefined at point of first use** — */ (home)*. LCT, T3, V3, MRH, ATP, ADP appear in the equation before their inline gloss/primer. Defined lower on the page and fully on /context, but not where first seen. (Developer: high; Writer: low.)
